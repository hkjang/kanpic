## 릴리즈 요약

v0.93.0은 **CSV로 내보낸 파일을 다시 가져오면 전화번호가 달라지던 문제**를 고칩니다. 지난 릴리즈에서 XLSX 왕복을 맞춰 본 김에 CSV도 같은 방식으로 확인했습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 대부분은 온전했습니다

한글, 쉼표가 든 값, 값 안의 줄바꿈, 큰따옴표, 앞자리 0, 음수, 소수, 탭, 앞뒤 공백, 이모지 — 열네 가지를 내보내고 다시 가져와 원본과 맞춰 봤고 전부 그대로였습니다.

## 전화번호가 달라지던 문제

`=`·`+`·`-`·`@` 로 시작하는 글자는 내보낼 때 앞에 작은따옴표가 붙습니다. 그 파일을 엑셀에서 열었을 때 수식으로 실행되지 않게 하려는 안전장치입니다.

문제는 **그 작은따옴표를 다시 가져올 때 벗기지 않는다**는 것이었습니다. `+82-10-1234-5678` 은 `'+82-10-1234-5678` 이 되어 돌아옵니다. 연락처를 내보냈다 다시 올리면 **모든 전화번호에 문자가 하나씩 붙습니다.**

작은따옴표는 값이 아니라 포장입니다. 엑셀도 셀에 `'=1+1` 을 입력하면 `=1+1` 이라는 글자를 저장하고 작은따옴표는 보여 주지 않습니다. 이제 가져올 때 벗깁니다.

**포장은 정확히 되돌릴 수 있어야 합니다.** 원래 값이 `'=1+1` 인 경우에는 내보낼 때 작은따옴표를 하나 더 붙이고(`''=1+1`), 가져올 때 하나만 벗깁니다. 반대로 `'tis` 처럼 뒤가 수식 기호가 아니면 아무것도 벗기지 않습니다.

내보낸 파일에는 안전장치가 그대로 남습니다. 엑셀에서 열어도 실행되지 않습니다.

## 큰 수가 지수로 나가던 문제

`12345678901234` 가 `1.2345678901234e+13` 으로 나갔습니다. 다시 가져오면 같은 수로 읽히지만, 파일을 열어 본 사람에게는 읽을 수 없는 값이고 다른 도구가 어떻게 읽을지도 알 수 없습니다. 이제 엑셀과 같이 그대로 씁니다. `1e+300` 처럼 자릿수가 감당되지 않는 값만 지수로 남깁니다.

## 검증 결과

- 열네 가지 값을 실제로 내보내고 다시 가져와 한 칸씩 맞췄습니다. 고치기 전에는 전화번호와 수식 글자 두 가지가 어긋났고, 지금은 전부 같습니다.
- 포장이 정확히 되돌려지는지 확인하는 테스트를 더했습니다. 일곱 가지 값을 내보내는 규칙과 가져오는 규칙에 차례로 통과시켜 원래 값으로 돌아오는지 봅니다.
