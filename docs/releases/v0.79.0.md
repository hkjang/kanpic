## 릴리즈 요약

v0.79.0은 **지운 시트를 되돌릴 수 있게 합니다.** 지난 릴리즈에서 행·열 삭제의 회수 경로를 만들면서 같은 종류의 함정이 더 있는지 훑었고, **시트 삭제에는 회수 경로가 아예 없다**는 것을 찾았습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 훑어본 결과

되돌릴 수 있어야 하는 작업을 하나씩 눌러 봤습니다.

| 작업 | 실행 취소 | 자동 백업 |
| --- | --- | --- |
| 값 입력·내용 지우기 | 된다 | — |
| 붙여넣기 | 된다 | — |
| 채우기 | 된다 | — |
| 정렬 | 된다 | — |
| 행·열 삭제 | 안 된다 | 있다 (v0.78.0에서 노출) |
| **시트 삭제** | **안 된다** | **없었다** |
| 워크북 삭제 | — | 휴지통 |

셀을 다루는 작업은 모두 실행 취소가 정상 동작했고, 실제로 값이 되돌아오는 것까지 확인했습니다. 구멍은 시트 삭제 한 곳이었습니다.

## 시트 삭제

시트 하나에는 수만 개의 셀이 들어 있을 수 있습니다. 지우면 전부 사라지고, 행 삭제와 달리 **백업조차 남지 않았습니다.** 확인 대화상자는 있었지만 확인은 회수가 아닙니다.

이제 서버가 시트를 지우기 전에 자동으로 버전 백업을 남기고, 삭제 응답에 그 번호를 담아 보냅니다. 화면에는 같은 안내가 나타납니다.

> ⚠ 시트 상세을(를) 삭제했습니다
> 실행 취소로는 되돌릴 수 없습니다. 삭제 직전 상태로 복원할 수 있습니다. **되돌리기**

**탭만 돌아오면 소용이 없습니다.** E2E는 되돌린 뒤 그 시트의 `A1`, `A2` 에 원래 값이 그대로 있는지까지 확인합니다.

## 안내가 사라지던 자리

시트를 지우면 활성 시트가 바뀌고, 그때 편집기 상태가 초기화되면서 **안내도 함께 지워지고 있었습니다.** 안내는 방금 한 편집에 대한 것이지 지금 보고 있는 시트에 대한 것이 아닙니다. 시트를 옮겼다고 지운 시트를 되돌릴 길이 없어지지는 않으므로, 초기화가 안내를 건드리지 않도록 고쳤습니다.

## 호환성

`DELETE /api/v1/sheets/{id}` 의 응답이 `204 No Content` 에서 `200 OK` 로 바뀌고 본문에 `workbook_id`, `sheet_name`, `backup_version_id`, `server_version` 을 담습니다. MCP의 `spreadsheet.sheet.delete` 동작은 그대로입니다.

## 검증 결과

- 저장소 계층 테스트를 더했습니다. 시트를 지우고 백업 버전으로 복원한 뒤, 탭이 아니라 **셀 값**이 돌아오는지 확인합니다.
- 응답 형태가 바뀌면서 기존 테스트 두 개가 실패했고, 새 동작을 확인하도록 고쳤습니다(버전 개수, 삭제 응답 코드).
- `go vet ./...`, `go test ./...`, React/Vitest 247개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 139건을 통과했습니다.
