## 릴리즈 요약

v0.33.3은 OpenAI 호환 vLLM 응답의 편차를 더 폭넓게 복구하고, Workbook Agent의 차트 생성·후속 수정 요청을 안전하게 이어 가도록 개선한 안정화 릴리즈입니다. 닫는 `</think>` 태그만 포함된 추론 응답, native tool call, 중첩·문자열 envelope와 잘린 최종 계획을 구분해 완성되고 검증된 계획만 실행합니다.

데이터베이스 마이그레이션과 외부 API 변경은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며, `BOOTSTRAP_ADMIN_ID`·`BOOTSTRAP_ADMIN_PASSWORD`와 Keycloak Confidential Client의 `client_secret` 설정도 그대로 사용할 수 있습니다.

## 더 견고한 vLLM 계획 복구

- 여는 태그 없이 도착한 `</think>` 추론 영역, JSON 문자열 안의 리터럴 추론 태그, Markdown·설명문·중첩 envelope와 OpenAI native `tool_calls`를 구분해 실제 최종 계획을 추출합니다.
- 여러 완성 계획이 섞였거나 중간 초안 뒤의 최종 JSON이 잘린 응답은 임의 실행하지 않고 교정 대상으로 처리합니다.
- camelCase와 snake_case 도구 인자, legacy function call과 이스케이프된 arguments를 정규화하되 지원하지 않는 도구나 모호한 응답은 거부합니다.
- 의미 교정, 응답 잘림, 일시적 Gateway 오류와 컨텍스트 조정의 재시도 예산을 분리했습니다. 의미 계획은 최대 3회, 전체 Gateway 호출은 최대 5회와 115초 안에서 끝납니다.
- 모델 컨텍스트와 실제 프롬프트 크기를 함께 계산하고, 관리자 `MaxOutputTokens`를 정확한 상한으로 지키며 모든 시도의 토큰 사용량을 합산합니다.
- `Retry-After`, `response_format` 비호환과 입력 컨텍스트 초과를 각각 분류해 불필요한 반복 호출 대신 구체적인 진단을 제공합니다.

## 안전한 차트 멀티턴

- “이 막대차트를 선 차트로 바꿔줘” 같은 후속 요청에서 명시한 차트 ID·정확한 제목·최근 적용 이력·유일한 현재 차트를 순서대로 사용해 대상을 결정합니다.
- 대상이 여러 개라 확정할 수 없거나 이미 요청한 상태인 경우 모델을 반복 호출하지 않고 사용자가 바로 조치할 수 있는 안내를 반환합니다.
- 차트 생성 요청은 `create_chart`, 수정 요청은 `update_chart`만 사용하도록 검증하고, Agent 모드의 차트 수정도 같은 대상 안전 규칙을 적용합니다.
- 새 차트의 원본 범위가 빠지면 현재 선택 범위를 사용하고, 모델이 되돌려 보낸 변경 없는 필드는 제거하며 현재 revision을 서버가 다시 채웁니다.
- `#REF!` 원본, 중복 수정, 잘못된 차트 형식·범례·제목, 10,000셀 초과 범위와 워크북당 100개 제한을 적용 전에 검사합니다.
- 한 계획에 여러 차트 변경이나 다른 쓰기 작업을 섞지 못하게 해 일부 작업만 적용되는 상황을 방지합니다.
