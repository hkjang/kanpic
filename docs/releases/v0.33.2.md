## 릴리즈 요약

v0.33.2는 OpenAI 호환 vLLM Gateway가 표준 계획 JSON과 조금 다른 응답을 반환해도 Workbook Agent가 안전하게 복구하도록 개선한 안정화 릴리즈입니다. 이전에는 JSON 코드 블록, 추론 태그 또는 일부 호환 응답 구조 때문에 즉시 “유효한 계획을 반환하지 못했습니다” 오류가 발생했지만, 이제 서버가 응답을 정규화하고 잘못된 계획에는 제한된 교정 피드백을 전달해 최대 3회 안에서 복구합니다.

데이터베이스 마이그레이션과 API 변경은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며, `BOOTSTRAP_ADMIN_ID`·`BOOTSTRAP_ADMIN_PASSWORD`와 Keycloak Confidential Client의 `client_secret` 설정도 그대로 사용할 수 있습니다.

## vLLM 응답 호환성

- `<think>…</think>` 추론 블록과 Markdown JSON 코드 블록, JSON 앞뒤의 설명문을 제거하고 실제 계획 객체를 추출합니다.
- 일부 vLLM 채팅 템플릿처럼 여는 `<think>` 없이 `</think>`만 반환하는 경우에도 닫는 태그 앞을 추론 영역으로 처리합니다. 추론 영역에 JSON처럼 보이는 중간 데이터가 있어도 최종 계획과 혼동하지 않습니다.
- 문자열, 배열형 content, 객체형 content, legacy `choice.text`와 `reasoning_content` 응답을 읽습니다.
- `plan`·`result`·`data` envelope, `toolCalls`, OpenAI function tool call과 문자열로 이스케이프된 tool arguments를 정규화합니다.
- `response_format: json_object`를 HTTP 400 또는 422로 거부하는 Gateway에서는 해당 옵션을 제거하고 엄격한 JSON 프롬프트로 다시 요청합니다.

## 자동 교정과 안전 검증

- JSON 문법 오류, 필수 필드 누락, 선택 범위 이탈과 작업 유형별 계약 위반을 즉시 종료하지 않고 안전하게 축약한 실패 사유를 모델에 다시 전달합니다.
- 한 계획은 응답 잘림, 일시적인 Gateway 장애와 형식 교정을 모두 합쳐 최대 3회 호출합니다.
- `ai.timeout_seconds`를 전체 교정 과정이 아니라 Gateway 호출별로 적용해 뒤쪽 교정 시도가 시작 전에 만료되지 않도록 했습니다.
- 선택 범위, 허용 도구, 수식·값·서식·차트 인자와 최대 변경 수 검증은 매 시도마다 유지하며 검증을 통과한 계획만 사용자에게 표시합니다.
- 세 번 연속 잘린 응답은 일반적인 계획 오류 대신 범위를 줄이거나 변경 한도를 낮추라는 구체적인 진단을 기록합니다.

## 검증 결과

- Go 정적 검사와 전체 단위 테스트를 통과했습니다.
- vLLM 고아 `</think>` 태그, 추론·Markdown 혼합 응답, 배열형 content, envelope, function tool call과 `response_format` 호환 폴백 회귀 테스트를 추가했습니다.
- React/Vitest 31개 테스트 파일, 144개 테스트를 통과했습니다.
- TypeScript 타입 검사와 Vite 프로덕션 빌드를 통과했습니다.
- PostgreSQL 통합 테스트와 실제 Chromium 기반 Playwright 84개 브라우저 시나리오를 통과했습니다.
