## 릴리즈 요약

v0.123.6은 **TREND 함수가 인수를 뒤바꿔 읽어 오류 없이 엉뚱한 수를 내놓던 것** 을 고칩니다. 같은 자리에서 통계 함수 네 개의 셈도 바로잡고, 셈은 되면서 함수 목록에 없어 찾을 수 없던 아홉 개를 실었습니다.

## 목록과 실제를 맞대어 본다

함수 목록에 실린 이름 226개와 엔진이 실제로 알아듣는 이름을 뽑아 맞대어 보았습니다. 목록에만 있고 셈이 없는 것은 없었습니다 — 그쪽은 이미 시험이 지키고 있습니다. 반대쪽에 구멍이 있었습니다.

## 오류보다 나쁜 것

`TREND`가 `FORECAST`와 한 갈래로 묶여 있었습니다. 두 함수는 같은 회귀 직선을 쓰지만 **인수 차례가 다릅니다**.

| 함수 | 차례 |
| --- | --- |
| `FORECAST(구할 x, 알려진 y, 알려진 x)` | 구할 값이 맨 앞 |
| `TREND(알려진 y, [알려진 x], [구할 x], [b])` | 구할 값이 뒤 |

엑셀과 구글 시트의 문서를 그대로 따라 쓰면 인수가 조용히 뒤바뀌었습니다.

```
=TREND({2;4;6},{1;2;3},{7;8;9})
  엑셀·시트  14, 16, 18
  고치기 전  -4
```

`#VALUE!`가 떴다면 바로 알아챘을 것입니다. 그럴듯한 수 하나가 나오는 쪽이 훨씬 나쁩니다.

`TREND`를 따로 떼어 제 차례대로 읽게 했습니다. 알려진 x를 적지 않으면 1, 2, 3…을 쓰고, 구할 x를 적지 않으면 알려진 x를 되짚고, `b`를 거짓으로 두면 직선이 원점을 지납니다. 결과는 구할 x와 같은 모양으로 — 세로로 주면 세로로, 가로로 주면 가로로 — 펼쳐집니다. `FORECAST`는 원래 맞았으므로 건드리지 않았습니다.

## 같은 묶음 안에서 셈이 갈렸다

이름 끝에 `A`가 붙은 통계 함수는 숫자가 아닌 값을 **0으로 세는** 쪽입니다. 붙지 않은 쪽은 건너뜁니다. `AVERAGEA`는 처음부터 그렇게 세고 있었는데 `STDEVA`, `STDEVPA`, `VARA`, `VARPA`는 건너뛰고 있어서, 한 묶음 안에서 셈이 갈려 있었습니다.

```
=STDEVA(1,2,3,"x")   1  →  1.291    ("x" 를 0 으로 센다)
=STDEV(1,2,3,"x")    1  →  1        (건너뛰는 쪽은 그대로)
```

## 찾을 수 없던 함수 아홉 개

셈은 붙어 있는데 함수 목록에 없어 아무도 찾을 수 없던 것들을 실었습니다 — `PEARSON`, `STDEVA`, `STDEVPA`, `VARA`, `VARPA`, `TREND`, `UNICHAR`, `UNICODE`, `T`. 목록을 만든 자리에는 "사람들이 `#NAME?`를 만나며 알아내게 두지 않으려고" 둔다고 적혀 있습니다. 그 약속의 반대쪽은 지켜지지 않고 있었습니다.

## 검증 결과

- TREND 시험과 A 계열 시험 모두 고치기 전 코드에서 실패합니다.
- TREND 는 값 하나, 세로 배열, 가로 배열, 알려진 x 생략, 구할 x 생략, `b`=거짓, 길이가 어긋난 경우까지 확인합니다.
- Go 시험 전체가 그대로 통과합니다.
