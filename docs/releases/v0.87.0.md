## 릴리즈 요약

v0.87.0은 **500번째 열 너머를 화면에서 볼 수 있게 합니다.** 행에서 찾은 것과 같은 종류의 구멍이 열에도 있었습니다. 이번에는 엑셀과 같은 16,384열(XFD)까지 열었습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 닿을 수 없던 열

서버는 엑셀과 같은 **16,384열까지 받아서 저장합니다.** 실제로 501번째 열에 값을 쓰면 그대로 들어갑니다. 그런데 편집기는 500번째 열(`SF`)에서 끊겨 있었습니다. 이름 상자에 `SG1` 을 넣으면 `SF1` 로, `ZZ1` 을 넣어도 `SF1` 로 잘렸습니다.

이제 `AAA1`, `XFD1` 로 이동해 값을 넣을 수 있고, 세 글자 열 머리글(`AAA`~`XFD`)도 제대로 그려집니다. 엑셀의 마지막 열 다음인 `XFE1` 은 그대로 막습니다.

## 행과 달리 타협하지 않은 이유

지난 릴리즈에서 행은 엑셀의 1,048,576이 아니라 200,000으로 정했습니다. 격자가 전체 높이만큼 스크롤 영역을 만드는데, 확대하면 브라우저가 요소 높이를 잘라 내기 시작하는 지점을 넘기 때문입니다.

열은 사정이 다릅니다. 16,384열 × 108px × 최대 확대 2배는 약 354만 px로, 그 한계에서 한참 멉니다. 그래서 여기서는 엑셀과 정확히 같은 수를 씁니다.

## 검증 결과

- 500열짜리 시트를 만들어 `SG1`·`ZZ1` 이 `SF1` 로 잘리는 것을 먼저 확인한 뒤 고쳤습니다.
- 고친 뒤 `AAA1` 에 값을 입력해 서버에 저장되는 것과, 머리글이 `ZV ZW ZX ZY ZZ AAA` 로 이어지는 것을 눈으로 확인했습니다.
- E2E를 더했습니다. `AAA1` 로 이동해 그 자리에 미리 저장해 둔 값이 보이는지, `XFD1` 까지 닿고 `XFE1` 은 막히는지 확인합니다. 이전 번들에서는 `SF1` 에 멈춰 실패합니다.
- `go vet ./...`, `go test ./...`, `go test -tags integration ./internal/...`, React/Vitest 259개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 145건을 통과했습니다.
