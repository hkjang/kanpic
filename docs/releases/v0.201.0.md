## 릴리즈 요약

v0.201.0은 관리자 화면에 **퇴사자 인수인계** 를 더합니다.

## 조각은 다 있는데 흐름이 없었습니다

관리자 화면에는 계정 정지, 세션 종료, 워크북 **하나씩** 소유권 이전이 이미 있었습니다. 그런데 퇴사자를 정리하는 흐름은 없었습니다.

```
이 사람이 무엇을 가지고 있는가?   볼 방법이 없다
마흔 개를 넘기려면?               마흔 번 누른다
몇 개를 빠뜨렸는가?               알 수 없다
```

빠뜨린 워크북은 **정지된 계정에 묶인 채로 잊힙니다.** `소유자가 없거나 정지된 워크북` 필터가 나중에 주워 담지만, 그때는 이미 사람이 떠난 뒤입니다.

## 사용자 › 가진 워크북 인수인계…

사용자별로 가진 워크북을 **모두** 보여 주고 한 번에 넘깁니다. 넘기는 일 자체는 이미 있던 것을 그대로 씁니다 — 소유권 이전은 관리자를 이미 허락하고 있었습니다.

## 조용히 빼지 않습니다

- **목록을 자르지 않습니다.** 200개까지만 보여 주면 201번째는 넘겨지지 않은 채 남고 아무도 그것을 모릅니다.
- **휴지통에 있는 것은 넘기지 않고 몇 개인지 셉니다.** 되살리기 전에는 손댈 수 없기 때문입니다. 조용히 빼면 "다 넘겼다" 는 말과 남아 있는 워크북이 어긋납니다.
- **넘긴 것과 못 넘긴 것을 하나하나** 돌려줍니다. 절반만 넘어갔는데 다 됐다고 하면 남은 절반은 잊힙니다.
- **정지된 사람에게는 넘기지 않습니다.** 받은 사람도 손댈 수 없으므로 옮긴 것이 아니라 옮긴 척한 것이 됩니다.

**이전 소유자를 편집자로 남기기** 를 켜면 인수인계 기간에 이전 담당자가 계속 볼 수 있습니다. 워크북을 하나씩 넘기는 것은 워크북 거버넌스 화면에 그대로 있습니다.

## 검증 결과

- 전부 넘어가는지, 휴지통을 세는지, 정지된 사람과 자기 자신에게 넘기려 들면 막는지, 관리자만 쓸 수 있는지 시험합니다.
- 브라우저에서 관리자 화면으로 넘기고, **서버에서도 주인이 바뀌었는지** 까지 확인합니다.
- 웹 시험 457개와 Go 시험 전체가 통과하고 `gofmt` 도 확인했습니다.
