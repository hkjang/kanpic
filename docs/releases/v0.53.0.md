## 릴리즈 요약

v0.53.0은 기능 추가 대신 **같은 버그가 두 번 난 구조를 없앱니다.** v0.45.0의 차트 보조 축과 v0.52.0의 시트 보호에서 똑같은 일이 벌어졌습니다. 새 필드가 구조체와 REST에는 도달했지만 PostgreSQL 저장 경로에는 닿지 않아, 저장한 값이 조용히 되돌아갔습니다.

마이그레이션은 없습니다. 동작 변화도 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 원인과 조치

두 저장소(메모리·PostgreSQL)가 각자 입력에서 엔터티를 조립하고 있었습니다. 같은 코드가 두 벌 있으니 한쪽만 고치는 일이 반복됩니다.

- **공용 생성 함수로 통일했습니다.** 차트, 피벗, 보호 범위, 필터 뷰, 이름 범위의 생성 경로가 이제 `chartFromInput`, `pivotFromInput`, `protectedFromInput`, `filterViewFromInput`, `namedRangeFromInput` 하나씩만 지납니다. 필드를 더할 곳이 한 군데뿐입니다.
- **저장 왕복 테스트를 추가했습니다.** 차트·보호 범위·조건부 서식·필터 뷰·슬라이서의 모든 선택 필드에 값을 넣어 만든 뒤, 데이터베이스에서 다시 읽어 비교합니다.

왕복 테스트가 중요한 이유는 이 버그가 **생성 응답만 보면 정상으로 보이기 때문**입니다. 응답은 메모리의 구조체로 만들어지므로, 저장되지 않은 필드도 응답에는 그대로 실려 나갑니다. 읽어 와야만 드러납니다.

테스트가 실제로 잡는지 확인하려고 v0.45.0 버그를 그대로 재현해 봤습니다(생성 함수에서 `SecondaryAxis` 한 줄 제거). 테스트는 `SecondaryAxis:false` 를 지적하며 실패했고, 되돌리자 통과했습니다.
