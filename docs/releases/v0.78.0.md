## 릴리즈 요약

v0.78.0은 **지운 행과 열을 되돌릴 수 있게 합니다.** 지난 릴리즈에서 "잘못 지웠다면 실행 취소로 되돌리면 됩니다"라고 적었는데, 확인해 보니 **사실이 아니었습니다.** 행을 지우면 실행 취소 버튼이 비활성 상태로 남습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 실행 취소가 못 하는 일

행 삭제는 셀을 지우는 것으로 끝나지 않습니다. 아래 행을 전부 끌어올리고, 그 행을 가리키던 수식을 `=A3*2` 에서 `=#REF!*2` 로 **영구히 다시 씁니다.** 셀 단위로 되돌리는 실행 취소는 원래 수식이 무엇이었는지 알 방법이 없어, 서버도 이 작업에 대해서는 `operation has no cells to undo` 를 돌려줍니다.

즉 실행 취소 버튼이 꺼져 있던 것은 정직한 상태였습니다. 문제는 **그 대신 쓸 방법이 화면 어디에도 없었다**는 것입니다.

## 되돌리기

서버는 행·열을 지우기 전에 **자동으로 버전 백업을 남기고** 있었습니다. 응답에 백업 버전 번호까지 담아 보내고 있었는데 클라이언트가 그것을 버렸습니다.

이제 행이나 열을 지우면 왼쪽 아래 안내에 **되돌리기** 가 함께 나타납니다.

> ⚠ 행 3을(를) 삭제했습니다
> 실행 취소로는 되돌릴 수 없습니다. 삭제 직전 상태로 복원할 수 있습니다. **되돌리기**

누르면 지운 행과 **그 행을 가리키던 수식 원문까지** 삭제 직전 상태로 돌아갑니다. 되돌리기 자체도 현재 상태를 자동 백업하므로 다시 되돌릴 수 있습니다. 안내를 닫은 뒤에도 버전 이력에 `행 삭제 전 자동 백업` 으로 남아 있습니다.

수식이 함께 깨진 경우에는 **보기** 와 **되돌리기** 가 나란히 나옵니다. 깨진 자리를 손으로 고칠지, 통째로 되돌릴지 고를 수 있습니다.

행 삽입처럼 지워지는 것이 없는 편집에는 안내가 뜨지 않습니다. 모든 편집마다 안내가 뜨면 안내는 배경이 되고, 정작 위험한 것을 놓칩니다.

## 검증 결과

- 실제 브라우저에서 확인하다 발견한 문제입니다. 행을 지운 뒤 실행 취소 버튼이 꺼져 있는 것을 보고, 서버 API로 되돌리기를 시도해 `operation has no cells to undo` 를 확인한 뒤, 응답에 이미 들어 있던 자동 백업을 찾았습니다.
- E2E는 삭제가 수식 원문을 `=#REF!*2` 로 바꿔 놓은 것을 먼저 확인하고, 되돌린 뒤 `=A3*2` 로 돌아오는지 봅니다. 되살아나는 것이 행만이 아니라는 뜻입니다.
- 이전 버전 번들에서 E2E가 실패하는 것을 확인했습니다. `docs/USER_GUIDE.md` 의 잘못된 안내도 함께 고쳤습니다.
- `go vet ./...`, `go test ./...`, React/Vitest 247개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 138건을 통과했습니다. `multiline` 한 건이 한 번 실패했다가 네 번 연속 통과해 전체를 다시 돌렸고, 두 번째 전체 실행은 138건 모두 통과했습니다. 제품 문제가 아니라 타이밍 흔들림으로 봅니다.
