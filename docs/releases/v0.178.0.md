## 릴리즈 요약

v0.178.0은 **무엇이 숫자인지** 를 한 곳에서 정하고, 글자로 담긴 숫자를 고치는 자리를 더합니다.

## 세 곳이 서로 달랐습니다

```
           SUM(엔진)  선택 요약  열 통계
"2000"       2000      2000      2000
"1,234"      뺌        뺌        1234
TRUE         1         뺌        1
```

같은 열에서 **세 가지 합계** 가 나올 수 있었습니다. 상태 줄에 보이는 수와 `=SUM` 이 내는 수가 다르면 사람은 어느 쪽을 믿어야 할지 알 수 없습니다.

엔진이 정하는 것으로 모았습니다. 값이 실제로 얼마인지는 수식이 정하기 때문입니다. 화면이 더 너그럽게 세는 것은 친절해 보이지만, **그 합계는 어떤 수식으로도 재현되지 않습니다.**

열 통계가 `"1,234"` 를 세던 것은 일부러 넣은 것이었고 시험에도 그렇게 적혀 있었습니다. 그 뜻은 좋았지만 답이 어긋나는 쪽이었으므로, **그 필요는 자료를 고쳐서** 채웁니다.

## 데이터 › 데이터 정리 › 텍스트로 저장된 숫자…

```
1,234    →  1234
₩5,000   →  5000
(500)    →  -500      괄호는 회계에서 음수를 적는 꼴입니다
50%      →  0.5       화면에 보이던 것과 셈하는 값이 같아야 합니다
```

다른 곳에서 붙여 넣으면 이렇게 들어옵니다. 사람 눈에는 숫자인데 `=SUM` 은 조용히 빼고 셈합니다 — **합계가 작게 나오는데 무엇이 빠졌는지는 아무 데도 적히지 않습니다.**

**쉼표가 세 자리마다 찍혀 있지 않으면 숫자로 보지 않습니다.** `"1,2,3"` 을 억지로 123으로 바꾸면 사람이 적은 것과 다른 값이 칸에 들어갑니다.

수식이 든 칸은 건드리지 않습니다. 수식의 결과가 글자라면 고칠 것은 그 값이 아니라 수식입니다.

## 검증 결과

- 세는 규칙과 바꾸는 규칙을 따로 시험합니다.
- 브라우저에서 고치기 전 합계 `1000`, 고친 뒤 `7234` 를 확인합니다.
- 웹 시험 401개와 Go 시험 전체가 통과합니다.
