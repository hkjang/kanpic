## 핵심 변경

- 동일 셀을 여러 사용자가 같은 기준 버전에서 수정할 때 마지막 입력만 조용히 남기지 않고, 비교·결정 가능한 서버 권위 충돌 기록을 생성합니다.
- 충돌 전 기준 셀, 먼저 반영된 상대 사용자 셀, 충돌을 만든 사용자의 제출 셀, 실제 임시 적용 셀과 현재 서버 셀을 각각 보존합니다.
- 리터럴 값뿐 아니라 수식, 계산 결과, 셀 서식과 배열 결과 출처까지 하나의 충돌 타임라인에서 비교할 수 있습니다.
- 사용자는 **현재 값 유지** 또는 **먼저 반영된 값 복원**으로 충돌을 명시적으로 해소할 수 있습니다.
- 모든 해소 결정은 별도 작업 ID와 새 워크북 서버 버전으로 기록되며, 충돌 원본과 해소 작업을 서로 추적할 수 있습니다.

## 데이터 내구성과 동시성 안전

- PostgreSQL `cell_conflicts` 테이블에 워크북·시트·작업·좌표·기준/충돌/서버 버전, 양쪽 작업자와 클라이언트, 전체 셀 스냅샷, 상태, revision, 결정자, 결정 작업과 시각을 저장합니다.
- 충돌 생성은 원래 셀 변경 및 `cell_operations` 작업 로그와 같은 PostgreSQL 트랜잭션에서 커밋됩니다. 셀 변경만 승인되고 충돌 비교 자료가 빠지는 중간 상태를 허용하지 않습니다.
- `operation_id + row + column` 유일 제약으로 한 작업의 같은 셀 충돌이 중복 생성되지 않으며, 워크북·상태 및 시트·좌표 인덱스로 열린 충돌과 이력을 조회합니다.
- 해소 요청에는 `idempotency_key`와 `expected_revision`이 필수입니다. 같은 요청을 재전송하면 셀 변경이나 워크북 버전을 중복 생성하지 않습니다.
- PostgreSQL 행 잠금으로 같은 충돌에 대한 동시 해소를 직렬화합니다. 먼저 완료된 결정만 반영되고 다른 결정은 revision 충돌로 거부됩니다.
- 복원은 현재 서버 셀이 충돌 당시 임시 적용 셀과 동일할 때만 허용합니다. 충돌 후 제3의 변경이 있었다면 `409 Conflict`로 중단하여 최신 값을 덮어쓰지 않습니다.
- 해소용 셀 작업이 커밋된 직후 프로세스가 중단되어 충돌 상태 갱신이 늦어진 경우에도, 같은 idempotency key 재시도로 이미 커밋된 작업을 찾아 충돌 상태를 안전하게 마무리합니다.
- 메모리 저장소와 PostgreSQL 저장소가 같은 비교·revision·멱등·복원 계약을 구현합니다.
- 런타임 최종 상태는 계속 PostgreSQL이며 Redis, 외부 메시지 브로커 또는 인터넷 연결을 필수 구성으로 추가하지 않았습니다.

## 편집기 충돌 비교 화면

- 상단 저장 상태에 열린 충돌 수를 표시하는 주황색 배지를 추가하고, 배지와 시트 상태 표시줄을 눌러 충돌 패널을 열 수 있습니다.
- 툴바에 독립된 **편집 충돌** 버튼을 추가했습니다. 현재 사용자의 저장 작업에서 충돌이 감지되면 배지와 목록이 즉시 갱신됩니다.
- 오른쪽 패널은 시트와 A1 주소, 기준·충돌 버전, 시각, 충돌 작업자를 보여주며 해당 셀로 바로 이동할 수 있습니다.
- **충돌 전 기준**, **먼저 반영된 값**, **현재 서버 값**을 나란히 표시하고, 현재 값이 당시 제출값과 달라졌다면 **당시 내 제출 값**도 별도로 표시합니다.
- 수식은 수식 문자열과 계산 결과를 함께 보여주고 굵게·기울임·배경색·글자색 같은 주요 서식 차이도 표시합니다.
- 충돌 뒤 셀이 다시 바뀌면 복원 버튼을 비활성화하고 이유를 안내합니다. 서버도 같은 검사를 반복하므로 UI 우회 요청으로 최신 변경을 덮어쓸 수 없습니다.
- **해소된 충돌 이력 포함** 선택으로 처리 방식, 처리자와 처리 버전을 다시 볼 수 있습니다.
- 공동 편집의 `workbook.version`과 `operation.conflict` 이벤트에서 충돌 목록을 갱신하고, 해소 작업은 다른 편집자에게 일반 셀 작업과 버전 이벤트로 즉시 전파됩니다.

## REST API 및 MCP

- REST 조회: `GET /api/v1/workbooks/{workbookId}/conflicts?include_resolved=true|false`
- REST 단건 조회: `GET /api/v1/conflicts/{conflictId}`
- REST 해소: `POST /api/v1/conflicts/{conflictId}:resolve`
- MCP 조회: `spreadsheet.conflict.list`, `spreadsheet.conflict.get`
- MCP 해소: `spreadsheet.conflict.resolve`
- 해소 값은 `keep_current` 또는 `restore_previous`이며 REST와 MCP 모두 같은 저장소와 검증·멱등·revision·공동 편집 전파 경로를 사용합니다.
- 조회는 `range.read`, 해소는 `range.write` scope를 검사합니다. 개인 API 키로 MCP를 사용할 때는 기존과 같이 `mcp.use` scope도 필요합니다.
- 충돌 생성 직후 반환되는 `MutationResult.conflicts`에도 영속 충돌 ID, 전체 비교 스냅샷과 actor/version 정보가 포함되므로 WebSocket·REST·MCP 클라이언트가 같은 계약을 사용합니다.

## 제한과 안전장치

- `restore_previous`는 충돌 직전에 서버에 먼저 반영되어 있던 상대 사용자 셀 전체를 복원합니다. 사용자의 더 오래된 기준 셀은 비교 자료로 보존되지만 복원 대상으로 자동 선택하지 않습니다.
- `keep_current`도 아무 기록 없이 상태만 닫지 않고 현재 셀을 하나의 명시적 작업으로 재확인하여 버전 이력에 남깁니다.
- 이미 해소된 충돌에 다른 결정을 제출하면 revision 충돌로 거부합니다. 같은 결정을 재전송하면 기존 해소 작업을 반환합니다.
- 삭제된 워크북이나 시트의 충돌 레코드는 PostgreSQL 외래 키 정책과 메모리 저장소 정리 정책에 따라 함께 제거됩니다.
- 복원 작업은 데이터 검증, 수식 증분 재계산, 배열 수식 보호와 기존 셀 스타일 검증을 우회하지 않습니다.

## 검증

- 전체 Go 단위 테스트와 `go vet ./...` 정적 검사를 통과했습니다.
- 실제 PostgreSQL 5432 통합 테스트 전체를 통과했습니다.
- 메모리 저장소에서 기준·상대·제출·적용·현재 셀 비교, 값과 서식 복원, 열린/해소 이력, revision과 멱등 재시도, 후속 변경 시 복원 거부를 검증했습니다.
- 실제 PostgreSQL에서 서버 재시작 후 충돌 재조회, 원자적 충돌 저장, 해소 작업의 버전 증가와 셀 복원, 열린 목록 제거와 해소 이력을 검증했습니다.
- 해소 작업 커밋과 충돌 상태 갱신 사이 장애를 모사하고 같은 idempotency key 재시도로 중복 버전 없이 복구되는 경로를 검증했습니다.
- REST 목록·단건·해소와 MCP `spreadsheet.conflict.list|get|resolve`, 입력 스키마 및 `range.read`/`range.write` scope 계약을 검증했습니다.
- React/Vitest 17개 테스트 파일, 57개 테스트에서 비교 타임라인, 셀 이동, 복원 요청 계약과 후속 변경 시 버튼 차단을 포함한 프런트엔드 회귀를 검증했습니다.
- TypeScript/Vite 프로덕션 빌드와 실제 컨테이너 기반 Playwright E2E 29건을 통과했습니다.
- Docker 이미지를 PostgreSQL 전용 구성으로 다시 빌드하고 자동 마이그레이션, health check, 버전 endpoint와 오프라인 이미지 아카이브 무결성을 확인했습니다.

## 업그레이드 참고

- 서버 시작 시 `011_cell_conflicts.sql`이 자동 적용되어 충돌 기록과 조회 인덱스를 생성합니다.
- 필수 런타임 환경 변수는 기존과 동일하게 `POSTGRES_DSN` 하나이며 PostgreSQL 기본 포트 5432를 사용할 수 있습니다.
- 기존 셀 작업, 워크북 버전과 스냅샷 형식은 그대로 호환됩니다. 업그레이드 전 작업에는 영속 충돌 레코드가 없고 업그레이드 후 감지된 충돌부터 목록에 나타납니다.
- 기존 API 키가 `range.read`/`range.write`를 이미 포함하면 새 충돌 도구를 바로 사용할 수 있습니다. 필요한 scope가 없다면 개인화 화면에서 키를 수정하거나 회전합니다.
- 오프라인 번들은 `kanpic-v0.13.0.tar.gz`와 SHA-256 파일로 제공되며 Docker에 로드한 뒤 기존 PostgreSQL 5432 인스턴스에 연결하면 됩니다.
