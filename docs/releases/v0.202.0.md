## 릴리즈 요약

v0.202.0은 서버 로그를 **기간으로 거르고 CSV로 내보냅니다.** 감사 대응에 필요한 것입니다.

## 화면을 긁는 수밖에 없었습니다

감사에서는 "그 기간 기록을 주세요" 라고 합니다. 그런데 로그 화면에는 **기간이 아예 없었고** 200건에서 끊겼습니다.

## 기간

시작·끝 날짜만 적으면 **그 날이 통째로** 들어갑니다. `2026-01-06` 이라고 적은 사람은 그 날을 뜻하지 그 날 0시 한 순간을 뜻하지 않습니다. 그렇게 하지 않으면 **마지막 날의 기록이 통째로 빠지고**, 그것을 알아채는 사람은 없습니다.

끝이 시작보다 앞이면 **거절합니다.** 그대로 두면 늘 빈 파일이 나오고, 사람은 기록이 없다고 믿습니다.

## CSV 내보내기

화면에 건 조건을 **그대로** 씁니다. 물음을 한 곳에서 만들어 화면과 내보내기가 나눠 씁니다 — 따로 만들면 감사에 넘긴 파일과 화면에서 본 것이 달라집니다. 인쇄 미리보기에서 같은 잘못을 두 번 했습니다.

- **개수를 자르지 않습니다.** 감사에 넘길 파일이 조용히 잘려 있으면 없느니만 못합니다 — 받은 사람은 그것이 전부라고 믿습니다.
- 한 줄씩 흘려 보내므로 기록이 많아도 서버 메모리를 채우지 않습니다.
- 파일 앞에 **BOM** 을 붙입니다. 받은 사람이 엑셀로 여는 것이 보통이고, 없으면 한글이 깨집니다.
- 내보내는 도중에 끊기면 **파일 끝에 그렇게 적습니다.** 머리글이 이미 나간 뒤라 상태 코드를 바꿀 수 없으므로, 조용히 끊기는 것보다 낫습니다.

```bash
curl -H "X-Kanpic-Actor: admin" \
  "https://kanpic.example/api/v1/admin/logs.csv?from=2026-01-01&to=2026-01-31&level=ERROR" \
  -o kanpic-logs-1월.csv
```

## 검증 결과

- 사람이 적을 법한 꼴을 읽는지, 끝 날짜가 통째로 들어가는지, 거꾸로 적은 기간을 잡는지 시험합니다.
- 브라우저에서 화면의 조건이 내보내기 링크에 그대로 붙는지와, 실제로 CSV가 BOM과 머리글을 달고 내려오는지까지 확인합니다.
- 웹 시험 457개와 Go 시험 전체가 통과하고 `gofmt` 도 확인했습니다.
