## 릴리즈 요약

v0.90.0은 **오프라인 편집이 돌아왔을 때 벌어지는 일들을 확인하고 테스트로 묶습니다.** 제품 결함은 찾지 못했습니다. 최근에 따로따로 만든 기능들이 겹쳤을 때 제대로 맞물리는지가 궁금해 다섯 가지 상황을 실제로 만들어 봤습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다. 제품 동작은 v0.89.0과 같습니다.

## 눌러 본 다섯 가지

| 상황 | 결과 |
| --- | --- |
| 끊긴 채로 세 셀 입력 후 복구 | 세 값 모두 서버에 반영, 상태 표시도 `오프라인 · 로컬 저장` → `모든 변경사항 저장됨` |
| 끊긴 채로 입력하고 **탭을 닫은 뒤** 다시 열기 | 대기열이 살아남아 연결되자마자 전송 |
| 끊긴 동안 다른 사람이 **위쪽 행 삭제** | 내 편집이 원래 겨냥한 줄을 따라감(B5 → B4) |
| 끊긴 동안 **내가 쓰던 행이 삭제** | 그 편집만 반영되지 않고 `편집 1곳이 반영되지 않았습니다 · B3` 안내 |
| 끊긴 동안 **워크북이 삭제** | `저장 오류` 와 함께 알리고 대기열을 비움 (무한 재시도 없음) |

세 번째와 네 번째는 v0.80.0의 서버 재배치, v0.77.0의 안내, 그리고 오프라인 대기열이 한꺼번에 맞물려야 나오는 결과입니다. 따로 만든 것들이라 겹쳤을 때를 확인한 것은 처음입니다.

## 테스트로 묶은 이유

기존 오프라인 시나리오는 기능별 재전송(서식·병합·정렬·채우기)을 확인합니다. 위의 **겹치는 경우**는 어느 것도 확인하지 않고 있었습니다. 조용히 깨지면 사용자는 자기가 친 값이 어디로 갔는지 알 수 없는 종류의 문제입니다.

세 가지를 E2E로 더했습니다. 탭을 닫았다 여는 경우, 남의 삭제로 자리가 밀리는 경우, 겨냥한 행이 사라지는 경우입니다.

## 검증 결과

- 다섯 가지를 브라우저로 직접 확인한 뒤, 그중 셋을 시나리오로 남겼습니다. 새 시나리오는 세 번 연속 통과했습니다.
- 오늘 확인한 동작을 고정하는 테스트이므로, 고치기 전 실패를 보이는 종류는 아닙니다.
- `go vet ./...`, `go test ./...`, `go test -tags integration ./internal/...`, React/Vitest 263개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 148건을 통과했습니다.
