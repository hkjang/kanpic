## 릴리즈 요약

v0.190.0은 **화면과 서버가 같은 글자를 같은 날로** 읽게 합니다.

## 브라우저가 서버보다 너그러웠습니다

날짜 검증에서 화면은 `Date.parse` 를 그대로 썼습니다.

| 값 | 화면 | 서버 |
| --- | --- | --- |
| `2023/03/15` | 받음 | 물리침 |
| `March 15, 2023` | 받음 | 물리침 |
| `3/15/2023` | 받음 | 물리침 |

화면이 "괜찮다" 하고 값을 적어 넣으면 서버가 그 묶음을 물리칩니다. **사람은 값이 나타났다 사라지는 것을 봅니다.** 왜인지는 아무 데도 적히지 않습니다.

## 둘 다 받아 주면서 다른 날로 읽었습니다

```
"2023-03-15 00:00:00"   서버 2023-03-15T00:00Z
                        화면 2023-03-14T15:00Z
```

자리를 적지 않은 꼴을 브라우저는 **그 자리의 시각** 으로 읽습니다. 한국에서는 아홉 시간이 밀려 하루가 어긋납니다. `2023-03-15 이후` 라는 검증이 같은 값에 대해 화면과 서버에서 **다른 답** 을 냅니다.

## 서버가 읽는 것만 읽습니다

`2023-03-15`, `2023-03-15 16:12:00`, `2023-03-15T16:12:00Z` 세 가지입니다. 자리를 적지 않은 꼴은 UTC로 봅니다. 13월이나 2월 30일은 날짜가 아닙니다 — `Date.UTC` 는 다음 달로 넘겨 버리므로 직접 봅니다.

## 붙잡는 목록

`testdata/validation-dates.json` 을 두 곳이 함께 읽습니다. 목록에는 **브라우저가 기꺼이 읽어 주지만 서버가 물리치는 것들** 을 넣었습니다. 그런 것을 넣지 않으면 둘 다 틀린 채로 서로 맞아 붙잡히지 않습니다 — 표시 형식에서 두 번 그랬습니다.
