## 릴리즈 요약

v0.124.1은 **반올림이 사람이 적은 십진수를 따르지 않던 것** 을 고칩니다. `=ROUND(1.005,2)`가 `1.00`이었습니다. 엑셀과 시트는 `1.01`을 냅니다.

## 1원이 어긋난다

돈을 다루는 표에서 두 자리 반올림은 가장 흔한 셈입니다. 그 결과가 1원 어긋나면, 합계가 맞지 않는데 **어느 줄이 틀렸는지 눈으로 찾을 방법이 없습니다**. 각 줄은 저마다 그럴듯해 보이기 때문입니다.

`1.005`는 이진 실수로 `1.00499999999999989…`로 담깁니다. 100을 곱해 반올림하면 `100`이 되어 `1.00`이 나옵니다. 표 프로그램은 값을 열다섯 자리로 보고 셈하므로 `1.005` 그대로 반올림해 `1.01`을 냅니다.

## 틀린 방향이 일정하지 않았다

더 고약한 점이 있었습니다. `=ROUND(2.675,2)`는 **맞았습니다**. `2.675*100`이 이진 실수에서 마침 `267.5`로 떨어지기 때문입니다. `1.005*100`은 떨어지지 않습니다.

어떤 값은 맞고 어떤 값은 틀리면, 규칙을 알아도 미리 가려낼 수 없습니다. 고르게 틀리는 것보다 나쁩니다.

## 두 단계로 센다

```
1. 먼저 열다섯 자리로 다듬는다   (표 프로그램이 값을 보는 방식)
2. 그 십진수를 분수로 옮겨 자른다 (어긋남 없이)
```

첫 단계가 없으면 새 버그가 생깁니다. `0.1+0.2`는 `0.30000000000000004`로 담기므로, 십진수로만 자르면 `=ROUNDUP(0.1+0.2,1)`이 `0.4`가 됩니다. 엑셀은 `0.3`입니다. 두 경우가 서로 **반대 방향** 이라 한쪽만 맞추면 다른 쪽이 어긋납니다.

`ROUNDUP`과 `ROUNDDOWN`도 같은 셈을 씁니다. 세 함수가 서로 다른 답을 내면 안 됩니다.

| 수식 | 고치기 전 | 지금 |
| --- | --- | --- |
| `=ROUND(1.005,2)` | 1.00 | **1.01** |
| `=ROUND(0.615,2)` | 0.62 | 0.62 |
| `=ROUND(8.475,2)` | 8.48 | 8.48 |
| `=ROUNDUP(0.1+0.2,1)` | 0.4 | **0.3** |

## 검증 결과

- 고치기 전 코드에서 세 가지가 걸립니다. 그 중 하나가 `ROUNDUP(0.1+0.2,1)`로, 다듬는 단계를 빼면 **새로 생기는** 버그입니다.
- 중간값의 방향(0에서 먼 쪽), 음수 자릿수(`ROUND(1234,-2)` = 1200), 자릿수 생략까지 함께 확인했습니다.
- `ROUND` 한 번이 863ns에서 2421ns가 됩니다. 수식 만 개를 다시 셈해도 15ms 차이입니다.
- `MROUND`, `CEILING`, `FLOOR`는 아직 이진 셈입니다. 따로 두었습니다.
