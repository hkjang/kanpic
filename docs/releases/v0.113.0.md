## 릴리즈 요약

v0.113.0은 조건부 서식에 **아이콘 집합**을 더합니다. 값의 자리에 따라 셀 왼쪽에 신호등·화살표·기호·사분원이 붙습니다. 엑셀에서 가장 많이 쓰는 조건부 서식 중 kanpic에 없던 마지막 종류이고, 엑셀 파일과 양방향으로 오갑니다.

마이그레이션 `032_conditional_icon_set.sql` 이 하나 늘었습니다. 서버 기동 시 자동 실행됩니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 색만으로는 부족하다

kanpic에는 색 눈금과 데이터 막대가 있었습니다. 둘 다 **색**으로만 말합니다. 색을 구분하기 어려운 사람에게는 아무 말도 하지 않고, 흑백으로 인쇄하면 모두에게 같은 회색이 됩니다.

아이콘 집합은 같은 것을 색이 아닌 것으로도 말합니다. 화살표는 방향이, 기호는 모양이, 사분원은 채운 넓이가 색과 같은 말을 한 번 더 합니다. 신호등만은 엑셀과 마찬가지로 색으로만 구분되므로, 색이 유일한 단서가 되면 곤란한 표에는 다른 집합을 고르십시오.

| 집합 | 아이콘 |
| :--- | :--- |
| 신호등 3개 | 빨강·주황·초록 원 |
| 화살표 3개 | 아래·가로·위 |
| 기호 3개 | ✗ · ! · ✓ |
| 화살표 4개 | 아래·비스듬히 아래·비스듬히 위·위 |
| 화살표 5개 | 아래·비스듬히 아래·가로·비스듬히 위·위 |
| 사분원 5개 | 빈 원부터 꽉 찬 원까지 |

## 엑셀과 같은 자리에서 나눈다

범위의 최솟값과 최댓값 사이를 엑셀의 기본값과 **같은 자리**에서 나눕니다. 아이콘 3개는 33%·67%, 4개는 25%·50%·75%, 5개는 20%·40%·60%·80% 입니다.

3분의 1(33.33%)이 아니라 33% 입니다. 정확히 33% 자리에 있는 값이 kanpic에서는 가운데 아이콘, 엑셀에서는 아래 아이콘이 되면 같은 파일을 두 곳에서 열었을 때 다른 그림이 됩니다.

**순서 뒤집기**를 켜면 작은 값이 첫 아이콘을 받습니다. 오류 건수나 처리 시간처럼 작을수록 좋은 열에 씁니다.

## 값을 가리지 않는다

아이콘이 붙은 칸의 값은 아이콘 너비만큼 오른쪽으로 물러납니다. 아이콘이 값 위에 겹치면 도움이 아니라 방해입니다. 열이 좁아 아이콘과 값이 함께 들어가지 못하면 숫자는 `####` 로 바뀝니다 — 잘린 숫자를 보여 주는 것보다 열이 좁다고 말하는 편이 낫습니다.

## 엑셀 파일과 오간다

내보낼 때 엑셀의 아이콘 집합 규칙으로 나가고, 읽을 때 그대로 돌아옵니다. 순서 뒤집기도 함께 갑니다.

엑셀에는 kanpic이 그리지 못하는 집합(깃발, 별, 삼각형 등)도 있습니다. 그런 규칙은 **버리지 않고** 같은 개수의 집합으로 바꿔 읽습니다. 깃발 3개는 신호등 3개가 됩니다. 세 단계로 나눈다는 뜻은 남고, 어느 아이콘인지만 달라집니다.

## 함께 고친 것

에이전트용 MCP 도구의 조건부 서식 스키마가 **오래된 채로 남아 있었습니다.** `rule_type` 목록에 값 조건·중복·색 눈금·데이터 막대 네 가지뿐이라, 이미 몇 릴리즈 전에 들어간 맞춤 수식과 상위·하위 N개는 스키마에 없는 채로 동작하고 있었습니다. 서버는 받아 주지만, 도구 설명만 읽는 에이전트는 그런 규칙이 있다는 것을 알 수 없고 스키마를 검사하는 MCP 클라이언트라면 보내기 전에 막습니다. 일곱 가지 전부와 순위 연산자, 수식 필드를 함께 넣었습니다.

## 알려진 한계

- 인쇄 미리보기에는 배경색·글자색 같은 셀 서식만 나갑니다. 아이콘과 데이터 막대는 화면에서만 그려집니다.
- 문턱값은 엑셀 기본값 그대로이고 직접 정할 수 없습니다. 아이콘만 보이고 값을 숨기는 설정도 아직 없습니다.

## 검증 결과

- 0부터 100까지 고르게 놓은 범위에서 각 칸이 받는 아이콘 번호를 확인합니다. 32%는 아래, 33%는 가운데 — 엑셀의 자리와 같은지 봅니다. 순서를 뒤집으면 번호가 뒤집히는지, 숫자가 아닌 칸은 아이콘을 받지 않는지도 봅니다.
- XLSX로 내보낸 파일을 다시 읽어 아이콘 종류와 순서 뒤집기가 그대로인지 확인합니다.
- 규칙 종류를 아이콘 집합에서 데이터 막대로 바꾸면 아이콘 설정이 남지 않는지 봅니다. 남으면 저장소에 쓸모없는 값이 쌓입니다.
- 브라우저 E2E로 **캔버스에 실제로 칠해졌는지** 셉니다. 그리는 코드를 지우고 같은 테스트를 돌려 이 확인이 실제로 잡는지도 검증했습니다.
- 색 이외의 단서가 있는지 단위 테스트가 봅니다. 신호등을 뺀 모든 집합에서 아이콘의 모양이 서로 달라야 통과합니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
