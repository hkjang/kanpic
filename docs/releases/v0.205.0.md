## 릴리즈 요약

v0.205.0은 **부서 관리자** 에게 구성원 계정 관리를 위임합니다.

## 관리자가 전역 하나뿐이었습니다

`AccessPrincipal.Admin` 이 불리언이고 `requireAdmin` 이 여덟 파일 **서른일곱 곳** 에서 문을 지킵니다. 범위라는 개념이 없었습니다.

부서마다 관리자를 둡니다. 맡은 부서와 **그 아래 부서** 의 구성원 계정만 다룹니다. 부서가 나뉘어도 맡은 사람이 바뀌지 않도록 아래까지 봅니다 — 팀이 둘로 갈라졌다고 관리자가 절반을 못 보게 되면 위임이 끊긴 것을 아무도 알아채지 못합니다.

| 열어 준 것 | 열지 않은 것 |
| --- | --- |
| 맡은 구성원 목록 보기 | 워크북 소유권 이전 |
| 계정 정지·해제, 메모 | 개요(조직 전체 숫자) |
| kanpic 역할 부여·회수 | 워크북 거버넌스 |
| 모든 세션 종료 | 설정·로그·API 키·AI 정책·메일 |
| | 사용자 등록·일괄 등록 |

## 왜 그 문들을 닫아 두었는가

- **소유권 이전**: 자료를 옮기는 일입니다. 잘못 옮기면 조용히 사고가 나고, 되돌리려면 누가 무엇을 가졌는지 다시 맞춰야 합니다.
- **개요**: 조직 전체 규모가 새어 나갑니다. 사용자 목록도 **맡은 구성원만** 보입니다 — 조직 명부가 보이면 위임한 범위 밖의 사람까지 알게 됩니다.
- **자기 자신**: 스스로 정지를 풀거나 역할을 얹을 수 있으면 위임이 아니라 **승격** 입니다. 같은 이유로 부서 관리자는 전역 관리자만 지정합니다.
- **사용자 등록**: 새로 만든 사용자는 아직 어느 부서에도 없어 만든 사람이 곧바로 볼 수 없습니다. 부서까지 함께 정하게 하려면 부여 경로가 하나 더 필요한데, 그것 없이 문만 열면 **만들고 못 보는** 일이 납니다.

## 검증 결과

- 맡은 구성원만 보이는지, 아래 부서 구성원이 들어오는지, 다른 부서 사람과 자기 자신을 막는지, 소유권 이전·개요·설정·사용자 등록이 닫혀 있는지, 부서 관리자가 스스로를 늘리지 못하는지 시험합니다.
- 브라우저에서 전역 관리자가 화면으로 지정하고, 그 사람으로 요청했을 때 **열린 문과 닫힌 문이 실제로 그런지** 까지 확인합니다.
- 웹 시험 457개와 Go 시험 전체가 통과하고 `gofmt` 도 확인했습니다.
