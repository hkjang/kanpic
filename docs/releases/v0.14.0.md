## 핵심 변경

- 편집기에 사내 LLM을 사용하는 **AI 도우미**를 추가했습니다. 사용자는 수식 생성, 수식 설명, 수식 오류 수정 요청을 자연어로 작성할 수 있습니다.
- AI 요청은 곧바로 셀을 수정하지 않습니다. 선택 범위와 요청을 바탕으로 계획을 만들고, 요약·설명과 셀별 현재/제안 수식을 미리 보여 준 뒤 사용자가 명시적으로 승인해야 적용합니다.
- 설명 모드는 항상 읽기 전용이며 변경 계획을 허용하지 않습니다. 수식 생성과 오류 수정도 모델이 제안한 수식만 적용할 수 있습니다.
- 승인된 AI 작업은 하나의 서버 권위 셀 작업과 새 워크북 버전으로 기록되며, 적용 직후 전체 작업을 Undo할 수 있습니다.
- 최근 AI 작업에서 승인 대기, 설명 완료, 적용 중, 적용됨, 취소 중, 취소됨, 실패 상태와 사용 모델을 다시 조회할 수 있습니다.

## 폐쇄망 AI Gateway 관리

- 관리자 콘솔에 **사내 AI Gateway 간편 연결** 카드를 추가했습니다. OpenAI 호환 `/v1` Gateway URL, 모델, API Key, 사설 CA, 제한 시간, 최대 입력 셀과 최대 변경 셀을 화면에서 관리합니다.
- `ai.enabled`, `ai.gateway_url`, `ai.model`, `ai.api_key`, `ai.ca_pem`, `ai.timeout_seconds`, `ai.max_input_cells`, `ai.max_changes`를 기존 설정 CRUD·revision·복원 체계에 통합했습니다.
- AI를 활성화하기 전에 전체 설정 검증과 `GET /v1/models` 연결 테스트를 실행할 수 있습니다. 사내 CA PEM과 선택적 Bearer API Key도 연결 시험에 반영됩니다.
- API Key와 CA 원문은 비밀 설정으로 저장되고 설정 조회 응답에 다시 노출되지 않습니다.
- 사내 vLLM 또는 OpenAI 호환 Gateway를 지정하면 외부 인터넷 없이 AI 기능 전체를 운영할 수 있습니다.
- 런타임 필수 환경 변수는 기존과 동일하게 `POSTGRES_DSN` 하나이며 Redis나 별도 AI 환경 변수를 추가하지 않았습니다.

## 데이터 최소화와 모델 출력 검증

- AI에는 사용자가 선택한 범위의 비어 있지 않은 셀, 셀 주소, 값과 수식, 작업 요청만 전달합니다. 워크북 전체, API Key, 설정 비밀이나 다른 시트 데이터는 요청 문맥에 포함하지 않습니다.
- 시스템 지시문은 모든 셀 값을 신뢰할 수 없는 데이터로 취급하고 셀 내용의 명령, 외부 링크, 도구·네트워크·비밀정보 요청을 따르지 않도록 제한합니다.
- Gateway 응답은 `summary`, `explanation`, `changes` JSON 객체로 파싱하며 각 변경은 `=`로 시작하는 수식이어야 합니다.
- 서버는 제안 좌표가 선택 범위 안인지, 같은 셀이 중복되지 않는지, 최대 변경 수를 넘지 않는지, 설명 모드에 변경이 포함되지 않았는지 다시 검증합니다.
- Gateway 응답 본문은 최대 2 MiB로 제한하고 관리자 설정의 요청 시간 제한을 적용합니다.

## 승인·Undo 내구성과 동시성 안전

- 계획 생성, 승인과 Undo에 각각 멱등 키를 사용합니다. 같은 요청을 재전송해도 Gateway 계획이나 셀 작업, 워크북 버전이 중복 생성되지 않습니다.
- 계획은 생성 시점의 정확한 워크북 버전을 저장합니다. 승인 전에 다른 셀을 포함한 워크북 변경이 하나라도 발생하면 오래된 AI 계획을 `409 Conflict`로 거부합니다.
- 승인 시 각 대상 셀의 값·수식·서식을 계획 당시 스냅샷과 다시 비교하고 모든 제안 수식을 하나의 원자적 작업으로 적용합니다.
- `planned → applying → applied`와 `applied → undoing → undone` 상태 전이를 PostgreSQL revision으로 직렬화하여 중복 승인과 동시 상태 변경을 방지합니다.
- 셀 작업 커밋 직후 프로세스가 중단되는 장애 구간에서도 동일 idempotency key 재시도로 기존 작업을 찾아 AI 상태를 마무리할 수 있습니다.
- Undo는 원래 AI 승인 작업을 사용자별 작업 이력으로 되돌리며 새로운 작업 ID와 서버 버전을 생성합니다.

## PostgreSQL 이력과 감사

- `ai_actions`에 요청자, 클라이언트, 선택 범위, 자연어 요청, 기준 버전, 모델, 미리보기 변경, 상태, revision, 승인·Undo 작업과 결과를 저장합니다.
- `ai_action_events`에 계획, 적용, Undo와 실패 이벤트별 모델·도구·결과를 시간순으로 저장합니다.
- 계획, 승인과 Undo의 주요 결과를 기존 `audit_logs`에도 연결하여 관리자 감사 체계에서 추적할 수 있습니다.
- 작업 조회는 요청자 본인으로 제한하여 같은 워크북에 접근할 수 있는 다른 사용자가 AI 요청 내용이나 계획 이력을 열람하지 못하게 합니다.
- 적용된 셀 작업은 기존 `cell_operations`, 워크북 버전, 협업 WebSocket 이벤트와 동일한 경로를 사용합니다.

## REST API 및 MCP

- REST 공개 설정: `GET /api/v1/ai/config`
- REST 계획: `POST /api/v1/ai/actions:plan`
- REST 이력: `GET /api/v1/workbooks/{workbookId}/ai/actions`
- REST 단건: `GET /api/v1/ai/actions/{actionId}`
- REST 승인·Undo: `POST /api/v1/ai/actions/{actionId}:approve`, `POST /api/v1/ai/actions/{actionId}:undo`
- MCP 도구: `spreadsheet.ai.config.get`, `spreadsheet.ai.action.plan`, `spreadsheet.ai.action.list`, `spreadsheet.ai.action.get`, `spreadsheet.ai.action.approve`, `spreadsheet.ai.action.undo`
- 개인 API 키 호출은 `ai.use`를 기본으로 검사합니다. 계획에는 `range.read`, 승인에는 `formula.write`, Undo에는 `range.write` scope가 추가로 필요하며 MCP 호출은 기존처럼 `mcp.use`도 필요합니다.
- REST와 MCP는 같은 PostgreSQL 오케스트레이터, 권한, revision, 멱등, 감사 및 협업 전파 경로를 사용합니다.

## 편집기와 관리자 화면

- 편집기의 AI 패널은 현재 선택 범위, 전달 가능한 최대 셀 수와 사용 모델을 항상 표시합니다.
- 계획 미리보기는 각 셀의 A1 주소와 현재 값·수식, 제안 수식을 나란히 보여 주고 예상 변경 셀 수와 기준 워크북 버전을 표시합니다.
- 승인 전에는 쓰기 API를 호출하지 않으며 읽기 전용 설명에는 승인 버튼을 표시하지 않습니다.
- 적용 결과에는 새 서버 버전을 표시하고 Undo를 바로 제공하며, 최근 작업에서 이전 계획과 상태를 다시 열 수 있습니다.
- 관리자 AI 설정과 개인 API 키의 `ai.use` scope를 각각 `/admin`과 `/preferences`에 분리해 제공했습니다.

## 업그레이드 참고

- 서버 시작 시 `012_ai_actions.sql`과 `013_ai_action_completed.sql`이 자동 적용되어 AI 작업·이벤트 테이블, 조회 인덱스와 읽기 전용 완료 상태를 생성합니다.
- AI는 기본적으로 비활성화되어 기존 설치의 동작과 데이터 흐름을 바꾸지 않습니다. 업그레이드 후 관리자 콘솔에서 Gateway URL과 모델을 입력하고 **전체 검증**, **연결 테스트**, `ai.enabled` 활성화 순서로 설정합니다.
- OpenAI 호환 Gateway는 `POST /v1/chat/completions`와 연결 시험용 `GET /v1/models`를 제공해야 합니다. Gateway URL이 `/v1`로 끝나지 않아도 서버가 표준 경로를 조합합니다.
- 기존 개인 API 키에는 `ai.use`가 자동 추가되지 않습니다. AI 기능을 사용할 키는 개인화 화면에서 필요한 scope를 추가하거나 회전합니다.
- 기존 워크북, 셀 작업, 충돌, 버전과 설정 revision 형식은 그대로 호환됩니다.
- 오프라인 번들은 `kanpic-v0.14.0.tar.gz`와 SHA-256 파일로 제공되며 Docker에 로드한 뒤 기존 PostgreSQL 5432 인스턴스에 연결하면 됩니다.
