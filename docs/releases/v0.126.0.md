## 릴리즈 요약

v0.126.0은 **값 하나짜리 함수가 배열을 받으면 칸마다 따로 셈하도록** 합니다. `=SUMPRODUCT(--ISNUMBER(A1:A100))` 같은, 표에서 조건에 맞는 칸을 세는 가장 흔한 꼴이 이제 됩니다.

## 하나를 쫓다 여럿을 찾았다

v0.125.2에서 `NOT`이 배열을 못 받던 까닭을 쫓았습니다. 인수를 낱낱이 펴는 자리보다 **뒤** 에서 셈하기 때문이었습니다. 펴고 나면 배열 하나와 값 여럿을 가릴 수 없어 "인수는 하나여야 한다"에 걸립니다.

같은 자리에 있는 함수를 모두 살펴보니, 하나도 빠짐없이 그랬습니다.

```
=SUMPRODUCT(--ISNUMBER(A1:A5))    #VALUE!
=SUMPRODUCT(--ISTEXT(A1:A5))      #VALUE!
=SUMPRODUCT(--ISBLANK(A1:A5))     #VALUE!
=SUMPRODUCT(--(LEN(A1:A5)>0))     #VALUE!
=SUMPRODUCT(ABS(A1:A5))           #VALUE!
```

## COUNTIF로 적을 수 없는 조건

`COUNTIF`는 값과 견주는 조건만 셉니다. **"숫자가 든 칸이 몇 개인가"** 나 **"비어 있지 않은 칸이 몇 개인가"** 는 값과 견주는 조건이 아니라서, 위의 꼴 말고는 셀 방법이 없습니다.

그 방법이 통째로 막혀 있었습니다.

## 되부르기

펴기 전에 가로채, 배열이 섞여 있으면 칸마다 갈라 **같은 함수를 그대로 되부릅니다**. 셈하는 자리를 새로 만들지 않았으므로, 함수 하나를 고치면 홑값과 배열이 **함께** 고쳐집니다.

```
ABS INT SIGN SQRT TRUNC ROUND ROUNDUP ROUNDDOWN EXP LN LOG10
LEN UPPER LOWER PROPER TRIM VALUE N T TEXT
ISNUMBER ISTEXT ISNONTEXT ISBLANK ISLOGICAL ISEVEN ISODD TYPE
```

배열이 여럿이면 모양이 같아야 하고, 홑값은 칸마다 되풀이해 씁니다. 그래서 `=TEXT({0.5;45306},"hh:mm")`처럼 배열과 홑값을 섞어 쓸 수 있습니다.

모으는 함수(`SUM`, `COUNT` 같은)는 넣지 않았습니다. 배열을 펴서 하나로 줄이는 것이 그쪽이 하는 일입니다.

## 검증 결과

- 고치기 전 코드에서 걸립니다.
- 실제 서버에서 열여덟 가지를 확인했습니다. 홑값 셈(`=ABS(-3)`, `=LEN("abc")`)은 그대로입니다.
- 모양이 다른 배열끼리 짝지으면 `#VALUE!`입니다.
- Go 시험 전체와 웹 시험 376개가 통과합니다.
