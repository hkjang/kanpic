## 핵심 변경

- AI 도우미에 **선택 범위 요약**, **이상치 탐지**, **데이터 정제**를 추가했습니다. 기존 수식 생성·설명·오류 수정과 합쳐 여섯 가지 작업을 같은 안전 실행 흐름에서 사용할 수 있습니다.
- 범위 요약과 이상치 탐지는 읽기 전용입니다. 분석 결과와 구조화된 발견 항목만 반환하며 승인 또는 셀 쓰기를 허용하지 않습니다.
- 데이터 정제는 셀별 현재 값과 제안 값을 먼저 비교하고 사용자가 명시적으로 승인한 뒤 한 번의 원자적 서버 작업으로 반영합니다. 적용 직후 전체 작업을 Undo할 수 있습니다.
- 이상치 결과에는 심각도, 제목, 설명, A1 주소와 모델 응답이 아닌 현재 서버 셀 스냅샷을 함께 표시합니다.

## AI 출력 검증과 안전 경계

- Gateway 출력 계약을 작업 유형별로 분리했습니다. 수식 생성·오류 수정은 `=`로 시작하는 수식만, 데이터 정제는 문자열·숫자·불리언 JSON 스칼라 또는 명시적 `clear`만 허용합니다.
- 데이터 정제에서 `null`, 객체, 배열, 수식, 값과 `clear`의 동시 지정, 중복 좌표, 선택 범위 밖 좌표와 변경 한도 초과를 거부합니다.
- 설명·요약·이상치 탐지 응답에 셀 변경이 들어 있으면 전체 계획을 거부합니다. 이상치 발견은 선택 범위 안의 실제 셀에만 연결할 수 있고, 요약의 범위 전체 발견은 셀 주소 없이 기록할 수 있습니다.
- 발견 항목의 셀 값·수식은 모델이 제공한 내용을 신뢰하지 않고 PostgreSQL에서 읽은 계획 시점 스냅샷으로 대체합니다.
- 모든 셀 내용은 계속 신뢰할 수 없는 데이터로 취급합니다. 시스템 지시문은 셀 안의 명령, 외부 링크, 도구 호출, 네트워크 접근과 비밀정보 요청을 따르지 않도록 제한합니다.
- 모델 응답 크기, 설명 길이, 값 크기, 발견·변경 개수는 서버에서 제한합니다.

## 승인, 동시성 및 Undo

- 읽기 전용 분석은 계획 생성과 동시에 `completed` 상태로 저장되며 승인 endpoint로 다시 실행할 수 없습니다.
- 데이터 정제 승인은 계획 당시의 정확한 워크북 버전과 대상 셀의 값·수식·서식을 다시 비교합니다. 중간 변경이 있으면 `409 Conflict`로 중단해 다른 사용자의 변경을 덮어쓰지 않습니다.
- 승인된 정제는 기존 서버 권위 `ApplyCells` 경로를 사용해 하나의 작업 ID와 새 워크북 버전으로 저장되고 WebSocket 협업 이벤트로 전파됩니다.
- 셀 비우기도 기존 서식을 보존하는 명시적 콘텐츠 변경으로 처리됩니다.
- 승인과 Undo는 기존 멱등 키 및 revision 상태 전이를 사용하므로 재시도해도 작업이나 버전이 중복 생성되지 않습니다.

## PostgreSQL 이력과 감사

- `014_ai_analysis_clean.sql`이 AI 작업 모드 제약에 `summarize`, `anomaly`, `clean`을 추가하고 구조화된 `findings` JSONB 컬럼을 생성합니다.
- 요약·이상치 결과, 제안된 정제 값, 기준 버전, 모델, 요청자와 상태를 `ai_actions`에 보존합니다.
- 계획과 분석 완료는 `range.read`, 정제 적용은 `data.clean`, 취소는 `operation.undo` 도구 이벤트로 `ai_action_events`와 `audit_logs`에 기록합니다.
- 기존 워크북·셀 작업·버전·AI 작업과 설정 revision은 그대로 호환되며 서버 기동 시 마이그레이션이 자동 적용됩니다.

## REST API와 MCP

- 기존 `POST /api/v1/ai/actions:plan`의 `mode`에 `summarize`, `anomaly`, `clean`을 추가했습니다. 작업 조회 응답에는 구조화된 `findings`가 포함됩니다.
- REST 및 MCP 승인 권한을 작업별 최소 scope로 분리했습니다. 수식 생성·오류 수정은 `formula.write`, 데이터 정제는 `range.write`가 필요합니다.
- 계획에는 `ai.use`와 `range.read`, Undo에는 `ai.use`와 `range.write`가 필요합니다. MCP 호출에는 기존처럼 `mcp.use`도 필요합니다.
- `spreadsheet.ai.action.plan|list|get|approve|undo`는 REST와 같은 PostgreSQL 오케스트레이터, 권한, 검증, 멱등, 감사 및 협업 전파 경로를 사용합니다.

## 편집기 경험

- AI 작업 선택기에 여섯 가지 모드와 목적별 예시 요청을 제공합니다.
- 범위 요약과 이상치 탐지는 분석 결과 카드와 심각도별 발견 카드로 표시하며 읽기 전용 완료 상태를 명확히 구분합니다.
- 데이터 정제 미리보기에는 현재 값과 제안 값 또는 셀 비우기를 표시합니다. 승인 전에는 쓰기 API를 호출하지 않습니다.
- 최근 작업에서 요약 완료, 탐지 완료, 설명 완료, 승인 대기, 적용, 취소와 실패 상태를 다시 확인할 수 있습니다.

## 설정과 폐쇄망 운영

- 새 런타임 환경 변수나 외부 서비스는 필요하지 않습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며 Redis 없이 실행됩니다.
- 기존 관리자 화면의 `ai.max_input_cells`와 `ai.max_changes`가 분석 발견 수와 정제 변경 수에도 동일하게 적용됩니다.
- 사내 OpenAI 호환 Gateway와 사설 CA, API Key, 모델, 제한 시간은 계속 관리자 화면에서 CRUD·revision·복원·검증·연결 테스트할 수 있습니다.
- 런타임의 AI 요청은 설정된 사내 Gateway만 사용하므로 완전 폐쇄망에서 동작합니다.

## 업그레이드 참고

- 서버가 시작되면 `014_ai_analysis_clean.sql`을 자동 적용합니다. 별도 수동 DDL 작업은 필요하지 않습니다.
- AI Gateway는 기존처럼 `POST /v1/chat/completions`와 연결 시험용 `GET /v1/models`를 제공해야 합니다.
- 기존 개인 API 키에 새 scope는 자동 추가되지 않습니다. 데이터 정제 승인이 필요한 키는 개인화 화면에서 `range.write`를 추가하거나 키를 회전합니다.
- AI는 기본적으로 비활성화 상태를 유지하며 기존 관리자 설정, Gateway 연결 및 데이터 흐름을 변경하지 않습니다.
