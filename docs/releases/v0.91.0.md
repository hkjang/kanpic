## 릴리즈 요약

v0.91.0은 **역할별로 무엇을 할 수 있는지 API에서 하나씩 확인한 결과**입니다. 권한 결함은 찾지 못했고, 문서 한 줄이 실제 동작과 달라 고쳤습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다. 제품 동작은 v0.90.0과 같습니다.

## 화면에서 막힌 것이 API에서도 막히는가

화면은 권한이 없으면 버튼을 감춥니다. 그것만으로는 아무것도 보장하지 않습니다. 뷰어 자격으로 **바꾸는 요청 열여섯 가지** 를 직접 보냈습니다.

셀 쓰기, 붙여넣기, 정렬, 행 삭제, 시트 추가, 시트 삭제, 워크북 이름 변경, 워크북 삭제, 공유 변경, 이름 범위 생성, 차트 생성, 필터 보기 생성, 범위 보호, 레이아웃 변경, 버전 스냅숏, 댓글 작성 — **열여섯 가지 모두 403** 이었습니다.

댓글 작성자와 편집자도 같은 방식으로 확인했습니다.

| 동작 | 뷰어 | 댓글 작성자 | 편집자 |
| --- | --- | --- | --- |
| 워크북 읽기 | O | O | O |
| 셀 쓰기 | 403 | 403 | O |
| 댓글 쓰기 | 403 | O | O |
| 이름 범위 만들기 | 403 | 403 | O |
| 시트 추가 | 403 | 403 | O |
| 소유권 이전 | 403 | 403 | 405 |

## 문서가 틀렸던 한 줄

역할 표에 **워크북 삭제** 가 소유자만의 권한으로 적혀 있었습니다. 실제로는 **편집자도 휴지통으로 옮길 수 있습니다.** 재공유와 같은 스위치에 묶여 있어, 공유를 잠그면 둘 다 막힙니다.

어느 쪽을 고칠지 생각한 끝에 문서를 고쳤습니다. 편집자가 옮긴 워크북은 소유자의 휴지통에 나타나고 소유자가 데이터까지 그대로 복원할 수 있음을 확인했으므로, 되돌릴 수 없는 동작이 아닙니다. 권한 모델을 조용히 바꾸는 것보다 실제 동작을 정확히 적는 편이 맞습니다.

## 테스트로 묶은 이유

역할 규칙은 말하기는 쉽고 흘리기도 쉽습니다. 검사를 잊은 엔드포인트 하나면 읽기 권한만 가진 사람이 남의 시트를 고쳐 쓸 수 있습니다. 기존 테스트는 접근 요청 흐름과 뷰어의 셀 쓰기 한 가지만 보고 있었습니다.

역할 넷 × 동작 다섯을 표로 적고 스무 가지를 모두 확인하는 테스트를 더했습니다. 기대값을 역할마다 따로 적어 두어, 어느 하나가 바뀌면 그것이 의도된 변경이어야만 통과합니다. 실제로 기대값 하나를 일부러 느슨하게 만들어 테스트가 잡는 것을 확인했습니다.

공유 잠금이 편집자의 재공유와 삭제를 함께 막는지도 같은 테스트에서 확인합니다.
