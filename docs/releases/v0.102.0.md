## 릴리즈 요약

v0.102.0은 **셀에 친 `1,234` 가 글자로 저장되던 것**을 고칩니다. 지난 릴리즈에서 붙여넣기가 이런 값을 숫자로 읽게 했는데, 같은 값을 손으로 치면 여전히 글자였습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 친 것과 붙여넣은 것이 달랐다

`1,234` 를 셀에 치면 글자로 저장되어 합계에 들어가지 않았습니다. `₩1,000`, `12.5%`, `(500)` 도 마찬가지입니다. 그런데 엑셀에서 같은 값을 복사해 붙여넣으면 숫자로 들어옵니다. 같은 값인데 넣는 방법에 따라 결과가 달랐습니다.

이제 칠 때도 숫자로 받습니다. 보이던 모습은 표시 형식으로 남으므로 화면은 친 그대로이고, 합계에는 들어갑니다. 백분율은 0.125처럼 비율로 저장되고 화면에는 `12.5%` 로 보입니다.

**이미 표시 형식을 지정해 둔 칸에서는 그 형식을 그대로 둡니다.** 값을 넣는 것은 서식을 바꾸겠다는 뜻이 아닙니다.

읽지 말아야 할 것은 그대로 둡니다. 쉼표가 세 자리씩 끊지 않는 `1,2`, 하이픈이 들어간 전화번호, 날짜는 글자로 남습니다.

## 확인만 하고 지나간 것

`0012` 는 12가 됩니다. 엑셀과 구글 시트도 그렇습니다. 파일에서 **가져올 때** 는 `007` 같은 코드가 뜻을 잃지 않도록 글자로 남기는데, 이것은 의도한 차이입니다. 손으로 치는 것은 명시적인 행동이고 파일에서 들어오는 것은 남이 만든 값이기 때문입니다.

## 하마터면

`parsedValue` 가 이제 값과 표시 형식을 함께 돌려주는데, `Ctrl+Enter`(선택 범위 채우기)가 그 결과를 그대로 셀 값에 넣고 있었습니다. 셀마다 `{"value":1234,...}` 가 들어갈 뻔했습니다. 셀 값의 타입이 `unknown` 이라 타입 검사에 걸리지 않습니다. 같은 자리를 앞선 릴리즈에서 한 번 의심해 확인한 적이 있어(그때는 별개의 함수라 문제가 없었습니다) 이번에 바로 찾았습니다.

## 검증 결과

- 브라우저 E2E 두 가지를 남겼습니다. 친 `1,234`·`₩1,000`·`12.5%`·`(500)` 이 숫자와 표시 형식으로 들어가고 `=SUM` 이 2234를 내는지, 글자로 남아야 할 세 가지가 남는지 봅니다. 그리고 이미 형식이 있는 칸의 형식이 바뀌지 않는지 봅니다.
- 고치기 전 번들에서 두 가지가 모두 실패하는 것을 확인했습니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest 278개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
