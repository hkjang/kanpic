## 릴리즈 요약

v0.139.0은 **엑셀·구글 시트가 쓰는 함수 이름을 그대로 읽고 씁니다.** 오늘 엑셀에서 만든 파일을 가져오면 `IFS`, `XLOOKUP`, `TEXTJOIN` 이 모두 `#NAME?` 이었습니다.

## 셈은 있는데 이름을 몰랐습니다

구글 시트가 아는 함수 401개를 엔진에 하나씩 물어봤습니다. **232개는 알고 169개는 몰랐습니다.** 그중 가장 값이 큰 것부터 채웠습니다.

엑셀 2010부터 표준편차를 `STDEV.P` 라고 씁니다. kanpic은 `STDEVP` 로 이미 정확히 세고 있었는데 **이름을 몰라서** `#NAME?` 을 냈습니다. 열 개를 같은 셈에 이어 붙였습니다.

```
STDEV.S  STDEV.P  VAR.S  VAR.P  MODE.SNGL  RANK.EQ
PERCENTILE.INC  QUARTILE.INC  FORECAST.LINEAR  COVARIANCE.P
```

## 이름이 비슷해도 셈이 다른 것들

`PERCENTILE.EXC` 를 `PERCENTILE` 의 별명으로 두면 **조용히 틀린 답** 을 줍니다. 배타형은 양 끝을 자료 밖에 두므로 값이 다릅니다.

```
네 개짜리 자료의 1사분위
  PERCENTILE.INC({1,2,3,4}, 0.25)  ->  1.75
  PERCENTILE.EXC({1,2,3,4}, 0.25)  ->  1.25
```

`QUARTILE.EXC` 도 같은 이유로 따로 구현했고, 답할 수 없는 자리(`0`, `1`)에는 `#NUM!` 을 냅니다. `RANK.AVG` 는 동점자에게 그들이 차지한 등수의 **평균** 을 줍니다 — `RANK` 는 모두에게 가장 높은 등수를 줍니다. `MAXA`, `MINA` 는 숫자가 아닌 값을 0으로 셉니다.

## 파일 안의 이름은 화면과 다릅니다

이게 더 큰 문제였습니다. 엑셀은 2007 이후에 생긴 함수를 **파일 안에서 `_xlfn.` 을 붙여** 적습니다. 화면에는 `IFS` 로 보이지만 파일에는 `_xlfn.IFS` 라고 들어 있습니다. 동적 배열 함수 일부는 `_xlfn._xlws.` 를 씁니다.

```
가져오기:  파일의 _xlfn.XLOOKUP  ->  #NAME?   (이미 셀 줄 아는 함수인데)
내보내기:  파일에 XLOOKUP        ->  엑셀에서 #NAME?
```

양쪽 다 막혀 있었습니다. `IFS`, `SWITCH`, `TEXTJOIN`, `CONCAT`, `MAXIFS`, `MINIFS`, `XLOOKUP`, `XMATCH`, `UNIQUE`, `SEQUENCE`, `FILTER`, `SORT`, `LET`, `LAMBDA`, `VSTACK`… 51개가 해당됩니다.

**읽을 때** 는 이름을 모으는 한 자리에서 뗍니다. 가져오기·붙여넣기·MCP·에이전트가 모두 그 자리를 지나므로 한 번만 고치면 됩니다. 파싱 단계에서도 모읍니다 — `LET`, `LAMBDA` 는 셈이 아니라 파싱에서 갈라지기 때문입니다.

**쓸 때** 는 목록이 필요합니다. 잘못 넣으면 멀쩡하던 수식이 엑셀에서 깨지므로 확실한 것만 적었고, 목록에 우리가 모르는 이름이 섞이면 시험이 막습니다 — 실제로 열 개가 걸려 뺐습니다.

문자열 안은 건드리지 않습니다. `="IFS(" & A1` 처럼 사람이 쓴 글까지 함수로 보면 셈이 맞아도 틀린 것입니다. 따옴표 안의 두 겹 따옴표도 셉니다.

## 검증 결과

- 내보내고 다시 가져오는 왕복을 실제로 돌립니다. 수식 여섯 개가 제 이름으로 돌아오고, `SUM` 과 문자열은 그대로인지 봅니다.
- 별명 열 개가 예전 이름과 **같은 값** 을 내는지 짝지어 확인합니다.
- `EXC`·`RANK.AVG`·`MAXA`·`MINA` 는 포함형과 **값이 다른 자리** 를 골라 확인합니다.
- Go 시험 전체, 통합 시험 전체와 웹 시험 382개가 통과합니다.
