# v0.247.0

## MCP 클라이언트가 Keycloak 로그인으로 들어옵니다

`/mcp` 는 지금까지 **API 키만** 받았습니다. 에이전트를 붙이려면 사람이 개인화
화면에서 키를 만들고, scope 를 고르고, 원문을 클라이언트 설정에 붙여 넣어야
했습니다. 키는 사람보다 오래 살고, 만든 사람이 떠나도 남습니다. 회사에는 이미
누가 누구인지 아는 Keycloak 이 있는데, MCP 만 그 바깥에 있었습니다.

MCP 인가 명세(2025-06-18)의 **OAuth 2.1 리소스 서버** 를 kanpic 에 넣었습니다.
자격 없이 `/mcp` 를 부르면 401 과 함께
`WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource/mcp"`
가 돌아가고, 그 주소(RFC 9728)는 `resource` 와 `authorization_servers` — 곧 쓰고
있는 Keycloak Realm — 를 알려 줍니다. Claude, Cursor 같은 클라이언트는 이것만 보고
브라우저를 열어 Keycloak 에 로그인시키고, 받은 액세스 토큰을
`Authorization: Bearer` 로 들고 옵니다. kanpic 은 Issuer 의 JWKS 로 서명을 확인하고
그 토큰의 **사용자로** 도구를 실행합니다 — 워크북 공유 규칙도, 관리자 판정도
웹에서 로그인했을 때와 같습니다. API 키는 그대로 됩니다.

## 남의 토큰은 통하지 않습니다

같은 Realm 에서 나온 토큰이라고 다 받으면, 다른 사내 서비스용으로 발급된 토큰을
들고 와서 kanpic 을 부를 수 있습니다. 그래서 `aud` 가 kanpic 을 가리키는 토큰만
받습니다 — 관리자가 `auth.oidc.mcp_audiences` 에 적은 값, 비워 두었으면 Client ID
와 `<server.public_url>/mcp` 중 하나와 **정확히 같아야** 하고, 아니면 `azp` 가
kanpic 자신의 Client ID 여야 합니다. `iss`·`exp` 를 확인하고, `typ` 이 `ID` 인
토큰(로그인 증명이지 호출 권한이 아닌 ID 토큰)은 거절합니다. 거절 이유는 서버
로그에만 남고 클라이언트에는 `invalid_token` 만 나갑니다.

토큰의 `scope` 클레임에 `workbook.read` 같은 kanpic scope 가 실려 있으면 그 토큰을
**그 scope 만 가진 API 키처럼** 다룹니다. Keycloak 에서 Client Scope 를 그 이름으로
만들어 붙이면 됩니다. 아무 kanpic scope 도 없으면 사용자 권한 그대로입니다.

토큰은 `/mcp` 에서만 받습니다. REST 와 WebSocket 은 세션 쿠키와 API 키만 쓰는
것이 그대로입니다. Issuer discovery 와 키는 서버가 캐시하므로 호출마다 Keycloak 을
두드리지 않고, Issuer 로 나가는 요청에는 10초 제한이 걸려 있어 Keycloak 이 멎어도
kanpic 요청이 매달려 있지 않습니다.

## 켜고 끄기

새 설정 두 개가 **Keycloak OIDC 간편 연결** 카드에 들어갑니다.

| 설정 키 | 기본값 | 뜻 |
| :--- | :--- | :--- |
| `auth.oidc.mcp_enabled` | `true` | MCP 클라이언트가 Keycloak 토큰으로 `/mcp` 를 부르게 허용. OIDC 가 켜져 있을 때만 효력 |
| `auth.oidc.mcp_audiences` | 빈 목록 | 받아들일 `aud`. 비우면 Client ID 와 `/mcp` 주소 |

OIDC 를 쓰지 않는 설치는 아무것도 달라지지 않습니다. 토큰이 와도 모르는 키로
취급하고, 메타데이터 주소는 404 입니다. `GET /api/v1/auth/config` 와 MCP 도구
`platform.auth.config` 가 `mcp_oauth_enabled`·`mcp_resource`·`mcp_resource_metadata_url`
을 알려 줍니다. Keycloak 에서 Client 를 만들고 Audience 매퍼를 붙이는 순서는
관리자 가이드의 새 절 **4.2 MCP 클라이언트의 Keycloak OAuth 로그인** 에 있고 PDF 도
다시 구웠습니다.

## 올리실 때

새 마이그레이션은 없습니다. 새 설정 두 개는 서버가 뜰 때 기본값으로 들어갑니다.
필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다. Keycloak 로그인으로 MCP 를
쓰려면 Keycloak 에 MCP 클라이언트용 Client 와 Audience 매퍼를 더하고, 프록시
뒤라면 `server.public_url` 이 바깥 주소인지 확인합니다. 그것을 하지 않으면 토큰은
거절되고 API 키는 전과 같이 됩니다. v0.246.0 에서 올라오시는 분은 이미지만 바꿔
다시 띄우시면 됩니다.
