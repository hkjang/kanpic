## 릴리즈 요약

v0.129.0은 **인쇄 영역** 을 넣습니다. 고른 범위만 종이에 나가고, 엑셀 파일에서 가져온 인쇄 영역도 함께 따라옵니다.

## 알리기만 하고 버리던 자리

엑셀 파일을 가져오면 이런 안내가 떴습니다.

```
이름 정의 2개는 가져오지 않습니다: 인쇄 영역 1개, …
```

무엇이 빠졌는지 알려 주기는 했지만, 버리는 것은 마찬가지였습니다. 버린 까닭은 **kanpic에 인쇄 영역이라는 것이 아예 없었기 때문** 입니다.

## 시트의 성질로 담는다

인쇄 영역은 "이 범위만 종이에 낸다"는 시트의 성질입니다. 정해 두지 않으면 내용이 있는 곳 전체가 나갑니다 — 따로 말하기 전까지는 그쪽이 기대하는 바이기 때문입니다.

| 메뉴 | 하는 일 |
| --- | --- |
| 파일 › 인쇄 영역으로 설정 | 지금 고른 범위만 인쇄 |
| 파일 › 인쇄 영역 해제 | 전체를 인쇄. 영역이 없으면 눌리지 않습니다 |

시트 배치는 JSONB로 담기므로 **마이그레이션 없이** 자리를 낼 수 있었습니다. 이미 있는 배치 변경 통로에 두 가지 동작을 더했습니다.

## 엑셀에서 가져올 때

엑셀은 인쇄 영역을 `_xlnm.Print_Area`라는 이름으로 담습니다. 이제 그것을 읽어 시트에 옮겨 담습니다. 원래 문서가 **표 한 덩어리만 내도록** 짜여 있었다면 그 뜻이 그대로 지켜집니다.

## 적은 것을 다듬어 담는다

```
b2:d10  →  B2:D10        소문자로 적어도 한 가지 모양으로
말이 안 되는 값  →  거절   받아 두면 인쇄할 때가 되어서야 드러납니다
```

저장된 값이 하나뿐이라야 뒤에서 견주기 쉽습니다.

## 검증 결과

- 진짜 엑셀 파일을 만들어 가져온 뒤 확인했습니다.
- 인쇄 쪽 시험은 고치기 전 코드에서 **영역 밖 칸이 종이에 남아** 걸립니다.
- 읽을 수 없는 인쇄 영역이 담겨 있으면 전체를 인쇄합니다. 종이가 안 나오는 것보다 낫습니다.
- 시험 둘이 "인쇄 영역은 빠진 것으로 센다"를 고정하고 있었습니다. 일부러 바꾸는 것이므로 **인쇄 영역이 시트에 담겼는지 보는 쪽** 으로 고쳐 적었습니다.
- Go 시험 전체와 웹 시험 376개가 통과합니다.
