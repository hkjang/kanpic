## 릴리즈 요약

v0.192.0은 **CSV 로 들어오는 수** 도 담을 수 있을 때만 수로 읽습니다.

## 세 번째 길에는 한도가 없었습니다

같은 글자가 칸에 들어오는 길은 셋입니다 — 붙여넣기, 데이터 정리, 그리고 **CSV 가져오기**. 앞의 두 길에는 자릿수 한도를 두었는데 여기에는 없었습니다.

```
12345678901234567890  →  1.2345678901234567e+19
```

파일에 적힌 것과 **다른 값** 이 칸에 들어갑니다. 서버에서 벌어지고, 저장된 뒤에는 되돌릴 방법이 없습니다. 앞의 `0` 을 지키는 규칙은 이미 있었는데, 뒤가 뭉개지는 것은 보지 않고 있었습니다.

열다섯 자리를 넘는 평범한 수는 글자로 둡니다. 그런 것은 금액이 아니라 번호이고, 글자로 두면 적어도 파일에 적힌 그대로 남습니다. 지수로 적은 것(`1e30`)은 사람이 수로 적은 것이므로 건드리지 않습니다.

## 규칙을 네 번째로 베끼지 않았습니다

CSV는 쉼표나 통화 기호가 붙은 값을 숫자로 바꾸지 않습니다. 붙여넣기는 바꿉니다. 둘을 같게 만들려면 바꾸는 규칙을 Go에도 한 벌 더 적어야 하는데, **같은 규칙을 네 곳에 두는 것이 지금 고치고 있는 병입니다.**

대신 몇 칸이 그런지 세어 **가져오기 미리보기** 에 적고 고치는 자리를 가리킵니다.

```
숫자처럼 보이지만 글자로 담긴 칸이 2개 있습니다.
가져온 뒤 데이터 › 데이터 정리 › 텍스트로 저장된 숫자로 고칠 수 있습니다.
```

세는 것은 **어림** 입니다. 값을 바꾸지 않으므로 조금 넉넉해도 되지만, 바꾸는 규칙과 같지는 않습니다 — 바꾸는 일은 사람이 미리보기를 보고 정합니다.

한도 때문에 글자로 남긴 수는 "고칠 것" 으로 세지 않습니다. **일부러 지킨 것을 고치라고 말하면 안 됩니다.**
