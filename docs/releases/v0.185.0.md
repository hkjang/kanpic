## 릴리즈 요약

v0.185.0은 지난 판의 대사가 **번호를 수로 읽어 서로 다른 것을 같다고 하던 것** 을 고칩니다.

## 금액에 맞는 일을 번호에까지 했습니다

v0.184.0에서 `"1,000"` 과 `1000` 을 같은 항목으로 맞췄습니다. 금액에는 맞는 일인데, 번호에까지 그렇게 했습니다.

```
"007"  →  7        007번 전표와 7번 전표가 한 항목이 되었다

12345678901234567890  →  12345678901234567000
12345678901234567891  →  12345678901234567000     서로 다른 계좌번호 둘이 같은 키
```

**대사에서 틀리게 "맞았다" 고 하는 것은 "안 맞았다" 고 하는 것보다 나쁩니다.** 안 맞으면 사람이 들여다보지만, 맞았다고 하면 거기서 끝납니다. 계좌번호 둘이 다른데도 맞았다고 적힌 대사표는 아무도 다시 보지 않습니다.

## 번호는 번호로 둡니다

앞에 `0` 이 붙은 것과 **열다섯 자리를 넘는 것** 은 번호로 봅니다. 배정밀도가 정확히 담는 것은 열다섯 자리까지입니다.

쉼표나 통화 기호가 붙은 금액은 여기서 걸리지 않습니다 — 그것은 번호가 아니라 금액이고, `"1,000"` 과 `1000` 은 여전히 같아야 합니다.

## 칸을 고치는 쪽에도 같은 잘못이 있었습니다

`"₩12345678901234567890"` 을 **텍스트로 저장된 숫자** 로 바꾸면 뒤가 뭉개진 값이 칸에 들어갔습니다. 자료를 고치는 일이므로 되돌릴 수도 없습니다. 담지 못할 만큼 긴 것은 바꾸지 않습니다.

## 세는 규칙은 그대로입니다

수식 엔진과 맞춘 규칙은 건드리지 않았습니다. `=SUM` 은 `"007"` 을 7로 세고, 화면이 다르게 세면 두 수가 어긋납니다. 여기서 고친 것은 **무엇이 같은 항목인지** 와 **무엇을 칸에 적을지** 이지, 무엇을 셈에 넣을지가 아닙니다.

## 검증 결과

- `007` 과 `7` 이 갈리는지, 긴 계좌번호 둘이 갈리는지, 그러면서 `"1,000"` 과 `1000` 은 여전히 맞는지 따로 시험합니다.
- 웹 시험 439개와 Go 시험 전체가 통과합니다.
