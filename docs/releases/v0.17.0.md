## 릴리즈 요약

v0.17.0은 v0.16.0의 PostgreSQL 기반 워크북 자동화에 **시간대 인식 Cron 예약 실행**을 추가합니다. 사용자는 편집기에서 간단한 프리셋 또는 5필드 Cron 식과 IANA 시간대를 지정할 수 있고, 서버는 다음 실행 시각과 실행 이력을 PostgreSQL에 보존합니다.

이 릴리즈에서도 필수 런타임 환경 변수는 `POSTGRES_DSN` 하나입니다. Redis, 외부 스케줄러, 메시지 브로커와 외부 인터넷 연결은 필요하지 않으며, 스케줄러 확인 주기를 포함한 실행 정책은 관리자 화면에서 CRUD·버전 관리·검증·복원할 수 있습니다.

## 핵심 변경

- 자동화 트리거에 `schedule`을 추가했습니다. 기존 `manual`, `cell_change` 트리거와 동일한 정의 CRUD, revision, 미리보기, 작업 scope와 감사 계약을 사용합니다.
- 표준 5필드 Cron인 `분 시 일 월 요일`을 지원합니다. `*`, 쉼표 목록, 범위, step과 영문 월·요일 이름을 사용할 수 있습니다.
- `@hourly`, `@daily`, `@weekly`, `@monthly`, `@yearly` 별칭을 지원하며 저장 시 실제 5필드 식으로 정규화합니다.
- 일정마다 `UTC`, `Asia/Seoul` 같은 IANA 시간대를 지정합니다. 비어 있으면 `UTC`를 사용하고, 이미지에 포함된 시간대 데이터로 폐쇄망에서도 계산합니다.
- Cron의 일(day-of-month)과 요일(day-of-week)이 모두 제한된 경우 전통적인 Cron의 OR 규칙을 적용합니다. 일광 절약 시간 전환으로 존재하지 않는 로컬 시각은 안전하게 건너뜁니다.
- 자동화 목록에 서버가 계산한 `next_run_at`을 표시하고 실행 이력에는 예약 기준 시각인 `scheduled_for`를 제공합니다.

## 서버 권위 예약 실행

- Go 프로세스 안의 예약 실행 루프가 활성 자동화의 `next_run_at`을 PostgreSQL에서 조회합니다. 별도 cron daemon이나 외부 네트워크 서비스가 필요하지 않습니다.
- 서버가 시작되면 즉시 due 작업을 확인하고 이후 관리자 설정의 확인 주기로 반복합니다. 설정 변경은 프로세스를 재시작하지 않아도 다음 tick부터 반영됩니다.
- 예약 실행도 기존 `ApplyCells` 경로를 사용하므로 값·수식·서식 보존, 수식 재계산, 워크북 버전, 작업 로그와 WebSocket 협업 전파가 일반 편집 및 수동 자동화와 같습니다.
- 서버 종료 시 스케줄러 컨텍스트를 먼저 취소하고 HTTP 서버를 정상 종료합니다. 예약 상태는 메모리가 아니라 PostgreSQL에 있으므로 재시작 후 계속 처리됩니다.
- 장시간 중단 뒤에는 과거의 모든 발생 시각을 몰아서 실행하지 않습니다. 마지막 due 작업을 한 번 처리한 뒤 현재 시각 다음의 미래 발생 시각으로 이동하여 예기치 않은 대량 변경을 방지합니다.

## 멱등성, 동시성 및 장애 복구

- `automation_runs`의 `(automation_id, scheduled_for)` 유일 인덱스로 같은 예약 시각의 실행을 한 번만 생성합니다.
- 여러 kanpic 인스턴스가 같은 due 자동화를 동시에 조회해도 동일한 예약 실행 ID와 서버 권위 셀 작업 멱등성으로 중복 반영하지 않습니다.
- 실행 레코드를 만든 뒤 프로세스가 중단되면 다음 인스턴스가 저장된 작업·셀·기대값 스냅샷을 사용해 `running` 실행을 재개할 수 있습니다.
- 셀 적용 후 실행 상태 저장 전에 응답이 끊겨도 동일한 셀 작업 멱등 키로 결과를 복구합니다.
- 예약 작업 대상이 이미 원하는 값이나 수식이면 새 워크북 버전을 만들지 않고 `skipped` 상태로 기록한 뒤 다음 시각으로 진행합니다.
- 실행 구성 오류, 실행 한도 초과 또는 셀 충돌은 `failed` 실행과 오류 메시지로 남기고 다음 미래 시각으로 진행합니다. 실패 상태 갱신과 `automation.run.failed` 감사 기록은 하나의 PostgreSQL 트랜잭션으로 저장합니다.

## 편집기와 관리자 화면

- 자동화 폼의 실행 조건에 **일정(Cron)**을 추가했습니다.
- 평일 오전 9시, 매시간, 15분마다, 매일 자정 프리셋을 제공하며 직접 Cron을 입력할 수도 있습니다.
- 시간대 입력에는 `Asia/Seoul`, `UTC`, `Asia/Tokyo`, `America/New_York`, `Europe/London` 예시를 제공하고 서버가 실제 IANA 시간대 유효성을 검증합니다.
- 예약 자동화 카드에는 Cron, 시간대와 로컬 표시 형식의 다음 실행 시각이 나타납니다.
- 실행 이력은 `running`, `succeeded`, `skipped`, `failed`, `undoing`, `undone` 상태를 구분해 표시합니다.
- 관리자 **워크북 자동화 실행 정책**에 `automation.scheduler_poll_seconds`를 추가했습니다. 기본값은 15초이고 허용 범위는 5~300초입니다.
- 자동화 전체 활성화, 셀 한도, 시간당 실행 수와 스케줄러 확인 주기는 기존 설정과 동일하게 추가·조회·수정·삭제, revision 이력, 검증, 연결 시험과 이전 버전 복원을 지원합니다.
- 관리자 설정은 `/admin`, 개인화와 개인 API 키는 `/preferences`에 계속 분리되어 있습니다.

## REST API와 MCP

새 endpoint를 만들지 않고 기존 자동화 계약을 확장했습니다. 자동화 생성·수정 요청의 `trigger`에 다음 형태를 사용할 수 있습니다.

```json
{
  "type": "schedule",
  "cron": "0 9 * * MON-FRI",
  "timezone": "Asia/Seoul"
}
```

- REST 응답의 자동화 정의에는 `next_run_at`, 예약 실행 이력에는 `scheduled_for`가 포함됩니다.
- 기존 `spreadsheet.automation.create`와 `spreadsheet.automation.update` MCP 입력 스키마에 `schedule`, `cron`, `timezone`을 추가했습니다.
- `spreadsheet.automation.list|get|test|run|run.list|run.undo|delete`도 같은 확장된 정의와 실행 이력을 반환합니다.
- 에이전트는 기존처럼 `mcp.use`와 `automation.read`, `automation.write`, `automation.run` 및 작업에 필요한 `range.read`, `range.write`, `formula.write`를 최소 scope로 조합합니다.
- 개인 API 키는 개인화 화면에서 생성·조회·수정·폐기·회전할 수 있고, 원문은 생성 또는 회전 직후 한 번만 표시됩니다.

## PostgreSQL 마이그레이션

- `016_scheduled_automations.sql`이 `automations.next_run_at`과 `automation_runs.scheduled_for`를 추가합니다.
- 자동화 실행 trigger 제약에 `schedule`, 상태 제약에 `skipped`를 추가합니다.
- 활성 due 자동화를 효율적으로 찾는 부분 인덱스와 `(automation_id, scheduled_for)` 예약 중복 방지 유일 인덱스를 추가합니다.
- 애플리케이션 시작 시 기존 자동 마이그레이션 체계가 `016`을 적용합니다. 별도의 수동 DDL이나 환경 변수가 필요하지 않습니다.

## 로그와 감사

- 스케줄러 시작·종료, tick 오류와 완료 실행 수를 구조화 JSON 로그로 기록합니다.
- 예약 성공, 변경 없음과 실패 로그에는 자동화 ID, 실행 ID, 트리거, 예약 시각, 작업 ID 또는 오류를 포함합니다.
- `automation.run`, `automation.run.skip`, `automation.run.failed` 감사 이벤트를 실행 이력과 연결할 수 있습니다.
- 운영자는 컨테이너 표준 출력과 `/admin`의 서버 로그 화면에서 같은 실행을 검색할 수 있습니다.

## 검증 결과

- `go test ./...`와 `go vet ./...`를 통과했습니다.
- Cron 파서 단위 테스트에서 step·범위·월/요일 이름·별칭·윤년·day/weekday OR 규칙·IANA 시간대와 잘못된 식을 검증했습니다.
- 실제 PostgreSQL 17의 호스트 5432 포트를 사용하는 전체 통합 테스트를 통과했습니다. due 실행, 다음 시각 갱신, 중복 tick 억제, 변경 없음 처리, 실행 이력·감사와 실제 백그라운드 스케줄러 콜백을 확인했습니다.
- Go HTTP 계약 테스트에서 예약 트리거 REST 구조와 MCP의 `cron`·`timezone` 입력 스키마, 예약 실행의 WebSocket 게시 연결을 검증했습니다.
- React/Vitest 19개 테스트 파일, 65개 테스트를 통과했습니다. Cron 프리셋·시간대 저장과 다음 실행 시각 UI를 포함합니다.
- TypeScript 타입 검사와 Vite 프로덕션 빌드를 통과했습니다.
- Playwright E2E 31건을 통과했습니다. 실제 브라우저와 PostgreSQL에서 예약 정의의 Cron·시간대·다음 실행 시각·미리보기 계약과 기존 자동화 및 전체 편집 기능 회귀를 확인했습니다.
- 릴리즈 이미지는 PostgreSQL 전용 구성으로 자동 마이그레이션, `/healthz`, `/api/v1/version`, 두 이미지 태그, 오프라인 `docker load`와 SHA-256 무결성을 검증합니다.

## 업그레이드 참고

- v0.16.0 이하에서 시작하면 `016_scheduled_automations.sql`이 자동 적용됩니다. 운영 업그레이드 전 PostgreSQL 백업을 권장합니다.
- 기존 수동·셀 변경 자동화 정의와 실행 이력은 그대로 호환됩니다. 새 컬럼은 기존 행에서 `NULL`이며 예약 정의를 만들거나 수정할 때만 채워집니다.
- `automation.scheduler_poll_seconds` 기본값은 15초입니다. 관리자는 `/admin`에서 정책 검증과 저장소 준비 상태 테스트를 통과한 뒤 환경 규모에 맞게 5~300초 사이로 조정할 수 있습니다.
- `automation.enabled=false`인 환경에서는 예약 실행도 수행되지 않지만 정의 CRUD와 쓰기 없는 미리보기는 사용할 수 있습니다.
- 필수 런타임 설정은 계속 `POSTGRES_DSN` 하나이며 PostgreSQL 포트 예시는 5432입니다.

## 현재 지원 범위와 다음 단계

- 현재 자동화 트리거는 수동, 셀 변경과 Cron 일정이며 작업은 값 설정, 수식 설정과 내용 지우기입니다.
- 웹훅, 알림, 파일 생성, AI 분석, 외부 MCP 호출, 승인 단계와 다단계 워크플로우는 아직 실행하지 않습니다.
- 자동화 간 연쇄·재귀 실행은 최대 단계, 실행 시간, egress 허용 목록, Secret Manager와 Dead Letter Queue 정책을 갖춘 후 확장할 예정입니다.
