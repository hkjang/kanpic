## 릴리즈 요약

v0.127.0은 **`TIME`이 시각에 더할 수 없는 값을 내놓던 것** 을 고칩니다. 이제 하루를 1로 본 분수를 돌려주므로 날짜에 더할 수 있습니다.

## 한 라이브러리 안에서 답이 갈렸다

시각을 다루는 자리를 훑다가 찾았습니다.

```
=TIME(1,30,0)             "01:30:00"   글자
=TIMEVALUE("01:30:00")    0.0625       분수
```

표 프로그램에서 시각은 **하루를 1로 본 분수** 입니다. 한 시간 반은 `0.0625`입니다. 그래야 날짜에 더할 수 있습니다. `TIME`만 글자를 돌려주고 있었습니다.

```
=A1+TIME(1,0,0)      #VALUE!
=TIME(12,30,0)*24    #VALUE!
```

시각을 만드는 함수를 시각에 더할 수 없으면 만들 까닭이 없습니다.

## 밑바탕은 이미 되어 있었다

셈하는 쪽은 모두 제대로 움직이고 있었습니다.

```
=A1+1/24                       한 시간 뒤
=A1+90/1440                    90분 뒤
=A1+TIMEVALUE("01:00:00")      한 시간 뒤
```

`TIME` 하나만 어긋나 있었습니다. 이제 이렇게 씁니다.

```
=A1+TIME(1,0,0)                             한 시간 뒤
=TEXT(A1+TIME(1,30,0),"yyyy-mm-dd hh:mm")   한 시간 반 뒤를 보기 좋게
=TIME(12,30,0)*24                           12.5 — 몇 시간인지
```

## 잃는 것도 적어 둡니다

칸에 `=TIME(1,30,0)`만 적으면 이제 **`0.0625`가 보입니다.** 예전에는 `"01:30:00"`이라고 보였습니다.

엑셀은 시각 서식을 저절로 입혀 `1:30`으로 보여주지만, 여기서는 수식 결과에 서식이 따라붙지 않습니다. **시각 서식** 을 주거나 `=TEXT(값,"hh:mm")`을 쓰면 됩니다. 사용자 가이드에 적었습니다.

보기 좋은 쪽과 쓸 수 있는 쪽 가운데 **쓸 수 있는 쪽** 을 골랐습니다. 보기는 서식으로 되돌릴 수 있지만, 더할 수 없는 것은 되돌릴 방법이 없습니다.

## 검증 결과

- 시험 하나가 `"13:05:00"`을 고정하고 있었습니다. 버그가 아니라 **일부러 바꾸는 것** 이므로 까닭을 적고 함께 고쳤습니다.
- 고치기 전 코드에서 새 시험이 걸립니다.
- 실제 서버에서 아홉 가지를 확인했습니다. 하루를 넘기면 돌아오고(`=TIME(25,0,0)`은 1시), 분과 초도 넘어갑니다(`=TIME(0,90,0)`은 한 시간 반).
- Go 시험 전체와 웹 시험 376개가 통과합니다.
