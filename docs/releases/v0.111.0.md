## 릴리즈 요약

v0.111.0은 **워크북이 많아질수록 홈 화면이 느려지던 것**을 고칩니다. 워크북 5,119개에서 목록 응답이 **1.78초에서 0.048초로** 줄었습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 워크북 하나에 질의 하나

워크북 목록은 워크북을 한 번에 읽은 다음, **각 워크북의 시트를 하나씩 따로** 물었습니다. 워크북이 5,000개면 데이터베이스에 5,000번을 더 다녀옵니다.

같은 함수 안에서 공유 정보와 즐겨찾기는 이미 한 번에 모아 읽고 있었습니다. 시트만 반복문 안에 남아 있었습니다. 이제 시트도 한 질의로 모아 읽습니다.

응답 내용은 **한 바이트도 달라지지 않습니다**(3,262,964바이트로 동일). 시트는 워크북별로 갈라져 position 순서를 지키고, 레이아웃도 그대로입니다.

## 재어 본 값

| 워크북 수 | 고치기 전 | 고친 뒤 |
| :--- | :--- | :--- |
| 693 | 0.054초 | 0.054초 |
| 5,119 | 1.78초 | **0.048초** |

브라우저에서 첫 카드가 보이기까지도 3.9초에서 2.6초로 줄었습니다.

## 남은 문제

**목록은 여전히 보이는 워크북을 전부 보냅니다.** 5,119개면 3.26MB이고, 브라우저는 카드 5,119개를 모두 그립니다. 첫 카드까지 2.6초가 걸리는 것은 이제 서버가 아니라 이쪽 때문입니다.

제대로 고치려면 서버 쪽 페이지 나누기와 검색이 필요합니다. 지금 화면의 필터(즐겨찾기·내 소유·공유됨)가 브라우저에서 걸러 내는 방식이라 함께 옮겨야 하고, 즐겨찾기는 사용자별 표라 조인이 필요합니다. 이번에는 손대지 않았습니다. 참고로 관리자 콘솔의 워크북 목록은 이미 200개로 끊고 있습니다.

## 검증 결과

- 통합 테스트를 하나 남겼습니다. 시계가 아니라 **연결 획득 횟수**를 셉니다 — 시간을 재면 흔들리고, 정작 중요한 성질은 "질의 수가 워크북 수를 따라 늘지 않는다" 이기 때문입니다. 워크북 24개에서 고치기 전에는 28번, 고친 뒤에는 10번 미만입니다.
- 같은 테스트가 시트가 워크북별로 바르게 갈라지는지, 시트가 여러 개인 워크북의 순서가 맞는지도 봅니다.
- 같은 반복문 안의 다른 질의(공유·즐겨찾기)는 이미 모아 읽고 있었고, 나머지 `listSheets` 호출은 모두 워크북 하나짜리라 그대로 두었습니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
