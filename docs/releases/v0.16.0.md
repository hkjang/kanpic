## 릴리즈 요약

v0.16.0은 반복 셀 작업을 안전하게 정의·검증·실행·취소할 수 있는 **PostgreSQL 기반 워크북 자동화**의 첫 번째 운영 가능 버전입니다. 수동 실행과 셀 변경 트리거, 값 설정·수식 설정·내용 지우기를 지원하며 편집기, REST API와 MCP가 하나의 서버 권위 서비스와 권한 계약을 사용합니다.

이 릴리즈에서도 필수 런타임 환경 변수는 `POSTGRES_DSN` 하나이고 Redis나 외부 인터넷 연결은 필요하지 않습니다. 자동화는 기본 비활성화 상태로 추가되며 관리자가 실행 정책을 검증하고 저장소 연결 시험을 마친 뒤 활성화합니다.

## 핵심 변경

- 워크북마다 이름, 활성 상태, 트리거, 작업과 revision을 가진 자동화 정의를 생성·조회·수정·삭제할 수 있습니다.
- 트리거는 사용자가 명시적으로 시작하는 `manual`과 지정한 시트의 A1 범위가 변경될 때 실행되는 `cell_change`를 지원합니다.
- 작업은 문자열·숫자·불리언 값을 적용하는 `set_value`, `=`로 시작하는 수식을 적용하는 `set_formula`, 값과 수식을 비우는 `clear`를 지원합니다.
- 수식을 범위에 적용하면 왼쪽 위 셀을 기준으로 상대 참조를 각 대상 셀 위치에 맞게 이동합니다. 절대 참조는 기존 수식 엔진 규칙을 유지합니다.
- 자동화 정의의 저장·수정·삭제는 이름 중복, 워크북 소속 시트, A1 범위, 값 유형, 수식 형태, 셀 변경 한도를 서버에서 검증합니다.

## 미리보기와 안전 실행

- **검증**은 최신 PostgreSQL 워크북 상태로 대상 셀의 현재 값·수식·서식과 실행 후 상태를 계산하지만 쓰기 작업이나 워크북 버전을 만들지 않습니다.
- 실행은 자동화 revision, 정확한 워크북 기준 버전과 대상 셀 스냅샷을 다시 검사합니다. 미리보기 이후 다른 사용자가 워크북이나 대상 셀을 변경했다면 `409 Conflict`로 중단합니다.
- 변경 셀 전체를 기존 `ApplyCells` 경로의 단일 원자적 작업으로 저장하여 부분 적용을 허용하지 않습니다. 수식 재계산, 워크북 버전 증가, 작업 로그와 WebSocket 협업 전파도 일반 셀 편집과 같은 경로를 사용합니다.
- 배열 수식의 spill 결과 셀은 자동화 대상으로 사용할 수 없으며 유효 변경이 없는 실행도 거부합니다.
- 자동화 작업으로 바뀐 셀의 기존 서식은 유지됩니다. `clear`는 값과 수식만 지우고 서식은 보존합니다.
- 성공한 실행은 실행 이력의 **Undo**로 되돌릴 수 있습니다. 원래 자동화 실행 뒤 대상 셀이 다시 변경되었다면 다른 사용자의 변경을 덮어쓰지 않도록 Undo를 거부합니다.

## 멱등성, 동시성 및 실행 제한

- 생성과 수동 실행은 필수 `idempotency_key`로 중복 요청을 한 번만 반영합니다. 응답 유실 후 같은 키를 재전송하면 기존 정의 또는 실행 결과를 반환합니다.
- 셀 변경 트리거는 자동화와 원본 셀 `operation_id`의 조합을 유일하게 저장하므로 REST, MCP 또는 WebSocket 작업 재전송 시 같은 자동화가 중복 실행되지 않습니다.
- 실행이 `running` 상태에서 프로세스 응답이 끊긴 경우 동일 요청은 저장된 셀·기대값 스냅샷으로 실행을 재개합니다.
- 정의 수정과 삭제는 `expected_revision` 기반 낙관적 잠금을 사용하며 오래된 화면이나 에이전트의 변경을 거부합니다.
- 관리자 정책으로 한 실행의 최대 변경 셀 수와 워크북별 최근 1시간 실행 수를 제한합니다. 기본값은 각각 1,000셀과 100회이고 유효 설정 범위는 1~10,000입니다.
- 자동화 결과가 다시 자동화 트리거를 연쇄 호출하지 않도록 이번 버전의 셀 변경 트리거는 사용자가 제출한 서버 권위 셀 작업만 기점으로 처리합니다.

## PostgreSQL 저장과 감사

- `015_automations.sql`이 `automations`와 `automation_runs` 테이블 및 조회·중복 방지 인덱스를 추가합니다.
- 자동화 정의에는 트리거·작업 JSON, revision, 생성자·수정자, 멱등 키, 생성·수정 시각과 soft delete 상태를 저장합니다.
- 실행 이력에는 트리거 유형과 원본 작업 ID, 상태, 기준 버전, 실행 당시 작업 정의, 변경 셀과 기대 셀 스냅샷, 적용 작업·Undo 작업 ID와 결과, 오류 및 실행 시각을 저장합니다.
- `automation.create`, `automation.update`, `automation.delete`, `automation.run`, `automation.run.undo`가 기존 `audit_logs`에 사용자와 리소스, 작업·워크북 버전 메타데이터를 기록합니다.
- 성공과 실패 실행은 구조화 서버 로그에도 자동화 ID, 실행 ID, 트리거, 작업 ID 또는 오류를 남겨 관리자 로그 화면과 컨테이너 표준 출력에서 추적할 수 있습니다.

## REST API

다음 endpoint가 추가되었습니다.

| Method | Endpoint | 최소 기본 scope | 설명 |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/workbooks/{workbookId}/automations` | `automation.read` | 자동화 목록 조회 |
| `POST` | `/api/v1/workbooks/{workbookId}/automations` | `automation.write` | 자동화 멱등 생성 |
| `GET` | `/api/v1/automations/{automationId}` | `automation.read` | 자동화 정의 조회 |
| `PATCH` | `/api/v1/automations/{automationId}` | `automation.write` | revision 기반 수정 |
| `DELETE` | `/api/v1/automations/{automationId}?expected_revision=N` | `automation.write` | revision 기반 soft delete |
| `POST` | `/api/v1/automations/{automationId}:test` | `automation.read` + `range.read` | 쓰기 없는 최신 셀 미리보기 |
| `POST` | `/api/v1/automations/{automationId}:run` | `automation.run` + 작업 scope | 수동 원자적 실행 |
| `GET` | `/api/v1/automations/{automationId}/runs` | `automation.read` | 실행·실패·Undo 이력 조회 |
| `POST` | `/api/v1/automation-runs/{runId}:undo` | `automation.run` + `range.write` | 성공 실행 안전 취소 |

값 설정과 내용 지우기는 `range.write`, 수식 설정은 `formula.write`를 작업 scope로 추가 검사합니다. 모든 쓰기 요청은 API Key의 scope와 사용자 인증을 서버에서 확인하며 UI 호출도 같은 서비스 경계를 사용합니다.

## MCP 도구와 개인 API 키

- `spreadsheet.automation.list`
- `spreadsheet.automation.get`
- `spreadsheet.automation.create`
- `spreadsheet.automation.update`
- `spreadsheet.automation.delete`
- `spreadsheet.automation.test`
- `spreadsheet.automation.run`
- `spreadsheet.automation.run.list`
- `spreadsheet.automation.run.undo`

모든 MCP 호출에는 기존처럼 `mcp.use`가 필요합니다. 정의 조회·검증·실행 이력에는 `automation.read`, 정의 변경에는 `automation.write`, 실행과 Undo에는 `automation.run`을 사용하고 실제 데이터 접근에 따라 `range.read`, `range.write`, `formula.write`를 최소 권한으로 조합합니다. 개인화 화면에서 이 scope를 포함한 키를 생성·수정·폐기·회전할 수 있고 원문은 생성 또는 회전 직후 한 번만 표시됩니다.

## 편집기와 관리자 화면

- 편집기 오른쪽 아래에 별도 **자동화** 패널을 추가했습니다. 정의 목록과 revision, 사용·중지 상태, 수동·셀 변경 트리거, 값·수식·지우기 작업을 한 화면에서 관리합니다.
- 새 정의 또는 수정 내용을 저장하면 자동으로 검증 미리보기를 열며 현재 값과 실행 후 값을 셀별로 비교합니다. 대량 미리보기는 앞 20개를 표시하고 전체 변경 셀 수를 별도로 보여 줍니다.
- 명시적인 **검토한 자동화 실행** 후 성공·실패·Undo 상태와 기준 버전을 실행 이력에서 확인할 수 있습니다.
- 관리자 화면에 **워크북 자동화 실행 정책** 전용 카드를 추가했습니다. `automation.enabled`, `automation.max_cells_per_run`, `automation.max_runs_per_hour`를 다른 시스템 설정과 분리해 간단히 관리합니다.
- 정책 설정도 기존 설정 관리 체계의 CRUD, revision 이력, 이전 버전 복원, 전체 검증과 연결 테스트를 그대로 사용합니다. 자동화 활성화 시 연결 테스트가 실제 PostgreSQL 테이블 준비 상태를 확인합니다.
- 관리자 화면과 개인화 화면의 역할 분리는 유지합니다. 실행 정책과 전역 상태는 `/admin`, 에이전트용 개인 API 키와 scope는 `/preferences`에서 관리합니다.

## 폐쇄망과 운영

- 새 외부 서비스, Redis, 메시지 브로커 또는 런타임 환경 변수는 필요하지 않습니다. 자동화 정의, 실행 잠금, 이력, 감사와 rate limit 기준은 PostgreSQL만 사용합니다.
- Docker 이미지는 React 정적 자산, Go 서버와 `015_automations.sql`을 포함하므로 외부 패키지 저장소 연결 없이 기동 시 자동 마이그레이션됩니다.
- 릴리즈 자산 `kanpic-v0.16.0.tar.gz`에는 `kanpic:v0.16.0`과 `ghcr.io/hkjang/kanpic:v0.16.0` 태그의 동일 이미지를 포함하며 `.sha256` 파일로 오프라인 반입 무결성을 검증할 수 있습니다.
- 서버 로그는 컨테이너 표준 출력의 JSON 로그와 관리자 로그 화면에서 조회할 수 있고 자동화 성공·실패를 실행 ID와 작업 ID로 연결할 수 있습니다.

## 검증 결과

- `go test ./...`와 `go vet ./...`를 통과했습니다.
- 실제 PostgreSQL 17의 호스트 5432 포트를 사용하는 전체 통합 테스트를 통과했습니다. 생성 멱등성, 비변경 미리보기, 상대 수식, 실행·재시도, 이력, Undo·재시도, revision 충돌, 셀 변경 트리거 중복 제거, soft delete와 감사 로그를 검증했습니다.
- Go HTTP 계약 테스트에서 REST와 MCP의 9개 자동화 도구, 동적 작업 scope, WebSocket 셀 변경 트리거와 중복 억제를 검증했습니다.
- React/Vitest 19개 테스트 파일, 64개 테스트를 통과했습니다. 자동화 정의 생성과 검증, 명시적 실행, 이력과 Undo UI를 포함합니다.
- TypeScript ESLint와 Vite 프로덕션 빌드를 통과했습니다.
- Playwright E2E 31건을 통과했습니다. 관리자 자동화 설정 검증·저장소 시험, 편집기 미리보기·실행·Undo, REST 셀 변경 트리거·이력과 기존 워크북 기능 회귀를 실제 브라우저와 PostgreSQL로 확인했습니다.
- 릴리즈 Docker 이미지는 PostgreSQL 전용 구성으로 기동해 자동 마이그레이션, `/healthz`, `/api/v1/version`, 이미지 태그, 오프라인 `docker load`와 SHA-256 무결성을 검증합니다.

## 업그레이드 참고

- v0.15.0 이하에서 서버를 시작하면 `015_automations.sql`이 자동 적용됩니다. 별도 수동 DDL은 필요하지 않지만 운영 업그레이드 전 PostgreSQL 백업을 권장합니다.
- 자동화는 업그레이드 직후 `automation.enabled=false`입니다. 관리자 화면에서 정책 값을 검토하고 **정책 검증**과 **저장소 준비 상태 테스트**를 통과한 뒤 활성화하십시오.
- 기존 개인 API 키에는 새 자동화 scope가 자동 추가되지 않습니다. 에이전트가 자동화를 사용할 경우 `/preferences`에서 최소 scope를 추가하거나 키를 회전하십시오.
- 기존 워크북, 셀 작업, 수식, 버전, AI 작업, 댓글과 관리자 설정 revision은 그대로 호환됩니다.

## 현재 지원 범위와 다음 단계

- 이번 버전은 수동·셀 변경 트리거와 값 설정·수식 설정·내용 지우기에 집중한 첫 번째 안전 실행 수직 기능입니다.
- 스케줄, 웹훅, 알림, 파일 생성, AI 분석, MCP 외부 도구 호출, 승인 단계와 다단계 워크플로우는 아직 실행하지 않습니다.
- 자동화 간 연쇄 실행과 재귀 실행은 의도적으로 비활성화되어 있습니다. 후속 버전에서 최대 단계, 실행 시간, egress 허용 목록, Secret Manager와 Dead Letter Queue 정책을 갖춘 뒤 확장합니다.
