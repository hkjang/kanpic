## 릴리즈 요약

v0.100.0은 **kanpic에서 복사해 다른 곳에 붙여넣을 때** 서식이 따라가게 합니다. 지난 릴리즈에서 들어오는 쪽을 고쳤으니 이제 나가는 쪽입니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 복사하면 글자만 나갔다

kanpic은 복사할 때 평문과 자체 형식만 클립보드에 올렸습니다. 자체 형식은 kanpic끼리만 알아보므로, 엑셀·구글 시트·워드에 붙여넣으면 **탭으로 나뉜 맨 글자**만 남았습니다. 굵게도 배경색도 정렬도 없습니다.

이제 `text/html` 표도 함께 올립니다. 굵게, 기울임, 밑줄, 취소선, 글자색, 배경색, 가로·세로 정렬, 줄바꿈, 글꼴과 크기가 따라갑니다.

숫자는 보이던 모습과 실제 값을 함께 보냅니다. 셀에 `₩1,234.50` 이 보였다면 표에는 그 글자와 함께 `x:num="1234.5"` 가 붙습니다. 받는 쪽이 통화 표기를 알아보지 못해도 숫자로 들어갑니다. 엑셀에는 표시 형식(`mso-number-format`)까지 전달되어 서식 그대로 붙습니다.

조건에 따라 다르게 보이는 표시 형식(`#,##0;[Red]-#,##0`)은 세미콜론이 CSS 선언을 끊어 버려 그대로 보낼 수 없습니다. 잘못된 형식을 보내느니 보내지 않고, 숫자만 정확히 넘깁니다.

메뉴로 복사할 때도 같습니다. `ClipboardItem` 을 쓸 수 없는 브라우저에서는 지금까지처럼 글자만 올립니다.

## 검증 결과

- 브라우저 E2E를 하나 남겼습니다. 실제로 복사해 클립보드에 올라간 것을 읽어 표가 있는지, 굵게·배경색·기울임·글자색과 `x:num` 이 들어 있는지 확인합니다. 고치기 전 번들에서 `text/html` 이 빈 문자열인 것을 확인했습니다.
- 단위 테스트로 서식 변환, HTML 이스케이프, 옮길 수 없는 표시 형식을 빼는지, 그리고 **내보낸 표를 스스로 다시 읽어** 값과 서식이 그대로 돌아오는지 확인합니다.
- 시나리오를 쓰다 두 가지가 걸렸습니다. 행 머리글 위를 눌러 행 전체가 선택되면 복사 한도(10,000셀)에 걸려 아무것도 복사되지 않고, 셀 값이 도착하기 전에 복사하면 빈 표가 나옵니다. 둘 다 시나리오에서 처리했습니다.
- 지난 릴리즈에서 원인을 확정하지 못했던 `everyday.spec.ts` 의 흔들림이 이번 전체 실행에서 메시지와 함께 재현됐습니다. 값이 도착하기 전에 `Ctrl+↓` 를 눌러 시트 맨 아래로 가 버리고, 있지도 않은 `A3 셀 입력` 을 30초 동안 기다리다 죽습니다. 짐작했던 경합이 맞았고, 같은 파일의 나머지 한 시나리오에도 있었습니다. 데이터에 기대지 않는 방법(이름 상자로 이동)으로 바꿨습니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest 278개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
