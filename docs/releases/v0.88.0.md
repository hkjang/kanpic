## 릴리즈 요약

v0.88.0은 지난 세 릴리즈가 따라온 패턴 — **서버가 담는 것보다 화면이 작다** — 을 끝까지 훑은 결과입니다. 남은 어긋남은 없었고, 대신 한도에 걸렸을 때의 안내를 고쳤습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 대조한 결과

서버가 강제하는 한도 60여 개와 화면이 강제하는 한도를 나란히 놓고 봤습니다. 화면이 따로 한도를 두는 곳은 네 군데뿐이고, 지난 두 릴리즈에서 고친 뒤로는 모두 서버와 맞거나 그보다 넓습니다.

| 대상 | 서버 | 화면 |
| --- | --- | --- |
| 행 | 1,048,576 | 200,000 (스크롤 높이 한계) |
| 열 | 16,384 | 16,384 |
| 붙여넣기 | 10,000셀 | 10,000셀 |
| 정렬 | 60,000셀 | 60,000셀 |

2,000열 × 100행짜리 시트를 만들어 실제로 확인했습니다. 2.7초에 열리고, 마지막 열 `BXX` 로 이동해 값이 보이며, 정렬 대상 범위도 `A1:BXX100` 로 정확히 잡습니다.

## 한도에 걸렸을 때

그 시트에서 정렬을 눌러 보니 문제가 셋 있었습니다.

**같은 경고가 두 번 떴습니다.** 정렬을 수행하는 쪽과 확인창이 각각 알리고 있었습니다. 수행하는 쪽만 알리도록 했습니다.

**누른 뒤에야 알려 줬습니다.** 확인창은 `A1:BXX100 범위를 정렬합니다` 라고만 하고, **정렬** 을 눌러야 20만 셀이라 안 된다고 말했습니다. 이제 확인창이 그 자리에서 셀 수와 한도를 함께 보여 주고 버튼을 잠급니다.

**잠긴 버튼이 잠겨 보이지 않았습니다.** 대화상자의 비활성 버튼에 스타일이 없어 평소와 같은 초록색이었습니다.

## 검증 결과

- 2,000열 시트에서 세 가지를 모두 눈으로 확인했습니다.
- 확인창 테스트를 더했습니다. 한도 안의 범위는 정렬이 실행되고, 넘는 범위는 셀 수와 한도를 말하며 버튼이 잠기는지 봅니다.
- `go vet ./...`, `go test ./...`, `go test -tags integration ./internal/...`, React/Vitest 261개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 145건을 통과했습니다.
