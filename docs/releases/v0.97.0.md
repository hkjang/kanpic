## 릴리즈 요약

v0.97.0은 **엑셀 파일을 오갈 때 조용히 잃는 것들**을 고칩니다. 서식·수식·검증·조건부 서식·차트를 넣은 워크북을 내보냈다가 다시 가져와 하나씩 대조했습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 시트의 꼬리가 숨겨졌다

값이 쓰인 마지막 행보다 아래에 병합 셀이 있는 시트를 내보냈다가 다시 가져오면, **그 사이의 행이 전부 숨김이 되었습니다.** 아홉 번째 행까지 값이 있고 11행에 병합이 있으면 10·11행이 숨겨져 병합 셀이 화면에서 사라집니다.

엑셀 파일은 값이 있는 행만 기록합니다. 그런데 파일을 읽는 라이브러리는 기록되지 않은 행을 물으면 오류가 아니라 **"숨겨져 있다"** 고 답합니다. 기록되지 않은 행은 숨겨질 수가 없으므로, 이제 파일이 실제로 적어 둔 행까지만 그 답을 믿습니다. 내용 없이 숨겨진 채로 파일 끝에 있는 행은 그대로 살아남습니다.

## 메모가 사라졌다

셀에 단 메모는 양쪽 모두에서 없어졌습니다. 내보낸 파일에는 메모가 담기지 않았고, 엑셀에서 만든 셀 메모도 가져올 때 버려졌습니다. 메모는 그 셀이 왜 그 값인지를 적어 두는 자리인데, 사라져도 표는 똑같아 보입니다.

이제 양방향으로 옮겨집니다. 값이 없는 셀에 달린 메모도 그대로 갑니다. 엑셀이 메모에 허용하는 길이를 넘는 경우에는 내보내기 전체를 실패시키지 않고 잘라서 담습니다.

## 이름 정의가 없었다

kanpic에서 만든 이름 있는 범위는 파일에 전혀 담기지 않았습니다. 엑셀에서 열면 `=SUM(단가)` 가 `#NAME?` 이 됩니다. 이제 엑셀의 이름 정의로 나갑니다. 한글 이름도 그대로 쓰입니다.

반대 방향(엑셀 이름 정의 읽어 오기)은 아직입니다. 가져오기가 이름을 그냥 버리는 대신 **미리보기에서 그렇게 말합니다.**

## 무엇을 버리는지 말하지 않았다

가져오기 미리보기에는 경고를 보여 줄 자리가 이미 있었지만, 서버가 경고를 하나도 만들지 않았습니다. 차트가 든 파일도, 피벗 테이블이 든 파일도, 매크로가 든 파일도 아무 말 없이 들어와 셀만 남았습니다.

이제 파일이 들고 있는데 kanpic이 아직 읽지 못하는 것을 세어서 알려 줍니다 — 이름 정의, 차트, 피벗 테이블, 이미지, 외부 파일 연결, 매크로. 가져온 뒤에 무엇이 없어졌는지 찾아다니지 않아도 됩니다.

## 확인만 하고 지나간 것

나머지는 멀쩡했습니다. 굵게·기울임·배경색·글자색·가로 세로 정렬·줄바꿈·사용자 지정 표시 형식, 수식과 계산된 값, 병합, 숨긴 행, 행 높이·열 너비, 틀 고정, 데이터 검증, 조건부 서식이 모두 왕복에서 살아남았습니다. 통화 서식이 붙은 숫자도 글자가 되지 않고 숫자로 돌아왔습니다.

## 검증 결과

- Go 테스트 세 가지를 남겼습니다. 마지막 기록된 행 뒤의 행이 숨겨지지 않는지, 메모가 양방향으로 살아남는지(값 없는 셀 포함), 이름 정의가 파일에 담기고 가져오기가 그것을 못 읽는다고 말하는지 확인합니다.
- 고치기 전 코드에서 세 가지가 모두 실패하는 것을 확인했습니다. 숨김 버그는 5~11행이 숨겨진 채로 실패합니다.
- 브라우저 E2E를 하나 남겼습니다. 실제로 내보낸 파일을 홈 화면에서 올려 경고를 확인하고, 가져온 워크북에 숨겨진 행이 없고 메모가 붙어 있는지 봅니다. 고치기 전 서버·번들에서 실패합니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest 267개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
