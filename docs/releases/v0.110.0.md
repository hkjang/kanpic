## 릴리즈 요약

v0.110.0은 **월 이름을 정렬하면 10월이 1월보다 앞에 오던 것**을 고칩니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 10월, 12월, 1월, 2월, 3월

월 이름이 든 열을 정렬하면 이렇게 늘어섰습니다. 글자 그대로 견주면 `0` 이 `월` 보다 앞이고 `1` 이 `2` 보다 앞이라 그렇습니다. `항목10` 이 `항목2` 보다 앞에 오는 것도 같은 이유입니다.

이제 값 안의 숫자를 **하나의 수로** 셉니다. `1월, 2월, 3월, 10월, 12월` 이 되고 `항목1, 항목2, 항목10` 이 됩니다.

## 엑셀과 다른 선택

**엑셀도 구글 시트도 글자 그대로 견주어 위의 순서를 냅니다.** 일부러 다르게 두었습니다. 그 순서를 원하는 사람은 거의 없고, 월별 보고서를 정렬할 때마다 손으로 고쳐야 하기 때문입니다.

다만 조용히 바꾸지는 않았습니다. **범위 정렬** 대화상자에 **숫자를 글자로 취급** 을 두어 엑셀과 같은 순서로 되돌릴 수 있습니다.

## 정확히 세는 것들

- 열다섯 자리를 넘는 숫자도 정확합니다. 계좌번호를 실수로 바꾸면 값이 뭉개지므로, 앞의 0을 뗀 뒤 자릿수를 먼저 견주고 같으면 글자로 견줍니다.
- 앞자리를 0으로 맞춘 `007호` 와 `7호` 는 같은 수입니다. 순서가 실행마다 흔들리지 않도록 자릿수를 맞춘 쪽을 앞에 둡니다.
- 같은 자리에서 숫자와 글자가 만나면 숫자가 앞입니다.

## 두 곳에 같은 규칙

정렬은 화면에서 먼저 반영하고 서버가 다시 확정합니다. 그래서 같은 비교 규칙이 Go 와 TypeScript 양쪽에 있어야 하고, 어긋나면 값이 한 번 튑니다. 두 구현 모두에 서로를 가리키는 주석을 달고 같은 경우들을 각각 테스트했습니다.

## 가는 길에 고친 것

전체 E2E 를 돌리다 `Alt+Enter` 시나리오가 한 번 깨졌습니다. 값이 `첫 줄⏎둘째 줄` 이 아니라 `첫 줄⏎째 줄둘` 이었습니다 — 첫 글자가 엉뚱한 자리로 갔습니다.

시나리오 문제가 아니라 **실제 버그였습니다.** `Alt+Enter` 는 줄바꿈을 넣은 뒤 캐럿을 다음 프레임에서 옮기고 있었습니다. 그 사이에 글자를 치면 이전 자리에 들어갑니다. 빠르게 치는 사람은 실제로 겪습니다. 이제 값과 캐럿을 그 자리에서 먼저 맞추고, 다시 그린 뒤에 한 번 더 맞춥니다. 같은 방식으로 쓰던 `F4` 도 함께 고쳤습니다.

## 검증 결과

- Go 테스트로 월 이름, 글자 그대로 옵션, 번호가 붙은 이름, 가운데 숫자, 숫자 없는 글자, 앞자리 0, 아주 긴 숫자 일곱 가지를 확인합니다.
- TypeScript 테스트로 같은 경우들을 다시 확인합니다. 처음 구현은 빈 칸의 `text` 가 없을 때 터졌고, 기존 정렬 테스트가 그것을 잡았습니다.
- 브라우저 E2E로 대화상자에서 정렬해 월 순서가 나오는지, **숫자를 글자로 취급** 을 켜면 엑셀 순서로 돌아오는지 봅니다.
- 셀 편집기와 수식 입력줄 양쪽에서 `Alt+Enter` 와 `F4` 뒤에 바로 이어 치는 경우를 확인했습니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
