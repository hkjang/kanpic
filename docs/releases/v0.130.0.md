## 릴리즈 요약

v0.130.0은 **엑셀 파일의 차트를 가져옵니다.** 오래 남아 있던 자리입니다.

## 막힌 것이 아직 막혀 있는지부터

가져오기는 오래전부터 이렇게 알렸습니다.

```
차트 2개는 가져오지 않습니다. 원본 데이터 범위는 그대로 들어옵니다.
```

버린 까닭은 `excelize`가 차트를 **쓸 수는 있어도 읽지는 못하기** 때문이었습니다. 오래된 메모를 그대로 믿지 않고 지금도 그런지 확인했습니다. v2.11.0에 `AddChart`·`AddChartSheet`·`DeleteChart`는 있고 `GetChart`는 없습니다. **여전히 막혀 있습니다.**

그래서 라이브러리를 우회해 `xl/charts/chartN.xml`을 곧바로 읽습니다.

## 무엇을 되살리나

종류와 제목, 계열이 가리키는 자리를 읽어 kanpic 차트로 다시 그립니다.

| 엑셀 | kanpic |
| --- | --- |
| 막대 · 선 · 원 · 영역 · 분산형 | `bar` `line` `pie` `area` `scatter` |
| 쌓은 막대 · 쌓은 영역 | `stacked_bar` `stacked_area` |

## 이름 공간이 두 모습으로 온다

엑셀이 쓴 파일은 `<c:barChart>`처럼 앞가지를 붙이고, 다른 도구가 쓴 파일은 기본 이름 공간을 써서 `<barChart>`로 적습니다.

이것이 중요한 까닭은 **시험에 쓸 수 있는 `excelize`가 뒤엣것만 쓰기** 때문입니다. `excelize`가 쓴 파일로만 확인하고 넘어갔다면, 정작 사람들이 들고 오는 **엑셀이 쓴 파일** 에서 아무 차트도 읽지 못하는 것을 모른 채 내보냈을 것입니다.

Go의 XML 읽기가 앞가지를 빼고 이름만 맞추는지 **파서를 쓰기 전에 따로 확인** 했고, 앞가지를 붙인 모습도 손으로 만들어 함께 시험합니다.

## 되살리지 않는 차트

계열이 **여러 시트에 걸쳐 있거나 떨어진 자리** 를 가리키는 차트는 되살리지 않습니다. kanpic의 차트는 이어진 범위 하나를 보므로, 억지로 감싸는 범위를 만들면 원래 뜻과 다른 그림이 됩니다.

엉뚱한 그림을 그려 두면 사람이 그것을 믿습니다. 그런 차트만 세어 알립니다.

## 검증 결과

- 진짜 xlsx를 만들어 가져온 뒤, 차트가 시트에 붙고 **자료까지 나오는지** 확인했습니다 — 막대 / `월별 매출` / `A1:B4` / 1월 100, 2월 150, 3월 120.
- 통째로 지나가는 시험은 이어 붙이기를 빼면 걸립니다.
- 여러 시트를 가리키는 차트가 알림으로 남는지도 확인합니다.
- Go 시험 전체와 웹 시험 376개가 통과합니다.
