## 릴리즈 요약

v0.20.0은 kanpic에 **사용자·부서·역할 기반 워크북 공유 체계**를 도입합니다. 지금까지 워크북은 로그인한 모든 사용자에게 열려 있었지만, 이제 워크북마다 소유자와 공유 대상이 있고 뷰어·댓글 작성자·편집자·소유자 역할이 모든 REST·WebSocket·MCP 경로에서 강제됩니다.

부서는 계층 구조이며 상위 부서에 공유하면 하위 부서 구성원까지 권한을 상속합니다. 링크 액세스, 편집자 재공유 허용, 뷰어 내보내기 제한, 소유권 이전, 액세스 요청 승인까지 Google Sheets에 대응하는 공유 흐름을 제공합니다.

필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며 새 마이그레이션 `018_sharing.sql`이 자동 적용됩니다.

## 업그레이드 시 접근 권한 이전 (먼저 확인하세요)

- 마이그레이션 시점에 존재하는 **모든 워크북은 `조직 내 모든 사용자 · 편집자`로 이전**됩니다. 업그레이드 직후 기존 사용자의 작업이 그대로 유지되고 접근 불가 사고가 발생하지 않습니다.
- **새로 만드는 워크북은 `제한됨`(소유자 전용)** 으로 시작합니다. 소유자가 공유 창에서 대상을 추가해야 다른 사용자가 열 수 있습니다.
- 기존 워크북을 좁히려면 공유 창의 **일반 액세스** 를 `제한됨`으로 바꾸고 필요한 사용자·부서·역할만 추가하십시오. 관리자는 모든 워크북에 접근할 수 있어 일괄 점검이 가능합니다.
- 워크북 목록(`GET /api/v1/workbooks`, `spreadsheet.workbook.list`)은 이제 **접근 가능한 워크북만** 반환합니다. 전체 목록이 필요한 자동화는 관리자 권한 키를 사용해야 합니다.

## 역할과 권한

| 역할 | 권한 |
| --- | --- |
| 뷰어 | 값·수식 결과 조회, 검색, 차트·피벗 결과 확인 |
| 댓글 작성자 | 뷰어 + 댓글 스레드 작성·답글·수정·해결 |
| 편집자 | 셀·서식·구조 편집, 정렬·필터·검증·조건부 서식, 차트·피벗·자동화, 기본적으로 재공유 |
| 소유자 | 편집자 + 공유·정책 변경, 소유권 이전, 워크북 삭제 |

- 여러 경로로 권한을 받으면 항상 가장 높은 권한이 적용됩니다.
- 소유자는 `workbooks.owner_id`가 유일한 근거이며 공유 항목으로는 부여할 수 없습니다.
- 관리자 역할 사용자는 감사와 복구를 위해 모든 워크북에 소유자 권한으로 접근하고, 공유 창에 관리자 접근임이 표시됩니다.

## 공유 대상과 링크 액세스

- **사용자**: 사용자 ID와 이메일을 모두 대소문자 구분 없이 검사합니다.
- **부서**: 관리자 콘솔에서 만든 계층형 부서. 상위 부서 공유는 하위 부서까지 상속합니다.
- **역할**: OIDC 토큰의 역할 이름을 그대로 사용해 조직 전체 정책을 표현합니다.
- **일반 액세스**: `제한됨`, `조직 내 모든 사용자`, `링크가 있는 모든 사용자` 중 선택하고 링크로 들어온 사용자에게 부여할 역할을 지정합니다. kanpic은 인증 뒤에서 동작하므로 익명 접근은 제공하지 않습니다.
- **소유자 정책**: 편집자의 재공유 허용 여부, 뷰어·댓글 작성자의 내보내기·복사 허용 여부, 소유권 이전(이전 소유자는 편집자로 유지).

## 액세스 요청

- 권한이 없는 사용자가 워크북 링크를 열면 액세스 요청 화면이 표시되고 보기 또는 편집 권한을 요청할 수 있습니다.
- 요청 생성 endpoint는 의도적으로 워크북 권한 없이 호출할 수 있으며, 로그인만 요구합니다.
- 같은 사용자의 재요청은 대기 중 요청을 갱신하고, 승인하면 요청 역할로 즉시 공유됩니다. 이미 처리된 요청을 다시 결정하면 `409`로 거부합니다.

## 권한 강제

- 경로 파라미터(시트, 차트, 피벗, 댓글, 댓글 메시지, 이름 범위, 필터 보기, 검증, 조건부 서식, 충돌, 버전, 작업, 자동화, 자동화 실행, AI 작업, 액세스 요청)에서 소속 워크북을 역추적하는 리졸버를 추가해 **단일 미들웨어**가 모든 워크북 관련 요청을 검사합니다.
- 읽기는 뷰어, 댓글 관련 쓰기는 댓글 작성자, 그 외 쓰기는 편집자, 공유·소유권·워크북 삭제는 소유자(또는 재공유가 허용된 편집자) 권한을 요구합니다.
- WebSocket 협업 세션은 같은 판정을 사용하며 뷰어·댓글 작성자는 읽기 전용으로 연결됩니다.
- MCP 도구 호출도 인자에 포함된 리소스 ID로 같은 검사를 수행합니다.
- 내보내기와 워크북 복제는 뷰어 복사 정책을 따르며 차단 시 `workbook_copy_disabled`를 반환합니다.
- 오류 코드: `workbook_access_denied`, `workbook_read_only`, `workbook_sharing_locked`, `workbook_copy_disabled`. 응답에는 호출자의 유효 권한이 함께 담겨 UI가 적절한 안내를 표시합니다.

## 편집기와 홈 화면 UX

- 편집기 상단에 뷰어·댓글 가능·편집자 배지를 표시하고, 공유 버튼에 공유 대상 수를 함께 보여줍니다.
- 보기 전용 사용자는 서식·정렬·병합·실행 취소 등 쓰기 도구가 비활성화되고, 셀 편집·붙여넣기·자동 채우기·삭제 시 권한 안내를 받습니다. 컨텍스트 메뉴의 쓰기 항목도 함께 잠깁니다.
- 자동화 패널과 차트·피벗 생성은 편집 권한이 있을 때만 노출됩니다.
- 홈 화면에 **내 소유 / 나와 공유됨** 필터, 소유자 이름, 권한·경로 배지를 추가하고 카드 메뉴에서 바로 공유 창을 열 수 있습니다.
- 권한이 없는 링크는 액세스 요청 화면으로 안내합니다.

## 관리자 콘솔

- `/admin`에 **부서 및 공유** 화면을 추가했습니다. 부서 계층 생성·이름 변경·상위 부서 이동·삭제와 구성원 추가·제거를 제공합니다.
- 부서는 최대 8단계까지 중첩되고 같은 상위 부서 아래에서 이름이 중복될 수 없습니다. 하위 부서가 있으면 삭제할 수 없고, 삭제 시 해당 부서로 부여된 공유가 함께 정리됩니다.
- 부서 조회는 모든 로그인 사용자가 가능하고(공유 대상 선택에 필요) 변경은 `admin.*` scope 또는 관리자 세션만 허용합니다.

## REST API

```http
GET    /api/v1/workbooks/{workbookId}/sharing
PATCH  /api/v1/workbooks/{workbookId}/sharing
PUT    /api/v1/workbooks/{workbookId}/shares
DELETE /api/v1/workbooks/{workbookId}/shares/{shareId}
POST   /api/v1/workbooks/{workbookId}/sharing:transfer-ownership
GET    /api/v1/workbooks/{workbookId}/access-requests
POST   /api/v1/workbooks/{workbookId}/access-requests
POST   /api/v1/access-requests/{requestId}:approve
POST   /api/v1/access-requests/{requestId}:deny
GET    /api/v1/departments
POST   /api/v1/departments
GET    /api/v1/departments/{departmentId}
PATCH  /api/v1/departments/{departmentId}
DELETE /api/v1/departments/{departmentId}
POST   /api/v1/departments/{departmentId}/members
DELETE /api/v1/departments/{departmentId}/members/{userId}
GET    /api/v1/me/departments
```

- 워크북 조회·목록 응답에 `link_access`, `link_role`, `sharing_locked`, `viewer_can_copy`, 호출자의 `access_role`·`access_source`와 `shared_count`가 추가되었습니다.
- 공유 endpoint 응답은 공유 상태와 호출자의 유효 권한을 함께 반환해 UI가 한 번의 호출로 화면을 구성합니다.

## MCP 도구

- `spreadsheet.share.list|grant|revoke|link|transfer_ownership`
- `spreadsheet.access_request.list|decide`
- `spreadsheet.department.list|create|update|delete|add_members|remove_member`

부서 변경 도구는 `admin.*`, 공유 변경 도구는 `workbook.write`, 조회 도구는 `workbook.read` scope를 사용합니다.

## PostgreSQL 마이그레이션

- `018_sharing.sql`이 `workbooks`에 `link_access`, `link_role`, `sharing_locked`, `viewer_can_copy`, `sharing_migrated_at`을 추가하고 기존 행을 조직 전체 편집으로 이전합니다.
- `departments`(계층), `department_members`, `workbook_shares`, `workbook_access_requests` 테이블과 소유자·공유 대상·대기 요청 조회 인덱스를 추가합니다.
- 링크 범위와 역할, 공유 역할, 요청 상태는 DB CHECK 제약으로 강제됩니다.

## 업그레이드 참고

- v0.19.0 이하에서 시작하면 `018_sharing.sql`이 자동 적용됩니다. 운영 업그레이드 전 PostgreSQL 백업을 권장합니다.
- 워크북 목록 API가 접근 가능한 워크북만 반환하므로 전체 목록에 의존하는 통합은 관리자 scope 키로 전환해야 합니다.
- 두 번째 사용자로 워크북을 조작하는 자동화 시나리오는 대상 사용자에게 먼저 권한을 부여해야 합니다.
- 인증을 활성화하지 않은 개방형 로컬 설치에서는 모든 요청이 같은 로컬 사용자로 취급되어 기존과 동일하게 동작합니다.

## 현재 지원 범위와 다음 단계

- 이번 버전의 부서는 관리자 콘솔에서 관리합니다. OIDC 그룹 클레임을 부서로 자동 동기화하는 기능은 포함하지 않았고, 조직 전체 정책은 역할 기반 공유로 표현합니다.
- 공유 알림 이메일과 시트·범위 단위의 세부 보호 범위는 아직 제공하지 않습니다.
