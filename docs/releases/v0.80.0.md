## 릴리즈 요약

v0.80.0은 **동시 편집 중에 값이 엉뚱한 줄에 찍히던 문제를 고칩니다.** 한 사람이 행을 지우는 사이 다른 사람이 그 아래 셀을 저장하면, 그 값이 **한 줄 아래에 들어가고 아무도 건드리지 않은 값이 지워졌습니다.** 오류도 경고도 충돌 기록도 없었습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 무슨 일이 일어났나

셀 저장 요청은 행과 열을 **번호로** 지목합니다. 그 번호는 저장하는 사람이 화면에서 본 시점의 것입니다. 그 사이에 누가 행을 지우면 아래 행이 전부 한 칸씩 올라가므로, 같은 번호가 다른 줄을 가리키게 됩니다.

여섯 줄짜리 표에서 재현한 결과입니다.

```
처음:            행1 행2 행3 행4 행5 행6
A가 3행 삭제:     행1 행2 행4 행5 행6
B가 A5 저장:      행1 행2 행4 행5 [B의 값]   ← 행6이 사라졌다
```

B는 행5를 고치려 했는데 행5는 그대로 남고 행6이 지워졌습니다.

## 고친 결과

요청에 담긴 기준 버전 이후의 **구조 변경을 찾아 주소를 먼저 옮긴 뒤** 적용합니다. 수식 참조를 옮기는 것과 같은 규칙을 씁니다.

```
고친 뒤:          행1 행2 행4 [B의 값] 행6   ← 편집이 행5를 따라갔다
```

편집하려던 행 자체가 지워진 경우에는 갈 곳이 없습니다. 그 자리를 물려받은 값을 덮어쓰는 것보다 낫기 때문에 **그 편집만 반영하지 않고** 왼쪽 아래에 알려 줍니다.

> ⚠ 편집 1곳이 반영되지 않았습니다
> A3: 저장하는 사이에 다른 사람이 그 행이나 열을 지웠습니다.

행 삽입도 같은 방식으로 처리합니다. 위에 두 줄이 들어왔다면 편집도 두 줄 내려갑니다.

## 구현 메모

기록해 둔 작업 로그에 구조 변경의 축·동작·위치·개수가 이미 들어 있어서, 그것을 기준 버전 이후로 읽어 순서대로 적용하면 됩니다. 다만 **이동**은 도착 위치가 기록되지 않고 있어 함께 남기도록 했습니다. 이동은 자리바꿈이라 도착 위치를 모르면 옮길 수가 없습니다.
