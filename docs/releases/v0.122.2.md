## 릴리즈 요약

v0.122.2는 빠른 채우기가 **본보기 하나만 보고 틀린 규칙을 세우던** 경우를 막습니다.

## 본보기가 하나일 때가 가장 위험하다

규칙은 본보기를 하나도 빠짐없이 설명할 때만 인정합니다. 그런데 본보기가 **하나뿐** 이면 어긋날 것이 없으니 틀린 규칙도 그 조건을 통과합니다.

`2026-08-23` 에서 `2026년 8월 23일` 을 만들어 보라고 하면 이런 일이 벌어졌습니다. 앞의 0을 떼는 방법이 없으니 **"년 8월 " 을 통째로 글자로** 굳혀 넣고, 그 규칙은 본보기를 정확히 재현합니다. 그리고 다음 줄에 `2027-01-15` 를 넣으면 **2027년 8월 15일** 이 나옵니다. 조용히, 틀리게.

이제 본보기가 하나뿐일 때는 규칙의 글자 조각이 **그 줄의 값에서 온 것처럼 보이는지** 봅니다. 글자나 숫자가 원본에 들어 있으면 그 규칙은 이 줄에서만 맞는 것으로 보고 채우지 않습니다. 구분자와 띄어쓰기는 사람이 적은 것이므로 따지지 않습니다.

| 본보기 하나 | 결과 |
| :--- | :--- |
| `2026-08-23` → `2026년 8월 23일` | 채우지 않고 본보기를 하나 더 청함 |
| `2026-08-23` → `2026년 08월 23일` | 채움 (굳혀 넣은 자료 없음) |
| `1234` → `ID-1234` | 채움 (`ID-` 는 원본에 없음) |
| `홍`+`길동` → `홍 길동` | 채움 (띄어쓰기뿐) |

본보기가 둘 이상이면 이 검사를 하지 않습니다. 서로 어긋나는 규칙은 이미 걸러지기 때문입니다 — 위의 날짜도 본보기 두 줄이면 바로 됩니다.

## 될 일이 안 되기도 한다

`seoul` → `seoul (Korea)` 처럼 사람이 적은 낱말에 원본의 글자가 우연히 섞이면 본보기 하나로는 거절합니다. 본보기를 하나 더 채우면 풀립니다.

이쪽으로 치우친 것은 의도한 것입니다. 잘못 거절하면 사람이 한 칸 더 채우면 되지만, 잘못 받아들이면 수백 줄이 틀린 채로 채워지고 **어느 줄이 틀렸는지 아무도 모릅니다.**

## 검증 결과

- 위 표의 네 가지가 각각 거절·통과되는지 봅니다.
- 본보기를 하나 더 주면 날짜 재배열이 되는지, 자릿수 맞추기는 두 본보기가 어긋나 여전히 거절되는지 봅니다.
