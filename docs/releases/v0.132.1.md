## 릴리즈 요약

v0.132.1은 **편집기 빠른 이동이 워크북 스무 개까지만 닿던 것** 을 고칩니다. 같은 자리에서 받는 양도 열 배 넘게 줄었습니다.

## 많이 받고 적게 썼다

앞 판에서 목록 화면에 빠른 이동을 붙이고, 편집기 쪽에도 같은 한계가 있는지 보았습니다. 있었고, 낭비까지 겹쳐 있었습니다.

```
limit 없이 전체 목록을 받은 뒤  →  .slice(0,20)
```

워크북이 208개인 곳에서 **편집기를 열 때마다 134KB** 를 받으면서, 정작 스물한 번째부터는 이름을 적어도 찾히지 않았습니다. 워크북이 늘수록 받는 양만 늘고 닿는 곳은 그대로입니다.

앞의 스무 개만 받고, 그 밖의 것은 적은 이름으로 서버에 묻도록 했습니다. 목록 화면에 쓴 것과 같은 길입니다.

| | 고치기 전 | 지금 |
| --- | --- | --- |
| 받는 양 | 134KB | **12KB** |
| 닿는 곳 | 스무 개 | **전부** |

## 흔들리던 시험

같은 자리에서 제 시험의 흔들림도 하나 고쳤습니다. 디자인 묶음을 세는 데 `evaluateAll`을 썼는데, 이것은 **기다려 주지 않아** 목록이 도착하기 전에 빈 것을 재고 맙니다.

혼자 돌리면 통과하고 전체를 돌리면 걸렸습니다 — 프레젠테이션 서비스가 느려질 때만 드러나는 종류입니다. 붙을 때까지 기다린 뒤에 세도록 고치고, 세 번 돌려 확인했습니다.

## 검증 결과

- 고치기 전 코드에서 스무 개 밖 워크북을 찾지 못합니다.
- e2e 193개를 통째로 돌렸습니다.
- Go 시험 전체와 웹 시험 379개가 통과합니다.
