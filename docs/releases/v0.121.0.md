## 릴리즈 요약

v0.121.0은 **조건부 서식을 종이에 싣습니다.** 지난 릴리즈에서 인쇄물의 서식이 살아난 김에 확인해 보니, 조건부 서식은 여전히 하나도 나가지 않고 있었습니다.

마이그레이션은 없습니다.

## 문서에 쓴 문장을 확인하다 찾았다

v0.120.0 사용 설명서에 "조건부 서식으로 칠해진 배경색도 함께 나갑니다" 라고 적었습니다. 그리고 그 문장이 맞는지 확인해 봤더니 **틀렸습니다.**

인쇄는 셀에 **저장된** 서식을 읽습니다. 조건부 서식은 저장된 것이 아니라 값에 따라 그때그때 정해지는 것이라, 인쇄가 따로 묻지 않으면 존재조차 모릅니다. 화면에서 초록으로 칠해진 칸이 종이에서는 흰 칸이었습니다.

읽으라고 칠해 놓은 표가 종이에서 아무 표시 없는 숫자 뭉치가 되면, 인쇄한 사람은 그 표를 다시 읽어야 합니다.

## 화면에서 본 대로 나간다

이제 인쇄할 때 그 범위의 조건부 서식을 함께 물어보고, 화면과 **같은 차례로** 얹습니다 — 셀 자신의 서식 위에 조건부 서식이 올라갑니다.

| 종류 | 종이에서 |
| :--- | :--- |
| 배경색·글자색 | 그대로 |
| 데이터 막대 | 같은 비율의 띠 |
| 아이콘 집합 | 값 앞의 기호 (▲ ▼ ✓ ● ◑ …) |

아이콘은 **흑백으로 인쇄해도 모양이 남는** 기호를 씁니다. 색이 유일한 단서면 흑백 종이에서는 아무 말도 하지 않습니다. 값을 밀어낼 뿐 대신하지도 않습니다.

규칙이 재는 칸 수에는 서버 한도가 있으므로 범위를 잘라 여러 번 묻습니다. 도중에 실패해도 인쇄 자체는 막지 않습니다 — 색이 빠진 종이가 안 나오는 종이보다 낫습니다.

## 검증 결과

- 규칙에 걸린 칸만 칠해지는지, 걸리지 않은 칸은 그대로인지 브라우저에서 계산된 색으로 확인합니다.
- 아이콘이 값 앞에 붙되 값을 지우지 않는지 봅니다.
- 조건부 서식이 셀 자신의 서식을 갈아치우지 않고 얹히는지, 데이터 막대의 띠 너비가 비율과 같은지, 모르는 아이콘 집합에 `undefined` 를 찍지 않는지 단위 시험으로 봅니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
