## 릴리즈 요약

v0.124.0은 **엑셀·구글 시트 문서를 그대로 따라 적었는데 되지 않던 선택 인수** 네 가지를 채웁니다. `CONCATENATE`도 함께 넣었습니다.

## 되는지 하나씩 적어 보았다

지난 판에서 함수 목록과 실제 셈을 맞대어 보며 `TREND`의 인수 차례가 뒤바뀐 것을 찾았습니다. 이번에는 한 걸음 더 들어가, 흔히 쓰는 함수를 **선택 인수까지 넣어** 실제 서버에 하나씩 적어 보고 답을 엑셀·시트와 맞대었습니다.

반올림과 나머지, 날짜 셈은 모두 맞았습니다 — 음수의 `INT`와 `TRUNC`, `MOD`가 나누는 수의 부호를 따르는 것, `CEILING(-4.42,-0.05)`이 `-4.45`가 되는 것, `PERCENTILE`의 선형 보간, `NETWORKDAYS`와 `EOMONTH`까지. 빠진 것은 네 군데였습니다.

| 함수 | 빠져 있던 인수 |
| --- | --- |
| `SUBSTITUTE(글, 찾을 값, 바꿀 값, [몇 번째])` | 몇 번째로 나온 것만 바꿀지 |
| `FIND(찾을 값, 글, [시작 위치])` | 어디부터 찾을지 |
| `SEARCH(찾을 값, 글, [시작 위치])` | 어디부터 찾을지 |
| `WEEKDAY(날짜, [유형])` | 한 주가 어느 요일에 시작하는지 |

문서대로 적으면 `#VALUE!`가 났습니다. 인수를 잘못 쓴 것이 아니라 받아주지 않았던 것입니다.

`WEEKDAY`의 유형은 엑셀이 쓰는 `1`, `2`, `3`과 `11`~`17`을 모두 받습니다. 나라마다 한 주가 시작하는 요일이 달라서 있는 값입니다. `WEEKNUM`은 이미 유형을 받고 있었으니, 같은 묶음 안에서 갈려 있었던 셈입니다.

## CONCATENATE

`CONCAT`만 있고 `CONCATENATE`가 없어서, 옛 이름을 적으면 `#NAME?`이 났습니다. 엑셀을 배운 사람은 대개 옛 이름을 먼저 떠올립니다. 이제 둘 다 알아듣습니다.

## 한글도 자리가 맞는가

`FIND`가 글자가 아니라 바이트로 세고 있었다면 한글에서 자리가 어긋났을 것입니다. 확인해 보니 이미 글자로 세고 있었고, 시작 위치를 더한 뒤에도 그대로입니다.

```
=FIND("나","가나다나",3)        4
=SUBSTITUTE("가나가","가","다",2)  가나다
```

## 검증 결과

- 고치기 전 코드에서 **17가지** 가 걸립니다.
- 말이 되지 않는 값은 조용히 넘어가지 않습니다 — `SUBSTITUTE(…,0)`과 글 끝을 넘어선 `FIND`는 `#VALUE!`, 없는 `WEEKDAY` 유형은 `#NUM!`입니다.
- 함수 목록의 설명도 새 인수에 맞추어 고쳤습니다.
- `AGGREGATE`와 `NUMBERVALUE`는 아직 없습니다. 따로 두었습니다.
