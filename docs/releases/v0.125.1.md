## 릴리즈 요약

v0.125.1은 **오류를 피해 가려고 쓰는 도구가 오류 때문에 막혀 있던 것** 을 고칩니다. `ERROR.TYPE`도 넣었습니다.

## 같은 모양을 마저 훑는다

v0.125.0에서 `COUNT`를 고치며, 같은 모양이 더 있는지 훑어보았습니다. 여섯 개가 더 있었고 모두 **함수의 뜻 자체가 막혀 있는** 꼴이었습니다. `A2`가 오류일 때입니다.

```
=ISNUMBER(A2)    #N/A
=ISBLANK(A2)     #N/A
=ISTEXT(A2)      #N/A
=ISNONTEXT(A2)   #N/A
=ISLOGICAL(A2)   #N/A
=TYPE(A2)        #N/A
=COUNTBLANK(…)   #N/A
=ERROR.TYPE(A2)  #N/A
```

## 도구가 오류에 막혀 있었다

가장 큰 것은 이것입니다.

```
=IF(ISNUMBER(A2),A2,0)
```

오류를 피해 가려고 쓰는 **가장 흔한 꼴** 입니다. 그런데 그 `ISNUMBER`가 `A2`의 오류에 걸려 함께 멈췄습니다. 피해 갈 방법 자체가 없었던 셈입니다.

"값이 숫자인가?"는 오류가 든 칸에도 답할 수 있어야 하는 질문입니다. 답은 "아니다"입니다.

`ERROR.TYPE`은 아예 쓸 수 없었습니다. 오류를 **들여다보라고** 있는 함수인데 인수의 오류에 먼저 걸렸습니다. 이제 번호를 돌려줍니다.

| 오류 | 번호 |
| --- | --- |
| `#NULL!` | 1 |
| `#DIV/0!` | 2 |
| `#VALUE!` | 3 |
| `#REF!` | 4 |
| `#NAME?` | 5 |
| `#NUM!` | 6 |
| `#N/A` | 7 |

`TYPE`은 오류에 `16`, 배열에 `64`를 돌려줍니다. 엑셀과 같습니다.

## 건드리지 않은 것

| 무엇 | 왜 |
| --- | --- |
| `ISEVEN`, `ISODD` | 짝수인지 묻기 전에 수여야 합니다. 엑셀도 오류를 그대로 냅니다 |
| `SUMIF`, `COUNTIF` | 조건에 맞는 것만 골라 세는 함수라, 오류를 어떻게 다뤄야 하는지 **확인하지 못했습니다**. 확인한 뒤에 고칠 일입니다 |
| `SUM`, `AVERAGE` 등 | 더할 수 없는 것이 섞여 있으니 합계도 알 수 없습니다. 그대로 멈춥니다 |

## 검증 결과

- 고치기 전 코드에서 열 가지가 걸립니다.
- 실제 서버에서 스무 가지를 확인했습니다.
- `=SUM`과 `=ISEVEN`은 그대로 멈춥니다.
- Go 시험 전체와 웹 시험 376개가 통과합니다.
