## 릴리즈 요약

v0.124.3은 **엑셀에서 가져온 날짜로 날짜 함수를 쓸 수 없던 것** 을 고칩니다. 화면에는 날짜로 잘 보이는데 `=YEAR()`를 걸면 `#VALUE!`가 났습니다.

## 보이기는 하는데 셈에는 쓸 수 없었다

표 프로그램은 날짜를 **날 수** 로 담습니다. 1899-12-30을 0으로 두고 하루씩 세므로 2024-01-15는 `45306`입니다. 엑셀 파일을 읽어 오면 날짜가 이 모습으로 들어옵니다.

칸에 손으로 적은 날짜는 `"2024-01-15"`라는 글로 담깁니다. 그래서 한 워크북 안에 **두 모습이 함께** 있게 됩니다.

수식 쪽은 글만 읽을 줄 알았습니다.

```
=YEAR(A1)               #VALUE!     A1 은 가져온 날짜
=MONTH(A1)              #VALUE!
=WEEKDAY(A1)            #VALUE!
=DATEDIF(A1,…,"M")      #VALUE!
=TEXT(A1,"yyyy-mm-dd")  "45306"

=YEAR("2024-01-15")     2024        손으로 적은 날짜는 된다
```

브라우저의 격자는 날 수를 **이미 날짜로 읽어** 제대로 보여주고 있었습니다. 그래서 가져온 파일의 날짜 칸은 눈으로 보기에 아무 문제가 없습니다. 그 칸을 수식에 넣는 순간에야 드러납니다.

서버가 브라우저와 같은 방식으로 읽도록 했습니다.

## 1900년은 윤년이 아니다

엑셀은 1900년을 윤년으로 잘못 셉니다. 초기 호환을 위해 남겨 둔 것으로, 지금까지 그대로입니다. 그래서 일련번호 `60`은 **없는 날인 1900-02-29** 를 가리킵니다.

이 어긋남 때문에, `60`보다 작은 번호는 하루 뒤에서 세야 `1`번이 1900-01-01이 됩니다. 브라우저 쪽은 이것을 보지 않고 있어서 `1`번을 `1899-12-31`로 그리고 있었습니다. 양쪽 다 고쳤습니다.

```
1번  →  1900-01-01
59번 →  1900-02-28
61번 →  1900-03-01
```

## 검증 결과

- 진짜 엑셀 파일을 만들어 가져온 뒤, 그 칸에 날짜 함수를 걸어 확인했습니다.
- 양쪽 시험이 **같은 날짜** 를 고정합니다. 고치기 전 서버에서 14가지, 브라우저에서 1가지가 걸립니다.
- 글로 적힌 `"2024"`는 날 수로 보지 않습니다. 진짜 숫자만 가릅니다.
- 날짜가 될 수 없는 값(`-1`, `"abc"`, 9999년 너머)은 그대로 `#VALUE!`입니다.
- Go 시험 전체와 웹 시험 372개가 통과합니다.
