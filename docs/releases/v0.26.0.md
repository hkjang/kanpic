## 릴리즈 요약

v0.26.0은 AI 요청을 **모델에 맞춰 스스로 조절**합니다. 응답 토큰 상한을 고정값 8,192로 보내던 것을 그만두고, Gateway가 알려 주는 **모델 컨텍스트 길이**에서 입력 추정치를 뺀 만큼을 자동으로 사용합니다. 응답이 잘리면 더 큰 상한으로 다시 요청하고, Gateway가 잠시 바쁘면 알아서 재시도합니다. 실제로 쓴 토큰도 화면에 표시합니다.

필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며 새 마이그레이션은 없습니다.

## 응답 상한 자동 계산

- 예전에는 `min(8192, 512 + max_changes × 96)` 이라는 고정 계산을 썼습니다. 32k, 128k 컨텍스트 모델을 붙여도 8,192 토큰에서 멈췄고, 계획이 길면 잘린 JSON이 `model returned invalid plan JSON` 오류로 보였습니다.
- 이제 `GET /v1/models`에서 `max_model_len`(vLLM) 또는 `context_length`를 읽어 **컨텍스트 길이 − 입력 추정 토큰 − 여유분**을 그 요청의 `max_tokens`로 사용합니다. 32k 모델에서는 8,192가 아니라 약 29,900 토큰을 쓸 수 있습니다.
- 모델 정보는 10분간 캐시하므로 계획마다 추가 왕복이 생기지 않습니다.
- `ai.model`에 적은 이름이 목록에 없고 Gateway가 모델을 하나만 서비스하면 그 모델을 사용합니다. 모델 이름을 비워 두고 운영할 수 있습니다.
- 새 설정 `ai.max_output_tokens`(기본 `0` = 자동)로 상한을 직접 고정할 수 있습니다.

## 잘린 응답과 일시적 실패의 자동 처리

- 응답이 상한에 걸려 잘리면(`finish_reason: length`) 상한을 키워 **자동으로 다시 요청**합니다. 컨텍스트를 이미 다 쓴 상태라면 재시도 대신 “선택 범위를 좁히거나 `ai.max_changes`를 낮추세요”라고 안내합니다.
- 429와 5xx, 연결 실패는 짧게 기다렸다가 최대 2회까지 재시도합니다. 400대 거부 응답은 재시도하지 않습니다.

## 사용량 표시

- 계획을 만들면 **입력 토큰 · 응답 토큰 · 재시도 횟수**가 계획 카드에 표시됩니다. 값은 감사 이벤트에도 남아 나중에 다시 볼 수 있습니다.
- **모델에 보내는 내용 보기**에는 `max_tokens`와 함께 **컨텍스트 길이**와 **입력 추정 토큰**이 표시되고, 그 상한이 어떻게 계산됐는지 한 줄로 설명합니다.

## 검증 결과

- `go vet ./...`와 `go test ./...`를 통과했습니다. 컨텍스트 길이에 따른 상한 계산, 모델 목록에서 컨텍스트 길이와 모델 이름 읽기, 잘린 응답의 상한 증가 재시도, 더 늘릴 수 없을 때의 안내, 일시적 실패만 재시도하는지를 확인합니다.
- React/Vitest 29개 테스트 파일, 133개 테스트를 통과했습니다.
- TypeScript 타입 검사와 Vite 프로덕션 빌드를 통과했습니다.
- Playwright E2E 69건을 통과했습니다. E2E용 게이트웨이가 컨텍스트 길이를 보고하도록 바꿔 실제 요청의 `max_tokens`가 고정값을 넘는지, 사용 토큰이 화면에 표시되는지 확인합니다.
- vLLM 형식의 임시 게이트웨이로 직접 확인했습니다. 32,768 컨텍스트 모델에서 `max_tokens` 29,921이 요청되고 사용량이 보고되며, 컨텍스트를 알리지 않는 게이트웨이에서는 8,192 → 16,384로 자동 증가한 뒤 계획을 받았습니다.

## 업그레이드 참고

- 응답 상한이 커지면서 모델이 더 긴 계획을 반환할 수 있습니다. 한 번에 바뀌는 셀 수는 계속 `ai.max_changes`가 제한합니다.
- 예전 동작(고정 상한)을 원하면 `ai.max_output_tokens`에 8192를 설정하세요.
