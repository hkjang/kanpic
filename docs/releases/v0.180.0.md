## 릴리즈 요약

v0.180.0은 **병합된 칸을 만난 데이터 정리** 가 알아들을 수 있는 말을 하고 멈추게 합니다.

## 사람이 본 것은 이 한 줄이었습니다

```
stored merge metadata is invalid
```

병합된 칸이 섞인 자료에서 **중복 항목 삭제** 를 하면 이렇게 되었습니다.

1. 남길 행을 위로 끌어올립니다 — 서식을 통째로 들고 갑니다.
2. 병합 정보는 **자기 자리를 적어 두는 것** 이므로, 다른 행으로 옮겨 적으면 자기 자리가 아닙니다.
3. 서버가 묶음을 통째로 물리칩니다.

무엇이 잘못되었는지도, 무엇을 해야 하는지도 알 수 없습니다. 게다가 정리는 **하나도 되지 않은 채** 끝납니다.

## 정렬이 하던 대로 합니다

정렬은 오래 전부터 이것을 알고 있었습니다 — `병합된 셀은 병합 해제 후 정렬할 수 있습니다`. 행을 옮기는 정리도 같은 일을 하므로 같은 말을 해야 합니다.

| 하는 일 | 무엇을 하는가 | 병합을 만나면 |
| --- | --- | --- |
| 중복 항목 삭제 | 행이 위로 올라갑니다 | 멈춥니다 |
| 부분합 제거 | 행이 지워집니다 | 멈춥니다 |
| 텍스트를 열로 분할 | 오른쪽 열을 덮어씁니다 | 멈춥니다 |
| 공백 제거 | 제자리에서 고칩니다 | 그냥 됩니다 |
| 텍스트로 저장된 숫자 | 제자리에서 고칩니다 | 그냥 됩니다 |

**어느 칸이 걸렸는지 짚어 줍니다.** "병합된 셀이 있습니다" 만으로는 넓은 표에서 그 칸을 찾을 수 없습니다.

```
B2은(는) 병합된 셀이므로 중복 행을 지울 수 없습니다.
병합을 해제한 뒤 다시 시도하세요.
```

## 열로 나누는 것은 물리쳐지지도 않았습니다

더 나쁜 쪽입니다. 오른쪽 칸에 서식 없이 써 넣으므로 **덮인 칸 일부만 병합을 잃습니다.** 반쪽짜리 병합은 아무 곳에도 적히지 않고, 화면은 살아남은 칸을 보고 상자를 계속 그립니다.

## 검증 결과

- 범위 **밖에서 시작한** 병합도 찾는지 시험합니다. 병합 정보는 덮인 칸마다 적혀 있으므로 안쪽 칸 하나만 보면 됩니다.
- 브라우저 시험은 막는 코드를 빼면 깨지는 것을 먼저 확인한 뒤에 넣었습니다.
- 웹 시험 408개와 Go 시험 전체가 통과합니다.
