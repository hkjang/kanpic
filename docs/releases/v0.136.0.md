## 릴리즈 요약

v0.136.0은 **AI 도우미가 필터 보기를 만들 수 있게** 합니다. "매출 100 이상만 보이게 해줘" 가 이제 됩니다.

## 보이지 않게 하는 것과 지우는 것

"완료된 항목은 빼고 보여줘" 를 에이전트가 할 수 있는 방법이 없었습니다. 줄을 지우는 것은 시킨 일이 아닙니다.

필터 보기는 조건에 맞지 않는 줄을 **숨길 뿐** 입니다. 자료는 한 칸도 사라지지 않습니다. 지우지 않으므로 위험도도 낮게 잡습니다.

```
"매출 100 이상만 보이게 해줘"
"완료된 항목은 빼고 보여줘"
"부서가 비어 있는 줄만 찾아줘"
```

**만든 필터는 바로 켭니다.** 만들어 놓고 꺼져 있으면 사람은 아무 변화도 보지 못합니다. 되돌리면 필터가 지워지고 숨겼던 줄이 다시 보입니다.

필터 보기는 만든 사람에게만 보이므로 남의 화면을 바꾸지 않습니다.

## 같은 "열 번호" 가 도구마다 다릅니다

피벗의 열 번호는 **원본 범위 안의 몇 번째** 자리입니다. 필터의 열 번호는 **시트의 열 번호** 입니다. 저장소가 그렇게 읽습니다.

둘을 섞으면 엉뚱한 열을 걸러 놓고도 계획은 그럴듯해 보입니다. 모델에게 다르다고 분명히 일러 두고, 계획할 때 범위 안을 가리키는지 확인합니다.

한 열에 조건을 둘 거는 것도 저장소가 거부합니다. 승인한 뒤에 깨지는 대신 **계획할 때** 걸러냅니다. 연산자 목록도 실제로 걸러내는 쪽에서 가져와 봅니다 — 옮겨 적으면 한쪽만 늘어납니다.

## 승인 화면이 열 이름으로 말합니다

```
필터 보기 만들기                     낮은 위험
A1:B10 · B열 이상 100
```

`{"column": 2}` 를 보고 B열이라고 머릿속에서 옮기지 않아도 됩니다.

## 검증 결과

- 계획부터 승인, 필터가 켜진 채로 만들어지는지, 여섯 칸이 그대로 남는지, 되돌리면 사라지는지까지 PostgreSQL 로 돌립니다.
- 범위 밖 열, 한 열에 조건 둘, 모르는 연산자, 조건 없음을 모두 계획 단계에서 확인합니다.
- Go 시험 전체, 통합 시험 전체와 웹 시험 381개가 통과합니다.
