## 릴리즈 요약

v0.135.0은 **AI 도우미가 피벗과 입력 규칙을 만들 수 있게** 합니다. 그리고 에이전트가 권한을 넘는 지름길이 되던 구멍을 막았습니다.

## "부서별 매출 합계" 를 수식으로 풀지 않습니다

분류별 합계를 물으면 에이전트가 할 수 있는 것은 셀마다 `SUMIF` 를 박아 넣는 것뿐이었습니다. 그러면 **줄이 늘 때마다 수식을 다시 손봐야 합니다.**

이제 피벗을 만듭니다. 원본은 한 칸도 건드리지 않고, 자료가 늘면 새로 고치면 그만입니다.

```
"부서별 매출 합계를 요약해줘"
"월별 평균을 내줘"
```

합계·평균·개수·고유 개수·최소·최대·중앙값·곱·표준편차·분산 중에서 고릅니다. 집계 방법 목록이 **계산하는 쪽에만** 있었는데, 옮겨 적으면 한쪽만 늘어납니다. 이제 양쪽이 같은 목록을 보므로 셀 수 없는 방법은 승인 화면에 오르기 전에 걸립니다.

## 잘못된 값은 색칠이 아니라 막아야 합니다

"상태 열은 진행/완료만 고르게 해줘" 를 조건부 서식으로 하면, 잘못된 값에 색이 칠해질 뿐 **값은 이미 들어와 있습니다.**

이제 입력 규칙을 만듭니다. 목록에서 고르기, 다른 범위의 값에서 고르기, 체크박스, 숫자·날짜 조건, 수식 조건을 만들 수 있습니다.

어긋나는 값을 **거부할지 경고만 할지** 는 요청에 달렸습니다. "못 넣게 해줘" 처럼 분명히 말한 경우에만 거부로 만듭니다 — 묻지도 않은 거부는 나중에 남의 입력을 막습니다.

되돌리면 규칙이 지워지고 막혔던 입력이 다시 됩니다.

## 승인 화면이 사람 말로 먼저 말합니다

승인 화면에는 `create_pivot` 이라는 이름과 JSON 만 있었습니다. 열 번호를 보고 승인 여부를 정하라는 것은 무리입니다.

```
피벗 요약 만들기
A1:B4 · 부서별 · 매출 합계

입력 규칙 만들기
B2:B5 · 목록에서 고르기 · 진행, 완료 · 어긋나면 입력 거부
```

원문은 그 아래 그대로 남습니다. 한 줄로 줄이면서 빠뜨린 것을 확인할 곳이 있어야 합니다.

## 에이전트가 권한을 넘는 지름길이었습니다

조건부 서식은 REST·MCP 에서 `format.write`, 피벗은 `pivot.write` 로 지킵니다. 그런데 **에이전트 계획을 승인할 때는 `range.write` 하나만 보았습니다.**

`ai.use` 와 `range.write` 만 가진 키가 에이전트를 거치면 직접은 만들지 못하는 것을 만들 수 있었습니다. 이제 물건마다 제 scope 를 요구합니다.

보고서 시트도 마찬가지였습니다. **안에 차트를 품고 있어도** `range.write` 만 보았습니다. 차트를 품고 있으면 `chart.write` 를 함께 요구합니다 — 차트 없는 보고서에는 요구하지 않습니다.

넣기만 해서는 안 되는 자리가 하나 더 있었습니다. 정렬 목록에 없는 scope 는 **조용히 사라집니다.** 목록을 함께 늘리고, 그래도 빠지는 것이 있으면 사라지는 대신 뒤에 붙게 했습니다. 검사에서 빠진 scope 는 없는 것과 같고, 그것이 가장 나쁜 실패입니다.

## 검증 결과

- 계획부터 승인, 실제 합계(영업 150, 개발 70), 되돌리기까지 PostgreSQL 로 돌립니다. 원본 여덟 칸이 그대로인 것도 봅니다.
- 입력 규칙은 실제로 "보류" 가 거부되는지 보고, 되돌린 뒤에는 같은 값이 들어가는지 봅니다. 규칙만 사라지고 막힘이 남으면 되돌렸다는 말과 화면이 어긋납니다.
- 종류마다 무엇이 없으면 막히는지 표로 확인합니다 — 고를 값, 출처 범위, 견줄 값, `=` 로 시작하는 수식.
- 도구와 직접 경로가 같은 scope 를 요구하는지 짝지어 확인합니다. 고치기 전 코드에서는 조건부 서식과 피벗이 `range.write` 만 요구해 실패합니다.
- 계획 쪽 허용 목록을 빼면 `unsupported workbook tool` 로 막히는 것까지 확인했습니다.
- Go 시험 전체, 통합 시험 전체와 웹 시험 380개가 통과합니다.
