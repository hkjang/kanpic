## 릴리즈 요약

v0.99.0은 **다른 스프레드시트에서 붙여넣을 때 잃던 것들**을 고칩니다. 엑셀에서 통화 열을 복사해 붙여넣고 합계를 내 보다 찾았습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 합계가 0이 되는 붙여넣기

엑셀에서 서식이 붙은 범위를 복사하면 클립보드에는 평문과 HTML 표가 함께 올라갑니다. kanpic은 **평문만 읽었습니다.** 평문에는 보이던 글자만 담기므로 `₩1,234.50` 이 그대로 글자로 저장되었고, 그 열의 합계는 0이었습니다. 굵게·배경색·정렬도 전부 사라졌습니다.

이제 HTML 쪽을 함께 읽습니다. 엑셀은 `x:num`, 구글 시트는 `data-sheets-value` 로 셀이 실제로 담고 있던 값을 알려 주므로 `₩1,234.50` 은 1234.5로, `12.5%` 는 0.125로 들어옵니다. 굵게·기울임·밑줄·글자색·배경색·가로 세로 정렬·줄바꿈·글꼴 크기가 함께 따라옵니다. 여러 칸을 차지하는 셀 뒤로 다음 셀이 밀리던 것도 자리를 맞춥니다.

## HTML이 없을 때도 숫자는 숫자로

메모장이나 터미널에서 붙여넣을 때는 HTML이 없습니다. 이때도 보이던 글자를 숫자로 읽습니다. `1,234`, `98,000원`, `(1,234)` 는 숫자로 들어오고 보이던 모습은 표시 형식으로 남아 화면은 그대로입니다.

읽지 말아야 할 것은 읽지 않습니다. 쉼표가 세 자리씩 끊지 않는 `1,2` 는 소수점으로 쉼표를 쓰는 표기일 수 있으므로 글자로 둡니다. 전화번호와 날짜도 그대로입니다.

## CSP가 가리고 있던 것

처음 고쳤을 때 값은 들어오는데 서식만 계속 비어 있었습니다. 이 앱의 CSP에는 `style-src 'unsafe-inline'` 이 없고, 그러면 크롬은 style 속성을 CSSOM에 넣지 않습니다. `element.style` 로 읽던 값이 전부 빈 문자열이었습니다.

CSP는 그대로 두는 것이 맞으므로 style 속성 문자열을 직접 해석하도록 바꿨습니다. 여기서는 스타일을 적용하는 것이 아니라 읽기만 하므로 문제가 없습니다.

**단위 테스트로는 이것을 잡을 수 없습니다.** jsdom에는 CSP가 없어 `element.style` 이 잘 동작하는 것처럼 보입니다. 그래서 붙여넣기 시나리오는 실제 브라우저에서 도는 E2E로 남겼고, 테스트 파일에도 그 이유를 적어 두었습니다.

## 검증 결과

- 브라우저 E2E 두 가지를 남겼습니다. 엑셀 모양 클립보드에서 숫자와 서식이 살아남고 붙여넣은 열의 `=SUM` 이 99,234.5를 내는지, 구글 시트 모양 클립보드에서 선언된 값이 쓰이고 `colspan` 뒤 칸이 밀리지 않는지 확인합니다.
- 고치기 전 번들에서 두 가지가 모두 실패하는 것을 확인했습니다.
- 단위 테스트로 표의 짜임새와 숫자 해석을 확인합니다. 특히 `1,2`, `12,34`, `010-1234-5678`, `2026-08-23` 을 숫자로 읽지 않는지 봅니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest 274개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
