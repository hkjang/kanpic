## 릴리즈 요약

v0.107.0은 **종이보다 넓은 표를 인쇄할 때 통째로 눌러 담던 것**을 고칩니다. 지난 릴리즈에서 화면의 눌러 담기를 고쳤는데, 종이에도 같은 문제가 있었습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 열 서른 개를 종이 한 장에

인쇄 문서의 표에 `width:100%` 가 걸려 있었습니다. 열이 몇 개든 종이 한 장 폭에 맞춰 넣는다는 뜻입니다. 열이 서른 개면 한 열이 몇 밀리미터로 찌그러져 글자를 알아볼 수 없습니다.

이제 들어가는 만큼 찍고 나머지는 **다음 장으로 넘깁니다.** 열은 화면에서 정한 너비 그대로 나가고, 장마다 열 머리글과 행 번호를 다시 찍어 어느 장을 봐도 어느 칸인지 알 수 있습니다. 엑셀이 오래 해 온 방식입니다.

한 장에 몇 열이 들어가는지는 A4 세로에 좌우 14mm 여백(210 − 28 = 182mm, 96dpi 에서 약 688px)을 기준으로 셉니다. 브라우저가 실제로 어떤 용지를 쓸지는 알 수 없으므로 가장 흔한 설정을 기준으로 삼았고, 어긋나더라도 다음 장으로 넘어갈 뿐 잘리지는 않습니다.

한 열이 종이보다 넓어도 혼자서 한 장을 차지합니다. 그렇지 않으면 어느 장에도 들어가지 못합니다.

## 달라지는 점

열이 몇 개 없는 좁은 표는 이제 종이 폭까지 늘어나지 않고 **제 너비로** 찍힙니다. 화면에서 정한 너비를 종이에서도 지키는 쪽이 맞고, 옆으로 넘기는 계산도 그래야 성립합니다.

## 검증 결과

- 단위 테스트 6가지로 한 장에 들어가는 열을 묶는지, 넘치는 열을 다음 장으로 넘기면서 빠뜨리거나 겹치지 않는지, 종이보다 넓은 열에 한 장을 주는지, 열 너비에 따라 장 수가 달라지는지, 그리고 다 들어가면 표가 하나로 남는지 확인합니다.
- 브라우저 E2E로 열 14개짜리 표를 실제로 인쇄해 표가 여러 개로 나뉘고 장마다 머리글과 행 번호가 있으며 열이 하나도 빠지지 않는지 봅니다. 고치기 전 번들에서 표가 하나뿐이라 실패하는 것을 확인했습니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
