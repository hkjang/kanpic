## 릴리즈 요약

v0.193.0은 **시트 메뉴가 열려 있는 동안에도 살아 있게** 합니다. CI가 빨개져서 찾은 것입니다.

## 메뉴가 죽은 채로 남았습니다

메뉴를 열 때 항목을 통째로 만들어 상태에 넣어 두었습니다. 각 줄을 쓸 수 있는지도 그때 굳습니다.

```js
const [menu,setMenu]=useState<{…;items:MenuItem[];…}>()
setMenu({…,items:sheetMenuItems(sheet),…})
```

시트 작업이 도는 동안 메뉴를 열면 모든 줄이 잠깁니다. **여기까지는 맞습니다** — 저장 중에 또 건드리면 안 됩니다. 그런데 작업이 끝나도 **잠긴 채로 남습니다.** 항목이 굳어 있어 `pending` 이 풀린 것을 모릅니다.

사람은 죽은 메뉴를 보고, 닫았다 다시 열면 살아난다는 것을 스스로 알아내야 합니다. 왜 그런지는 아무 데도 적혀 있지 않습니다.

## CI가 이것 때문에 빨개졌습니다

탭 색을 바꾼 뒤 서버에 색이 적힌 것을 보고 바로 메뉴를 열어 **왼쪽으로 이동** 을 누르는 시험입니다. 느린 기계에서는 아직 작업이 돌고 있었고, 30초를 기다리다 깨졌습니다.

**시험이 조급했던 것이 아니라 메뉴가 살아나지 않았던 것입니다.** 시험을 느슨하게 고쳤다면 진짜 문제는 그대로 남았을 것입니다.

## 무엇을 담을지와, 쓸 수 있는지를 나눕니다

무엇을 담을지는 열 때 정하고, 각 줄을 쓸 수 있는지는 **그릴 때** 정합니다.

자리 번호도 그릴 때 다시 봅니다. 열 때의 시트를 그대로 들고 있으면 옆 시트가 움직인 뒤에도 옛 자리로 **왼쪽으로 이동** 을 판단합니다. 아이디로 지금 목록에서 찾습니다.

## 검증 결과

- 작업이 도는 동안 잠기고, 끝나면 **열어 둔 채로** 다시 쓸 수 있는지 시험합니다.
- 옆 시트가 움직이면 판단이 따라 바뀌는지 시험합니다.
- 고치는 코드를 빼면 둘 다 깨지는 것을 확인하고 넣었습니다.
- 웹 시험 451개와 Go 시험 전체가 통과하고, 깨졌던 브라우저 시험을 두 번씩 돌려 확인했습니다.
