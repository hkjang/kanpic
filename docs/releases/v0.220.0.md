# v0.220.0

## 같은 글자가 들어오는 길에 따라 다른 값이 되고 있었다

`₩5,000` 같은 글자가 이 앱에 들어오는 길은 셋입니다.

1. 다른 스프레드시트에서 **붙여넣기**
2. 이미 글자로 들어와 있는 것을 **데이터 정리**로 고치기
3. 셀에 **직접 치기**

셋이 각자 글자를 뜯고 있었습니다. 전수로 대 보니 **여덟 가지**가 어긋나 있었습니다.

| 글자 | 붙여넣기 | 데이터 정리 |
|---|---|---|
| `5000 USD` | 글자로 둔다 | 숫자 5000 |
| `1,234달러` | 글자로 둔다 | 숫자 1234 |
| `5000KRW` | 글자로 둔다 | 숫자 5000 |
| `1234 won` | 글자로 둔다 | 숫자 1234 |
| `¢50` | 숫자 50 | 글자로 둔다 |
| `$-5` | 글자로 둔다 | 숫자 -5 |
| `5%원` | 숫자 0.05 | 글자로 둔다 |
| `₩1,234.50원` | 글자로 둔다 | 숫자 1234.5 |

같은 자료가 **어떻게 들어왔는지에 따라** 합계에 들어가기도 하고 빠지기도 했습니다.
`5000 USD` 열을 붙여넣으면 `=SUM` 이 0을 내지만, 같은 열을 데이터 정리로
고치면 제대로 더해집니다. 사람에게는 같은 표입니다.

## 뜯는 일을 한 군데로 모았다

여덟 가지를 하나씩 맞추는 대신, **뜯는 일 자체를 한 군데로 모았습니다.**
`decomposeNumberText` 하나가 글자를 값과 표시 형식으로 뜯고, 세 길이 모두
그것을 부릅니다.

이제 어긋날 자리가 없습니다. 규칙이 하나뿐이기 때문입니다.

어긋난 것을 고를 때는 **사람이 보던 것을 바꾸지 않는 쪽**을 골랐습니다.
`5%원` 처럼 뜻이 없는 글자는 양쪽 모두 놓아주고, `¢50` 이나 `$-5` 처럼
분명한 것은 양쪽 모두 읽습니다.

## 기호에 붙어 있던 빈칸이 사라지고 있었다

`5000 USD` 를 숫자로 바꾸면 `5000USD` 로 되돌아왔습니다. 표시 형식을 만들 때
단위 앞의 빈칸을 떼어 버렸기 때문입니다. `₩ 5,000` 도 `₩5,000` 이 되었습니다.

값은 맞지만 사람은 자기가 옮긴 표와 다른 것을 봅니다. 이제 빈칸까지 서식
안에 담아, 숫자로 바꾼 뒤에도 **글자 하나까지 그대로** 그려집니다.
