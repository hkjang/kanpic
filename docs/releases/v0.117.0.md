## 릴리즈 요약

v0.117.0은 프레젠테이션을 **에이전트 도구** 로 엽니다. 지금까지는 사람이 대화 상자에서 눌러야 했고, 이제 MCP 도구 다섯 개로 같은 일을 할 수 있습니다.

마이그레이션은 없습니다. 기능은 여전히 관리자가 켜야 합니다.

## 정해진 일은 REST, 판단이 필요한 일은 에이전트

| 도구 | 하는 일 | scope |
| :--- | :--- | :--- |
| `spreadsheet.presentation.preview` | 만들지 않고 어떤 슬라이드가 될지 돌려줍니다 | `presentation.read` |
| `spreadsheet.presentation.create` | 범위로 덱을 만듭니다 | `presentation.write` |
| `spreadsheet.presentation.list` | 워크북의 덱과 원본 변경 여부를 조회합니다 | `presentation.read` |
| `spreadsheet.presentation.refresh` | 같은 덱을 지금 값으로 다시 만듭니다 | `presentation.write` |
| `spreadsheet.presentation.template.list` | 디자인 목록 | `presentation.read` |

**미리보기가 있는 이유** 는 에이전트가 먼저 보고 정하게 하기 위해서입니다. 범위를 무엇으로 읽었는지(항목별 비교인지 추이인지 진행 순서인지), 어느 열이 증감이고 어느 열이 달성률인지, 슬라이드가 몇 장이 될지를 만들기 전에 돌려줍니다. 만들어 놓고 마음에 안 들면 지우는 것보다 낫고, 고르는 동안 공용 계정에 덱이 쌓이지도 않습니다.

**PPTX 내려받기는 MCP에 넣지 않았습니다.** 파일을 주고받는 일은 REST가 맞습니다.

## 에이전트도 같은 문을 지난다

MCP 도구가 REST와 다른 권한 규칙을 쓰면, 도구 하나가 공유 규칙 전체를 우회하는 길이 됩니다.

kanpic의 MCP 계층은 도구 인자 이름을 리소스 종류에 대응시켜 권한을 검사합니다. `presentation_id` 를 그 표에 넣어, 새 도구들이 REST와 **같은** 검사를 지나게 했습니다. 덱을 만드는 것은 워크북 읽기, 다시 만드는 것은 편집이고, kanpic이 만들지 않은 덱은 프레젠테이션 서비스에 닿기 전에 막힙니다.

확인한 것: 권한 없는 사용자는 만들기·미리보기·다시 만들기 셋 다 거절당하고, 모르는 덱 번호는 거절당하며, `presentation.read` 만 가진 API 키는 미리보기는 되고 만들기는 `insufficient scope` 로 막힙니다.

## 검증 결과

- 도구 네 개를 차례로 불러 미리보기 → 만들기 → 조회 → 다시 만들기가 이어지는지 봅니다.
- 미리보기가 프레젠테이션 서비스를 부르지 않는지 확인합니다.
- 권한 없는 사용자가 세 도구 모두에서 막히는지, kanpic이 모르는 덱이 막히는지 봅니다.
- 실제로 도는 Ptium을 상대로 다섯 도구를 모두 호출하고, scope를 좁힌 API 키로 만들기가 막히는 것까지 확인했습니다.
