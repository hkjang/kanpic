## 릴리즈 요약

v0.50.0은 조건부 서식에 **맞춤 수식 규칙**을 더합니다. 지금까지는 값 비교·중복·색상 범위·데이터 막대만 있었고, 구글 시트에서 조건부 서식을 실제로 쓰게 만드는 형태 — 다른 열의 값으로 행 전체를 칠하는 규칙 — 이 빠져 있었습니다.

마이그레이션 `027_conditional_custom_formula.sql`이 추가됩니다. `conditional_formats` 테이블에 `formula` 열을 더하고 유형 제약에 `custom_formula` 를 허용합니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 새로운 기능

- **맞춤 수식**: 규칙 범위의 **첫 셀 기준**으로 조건식을 쓰면 나머지 셀에서는 상대 참조가 함께 움직입니다. `A2:D100` 범위에 `=$C2="완료"` 를 넣으면 C열이 완료인 행 전체가 칠해집니다. 열 고정은 `$C2`, 행까지 고정은 `$C$2` 입니다.
- 규칙이 덮지 않는 열도 참조할 수 있습니다. 서버는 수식이 도달할 수 있는 범위까지 셀을 읽어 평가하므로, 규칙 범위 밖의 상태 열을 근거로 삼아도 빈 값으로 보이지 않습니다.
- 수식이 참(TRUE 또는 0이 아닌 숫자)일 때만 서식이 적용되고, 계산 오류가 나면 그 셀에는 적용되지 않습니다. **조건이 참이면 중지** 옵션도 값 조건 규칙과 같게 동작합니다.
- 저장 시 수식은 서버에서 파싱까지 확인합니다. `=` 로 시작하지 않거나 문법이 깨진 수식은 저장되지 않고, 규칙 유형을 다른 것으로 바꾸면 저장돼 있던 수식이 함께 정리됩니다.

REST와 MCP는 `rule_type:"custom_formula"` 와 `formula` 필드를 사용합니다. 길이 제한은 데이터 검증의 맞춤 수식과 같은 2,000자입니다.

## 검증 결과

- `go vet ./...`와 `go test ./...`를 통과했습니다. 새 테스트는 규칙 범위 밖 C열의 값으로 A·B열이 칠해지는지, 잘못된 수식이 거부되는지, 유형 전환 시 수식이 남지 않는지 확인합니다.
- React/Vitest 39개 테스트 파일, 209개 테스트를 통과했습니다.
- TypeScript 타입 검사와 Vite 프로덕션 빌드를 통과했습니다.
- Playwright E2E 113건을 통과했습니다. 새 테스트는 대화상자에서 맞춤 수식 규칙을 만들고, 저장된 정의와 서버 평가 결과가 같은 셀을 가리키는지 확인합니다.
- 실제 브라우저에서 업무 목록에 완료(초록)·지연(빨강) 두 규칙을 올려 행 전체가 상태 열에 따라 칠해지는 것을 눈으로 확인했습니다.
