## 릴리즈 요약

v0.137.0은 **AI 도우미가 범위를 정렬할 수 있게** 합니다. "AI 도우미 고도화" 로 시작한 다섯 개 도구가 이것으로 마무리됩니다.

## 하나만 성격이 다릅니다

지난 세 번에 걸쳐 붙인 도구들 — 피벗, 조건부 서식, 입력 규칙, 필터 보기 — 는 모두 **물건을 하나 더 얹을 뿐** 이었습니다. 원본은 한 칸도 건드리지 않으므로 되돌리기가 그 물건을 지우는 것으로 끝났습니다.

정렬은 **있던 자료를 다시 씁니다.** 그래서 다르게 만들었습니다.

```
"매출 많은 순으로 정렬해줘"
"부서별로 묶고 그 안에서 금액 큰 순으로"
```

## 셀 변경 목록으로 풀지 않았습니다

모델이 셀을 하나씩 적어 보내게 하면 두 가지가 깨집니다. 500줄짜리 표를 정렬하면 **승인 화면에 500칸짜리 diff** 가 뜨고, 사람은 그것을 읽을 수 없습니다. 그리고 수식과 서식이 줄을 따라 움직이는 규칙을 모델이 다시 구현하게 됩니다.

도구가 정렬 결과를 한 번에 만들어 **하나의 작업** 으로 적용합니다. 승인 화면에는 무엇을 어떻게 세우는지가 한 줄로 적힙니다.

```
범위 정렬하기                        높은 위험
A1:B10 · B열 내림차순 · 머리글 1줄
```

수식은 줄을 따라 옮겨지고, 수식 셀은 **계산된 값** 으로 줄을 섭니다. 배열 수식이 퍼진 칸이나 병합된 칸이 범위 안에 있으면 정렬하지 않고 그대로 알립니다.

## 되돌리기도 다릅니다

지울 물건이 없으므로 **작업 자체를 되돌립니다.** 순서와 수식이 함께 제자리로 옵니다.

## 위험도를 높게 잡았습니다

보이는 것만 바꾸면 되는 요청이라면 정렬보다 필터 보기가 맞습니다. 모델에게도 그렇게 일러 두었습니다 — 자료를 다시 쓰는 것은 마지막 선택지입니다.

## 검증 결과

- 수식 셀(`=70+30`)이 계산된 값 100 으로 줄을 서고, 수식이 줄을 따라 옮겨졌다가 되돌리면 순서와 수식이 함께 돌아오는지 PostgreSQL 로 돌립니다.
- 범위 밖 기준 열, 한 열에 기준 둘, 모르는 방향, 기준 없음, 머리글이 범위 전체, 세울 줄이 하나뿐인 경우를 모두 계획 단계에서 막습니다.
- Go 시험 전체, 통합 시험 전체와 웹 시험 382개가 통과합니다.
