## 릴리즈 요약

v0.101.0은 **날짜끼리 빼고 날짜에 며칠을 더하는 계산**을 되살립니다. 어떤 스프레드시트에서든 가장 흔한 날짜 계산인데 둘 다 `#VALUE!` 였습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 며칠 남았는지 물을 수 없었다

`=마감일-오늘` 과 `=오늘+7`. 이 두 가지가 되지 않았습니다.

kanpic은 날짜를 엑셀처럼 직렬 번호로 바꾸지 않고 `2026-08-23` 이라고 쓰인 그대로 담습니다. 저장과 읽기에는 이쪽이 낫지만, 더하기와 빼기 연산자가 그것을 숫자로 바꾸지 못해 `#VALUE!` 를 냈습니다. 날짜 **함수** 는 멀쩡했습니다 — `DATEDIF`, `DAYS`, `NETWORKDAYS`, `EDATE`, `EOMONTH`, `WEEKDAY`, `TEXT` 모두 잘 돌고, 비교와 `MIN`·`MAX` 도 됩니다. 그래서 며칠 떨어졌는지 알려면 `=DATEDIF(A1,A2,"d")` 를 알고 있어야 했습니다.

이제 연산자가 날짜를 압니다.

- **날짜 − 날짜 = 며칠** — `=A2-A1` 이 9를 냅니다.
- **날짜 ± 숫자 = 날짜** — `=A1+7` 이 `2026-08-30`, `=A1-1` 이 `2026-08-22` 입니다. `=7+A1` 도 같습니다.
- `2026/08/23` 처럼 다른 모양으로 쓴 날짜는 **그 모양 그대로** 돌아오고, `2026-08-23 09:30:00` 처럼 시각이 붙은 값은 시각을 지킨 채 움직입니다.

## 뜻이 없는 것은 오류로 둔다

날짜 둘을 더하는 것(`=A1+A2`)은 직렬 번호가 없는 이상 뜻이 없습니다. 엑셀은 큰 숫자를 내놓지만 kanpic은 `#VALUE!` 로 알려 줍니다. 숫자에서 날짜를 빼는 것(`=7-A1`)과 날짜에 곱하기(`=A1*2`)도 마찬가지입니다.

기간이 담을 수 있는 범위(약 292년)를 넘는 이동은 조용히 다른 세기로 넘어가지 않고 `#NUM!` 을 냅니다.

## 확인만 하고 지나간 것

`=SUM(날짜 범위)` 는 0을 냅니다. 날짜를 더한 합계는 뜻이 없으므로 그대로 두었습니다. 기간을 세려면 위의 뺄셈이나 `DATEDIF` 를 씁니다.

표시 형식을 사용자가 직접 쓸 수 있는지도 함께 확인했습니다. **서식 › 표시 형식** 에 이미 `사용자 지정` 이 있어 `#,##0"원"` 같은 형식을 직접 넣을 수 있습니다.

## 검증 결과

- 단위 테스트로 날짜 뺄셈·더하기, 달과 해를 넘어가는 이동, 시각 보존, 쓰인 모양 유지, 그리고 뜻이 없는 다섯 가지가 오류로 남는지 확인합니다. 고치기 전 엔진에서 `=A2-A1` 이 `#VALUE!` 로 실패하는 것을 확인했습니다.
- 브라우저 E2E로 실제 격자에 `=A2-A1` 과 `=A1+7` 을 입력해 9와 `2026-08-30` 이 저장되는지 봅니다. 고치기 전 서버에서 실패합니다.
- `go vet ./...`, `go test ./...`, PostgreSQL 통합 테스트, React/Vitest 278개 테스트, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E를 통과했습니다.
