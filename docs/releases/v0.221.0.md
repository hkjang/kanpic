# v0.221.0

## 내보낸 CSV 의 `NaN` 한 칸이 열 전체의 합계를 없앴다

pandas 나 R 로 만든 CSV 에는 빠진 값이 **`NaN`** 이라는 글자로 들어 있습니다.
`Inf`, `-Inf` 도 흔합니다. 그런 표를 kanpic 에 가져오면 이렇게 됐습니다.

```
A1  1200
A2  NaN      ← 내보내기가 남긴 빈 값
A3  800
A4  500

=SUM(A1:A4)  →  #NUM!
```

합계가 **틀린 것이 아니라 아예 없어졌습니다.** 한 칸 때문에 열 전체가
`#NUM!` 이 됩니다. 어느 칸이 그랬는지는 아무 데도 적히지 않습니다.

원인은 엔진이 글자를 숫자로 바꿀 때 Go 의 `ParseFloat` 를 그대로 쓴 것입니다.
그것은 스프레드시트보다 넓습니다.

| 글자 | 예전 엔진 | 스프레드시트 |
|---|---|---|
| `NaN` | NaN 으로 셈 → `#NUM!` | 세지 않음 |
| `Inf` `Infinity` | 무한대로 셈 → `#NUM!` | 세지 않음 |
| `0x1p4` | 16 (Go 의 16진 실수) | 세지 않음 |
| `1_000` | 1000 (Go 의 밑줄 구분자) | 세지 않음 |

Go 의 리터럴 문법이지 스프레드시트의 값이 아닙니다. 이제 세지 않습니다.
`NaN` 이 있어도 나머지가 제대로 더해집니다.

## 상태 줄 합계와 `=SUM` 이 어긋나 있었다

반대쪽도 넓었습니다. 격자는 자바스크립트의 `Number()` 로 셌는데, 그것은
**`0x1F` 를 31 로, `0b101` 을 5 로** 읽습니다. 엔진은 세지 않습니다.

그래서 그런 칸이 있는 범위를 잡으면 **상태 줄에는 더해지고 `=SUM` 에서는
빠졌습니다.** 두 숫자가 다른데 어느 쪽이 맞는지 알 길이 없었습니다.
`0x1F` 같은 값은 계측 자료나 장비 로그에서 흔합니다.
