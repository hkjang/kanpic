## 릴리즈 요약

v0.59.0은 **릴리즈 절차가 조용히 어긋나지 않도록** 검사를 붙입니다. 직전 릴리즈에서 문서 편집이 실패했는데도 커밋과 태그가 그대로 진행되어, `v0.58.0` 태그의 README에는 `VERSION=v0.57.0` 이 적혔습니다. 사람이 알아채기 전까지 아무것도 막지 않았습니다.

제품 동작 변경은 없습니다. 마이그레이션도 없습니다.

## 바뀐 곳

**`scripts/release-preflight.sh` (신규)** — `github-release.sh` 가 이미지 빌드 전에 먼저 실행합니다. 게시된 태그는 조용히 고칠 수 없으므로, 싸게 확인할 수 있는 것은 전부 빌드 전에 확인합니다.

- 릴리즈 노트(`docs/releases/vX.Y.Z.md`)가 있는지
- README의 `VERSION=` 이 릴리즈 버전과 같은지
- 커밋되지 않은 변경이 없는지 (아티팩트가 커밋과 달라집니다)
- 같은 태그가 이미 있는지
- push 되지 않은 커밋이 없는지 (태그가 남의 저장소에 없는 커밋을 가리키게 됩니다)

문제를 하나 발견하면 멈추지 않고 **전부 모아서** 보여 줍니다. 릴리즈를 준비하다 한 번에 고치는 편이 낫기 때문입니다.

**`scripts/check-release-docs.sh` (신규)** — README의 `VERSION=` 과 가장 최신 릴리즈 노트가 일치하는지 확인하며, CI에서 매 커밋 실행됩니다. 릴리즈 시점이 아니라 **PR 시점에** 어긋남을 잡습니다.

## 검증 결과

- 두 스크립트를 양방향으로 확인했습니다. 정상 상태에서 통과하고, README 버전을 일부러 되돌리자 `README.md의 VERSION(v0.57.0)과 최신 릴리즈 노트(v0.58.0)가 다릅니다` 로 실패했습니다. 통과만 확인했다면 값어치를 알 수 없었을 것입니다.
- preflight는 릴리즈 노트 누락·버전 불일치·미커밋 변경 세 가지를 한 번에 보고했습니다.
- `go vet ./...`와 `go test ./...`, React/Vitest 219건, TypeScript 타입 검사, Vite 프로덕션 빌드, Playwright E2E 120건을 통과했습니다.
