## 릴리즈 요약

v0.126.1은 **인수가 둘 이상인 함수도 배열을 칸마다 짝지어 셈하도록** 합니다. 글자를 다루는 함수가 특히 아쉬웠던 자리입니다.

## 남은 절반

v0.126.0에서 값 하나짜리 함수를 폈습니다. 인수가 둘 이상인 쪽에는 같은 자리가 그대로 남아 있었습니다.

```
=SUMPRODUCT(LEN(LEFT({"abc";"de"},2)))     #VALUE!
=SUMPRODUCT(MOD({5;7},{3;3}))              #VALUE!
=INDEX(SUBSTITUTE({"aa";"bb"},"a","c"),1)  #VALUE!
```

## 어떤 글이 든 칸을 세기

가장 아쉬웠던 것은 이 꼴입니다.

```
=SUMPRODUCT(--ISNUMBER(FIND("서울",A1:A100)))
```

`FIND`가 배열을 받지 못하면 통째로 막힙니다. `COUNTIF`의 와일드카드로 비슷하게 흉내낼 수는 있지만, **대소문자를 가려 찾거나 몇 번째 글자부터 찾는 것** 은 흉내낼 수 없습니다.

이제 됩니다.

```
LEFT RIGHT MID REPLACE REPT SUBSTITUTE FIND SEARCH EXACT MOD POWER
```

## 이어 붙이는 함수는 다르다

`CONCAT`과 `CONCATENATE`와 `TEXTJOIN`은 넣지 않았습니다. **여러 값을 하나로 잇는 것** 이 하는 일이라, 배열을 받으면 칸마다 나누는 것이 아니라 모두 이어 붙여야 합니다.

```
=CONCAT({"a";"b"},"!")   →  "ab!"
```

이것을 `"a!"`로 잘못 알고 고칠 뻔했습니다. 실제로 돌려 보고서야 이미 맞는 답이라는 것을 알았습니다.

## 검증 결과

- 고치기 전 코드에서 걸립니다.
- 실제 서버에서 열여섯 가지를 확인했습니다. 홑값 셈(`=MOD(5,3)`, `=LEFT("abc",2)`)은 그대로입니다.
- 앞 판에서 더한 되부르기를 그대로 쓰므로 셈하는 자리는 늘지 않았습니다.
- 만 칸짜리 배열에 `ISNUMBER`를 걸면 5.4ms입니다. 같은 크기 `SUM`이 3.9ms이므로 칸당 0.15µs 남짓 더 듭니다.
- Go 시험 전체와 웹 시험 376개가 통과합니다.
