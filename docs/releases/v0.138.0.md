## 릴리즈 요약

v0.138.0은 **말로 시킨 일이 그 일을 하는 도구에 닿게** 합니다. 네 번의 릴리즈로 만든 다섯 도구가 지금까지는 거의 닿지 않았습니다.

## 만들어 놓고 닿지 않았습니다

v0.134.0부터 v0.137.0까지 피벗·조건부 서식·입력 규칙·필터 보기·정렬을 더했습니다. 그런데 사람이 그 일을 말로 시키면 어디로 가는지 실제로 재 보니 이랬습니다.

```
부서별 매출 합계를 요약해줘   ->  formula    ("합계" 라는 말 때문에)
매출 100 이상만 보이게 해줘   ->  summarize
매출 많은 순으로 정렬해줘     ->  format     ("정렬" 이라는 말 때문에)
상태 열은 진행/완료만 고르게   ->  summarize
매출 상위 10%에 색 칠해줘    ->  summarize
```

`summarize` 는 **읽기 전용** 이라 도구를 아예 쓸 수 없습니다. 도구에 닿는 길은 "피벗" 이라는 단어를 직접 말하거나 `/pivot` 을 외우는 것뿐이었습니다.

## 이제 말한 대로 알아듣습니다

```
"부서별 매출 합계를 요약해줘"   ->  피벗
"제품별 판매 건수를 집계해줘"   ->  피벗
"매출 100 이상만 보이게 해줘"   ->  필터 보기
"완료된 항목은 빼고 보여줘"     ->  필터 보기
"매출 많은 순으로 정렬해줘"     ->  정렬
"최신순으로 줄 세워줘"         ->  정렬
"음수는 못 넣게 해줘"          ->  입력 규칙
"목표 미달이면 빨갛게 표시해줘"  ->  조건부 서식
```

## "정렬" 은 두 가지 뜻입니다

한국어에서 정렬은 **줄 세우기** 이면서 **맞춤** 입니다. "매출 많은 순으로 정렬" 은 자료를 다시 쓰는 일이고, "가운데 정렬" 은 서식입니다. 가르지 못하면 서식 요청이 자료를 다시 쓰는 쪽으로 새거나 그 반대가 됩니다.

가르는 목록을 한 곳에 두고, 줄 세우기에서 빼는 곳과 서식으로 보내는 곳이 **같은 것** 을 봅니다. 나누어 적으면 한쪽만 늘어나고 그때 다시 샙니다.

"특별", "개별" 처럼 `별` 이 접미사가 아닌 말은 분류로 보지 않습니다. "성별 인원수" 는 분류로 봅니다.

## 검증 결과

- 열여섯 가지 요청이 제 도구에 닿는지 확인합니다.
- 열두 가지 기존 요청 — 서식·분석·수식·차트·정제·이상치·설명·되돌리기 — 이 그대로인지 함께 확인합니다. 넓히면서 멀쩡하던 길을 끊는 것이 이 변경에서 가장 위험한 일입니다.
