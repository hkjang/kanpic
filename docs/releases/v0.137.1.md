## 릴리즈 요약

v0.137.1은 **한 계획에서 도구 하나가 실패했을 때 앞서 끝난 작업이 남던 문제** 를 고칩니다.

## 절반만 끝난 실행

Workbook Agent 계획에는 도구가 여러 개 들어갈 수 있습니다. "매출 순으로 세우고 상태 열에 체크박스를 넣어줘" 같은 요청이 그렇습니다.

뒤엣것이 실패하면 앞서 성공한 것이 **그대로 남았습니다.** 차트가 남는 것도 곤란하지만, v0.137.0에서 더한 정렬은 훨씬 나쁩니다 — **있던 자료가 다시 쓰인 채로 남습니다.**

그리고 실패한 실행에는 **되돌리기 단추가 없습니다.** 되돌리기는 적용에 성공한 작업에만 있습니다. 그래서 사람이 손으로 순서를 되돌려야 했습니다.

## 되돌리기와 같은 자리를 씁니다

이제 도중에 실패하면 앞서 끝난 도구를 **거꾸로 되돌린 뒤** 실패로 끝냅니다. 만든 물건은 지우고, 다시 쓴 자료는 제자리로 돌립니다.

되돌리기가 쓰던 자리를 따로 꺼내 부분 실패 보상도 **같은 것** 을 쓰게 했습니다. 두 곳에 나누어 적으면 한쪽만 고치게 되고, 그때 다시 어긋납니다.

되돌린 도구는 **완료가 아니라 취소** 로 표시합니다. 화면에는 완료라고 적혀 있는데 실제로는 없는 상태가 더 나쁩니다. 보상까지 실패하면 원래 실패를 가리지 않고 둘 다 알립니다.

## 검증 결과

- 정렬과 피벗이 끝난 뒤 세 번째 도구가 저장소에 거부당하는 계획을 PostgreSQL 로 실제로 돌립니다. 순서가 원래대로 돌아오고, 피벗이 남지 않고, 완료로 남은 도구가 없는지 봅니다.
- 고치기 전 코드에서는 정렬이 남아 이 시험이 실패합니다.
- Go 시험 전체, 통합 시험 전체와 웹 시험 382개가 통과합니다.
