## 릴리즈 요약

v0.85.0은 **만 행 너머의 데이터를 화면에서 볼 수 있게 합니다.** 서버는 5만 행짜리 시트를 저장하고 내보내기에도 담아 주는데, 편집기는 10,000행에서 끊겨 있었습니다.

마이그레이션은 없습니다. 필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나입니다.

## 닿을 수 없던 행

오래 걸리는 작업의 진행 표시를 보려고 2만 행 시트에서 정렬을 눌렀다가 발견했습니다. 정렬 확인창이 `A1:C10000 범위를 정렬합니다 · 9,999행이 정렬됩니다` 라고 말했습니다. 시트에는 20,000행이 있었습니다.

확인해 보니 편집기 자체의 한도였습니다. 이름 상자에 `A20000` 을 넣으면 **`A10000` 으로 잘렸습니다.** 그 아래 만 행은 서버에 그대로 있고 CSV·XLSX 내보내기에도 들어가지만, 화면에서는 존재하지 않는 것과 같았습니다.

한도를 **200,000행** 으로 올렸습니다. 이제 같은 시트에서 정렬 확인창이 `A1:C20000 · 19,999행` 이라고 말하고, `A150000` 으로 이동해 값을 입력할 수 있습니다.

## 왜 20만인가

격자는 전체 높이만큼의 스크롤 영역을 만듭니다. 200,000행 × 27px × 최대 확대 2배 ≈ 1,080만 px로, 브라우저가 요소 높이를 조용히 잘라 내기 시작하는 지점(파이어폭스 약 1,790만 px)보다 낮습니다.

엑셀과 같은 1,048,576행으로 두면 확대 상태에서 그 한계를 넘어 **스크롤 위치가 어긋납니다.** 보이지 않는 행보다 잘못된 자리를 가리키는 행이 더 나쁩니다. 격자의 좌표 계산 자체는 이분 탐색이라 행 수와 무관하므로, 한계는 순전히 브라우저의 스크롤 높이입니다.

## 함께 확인한 것

이 한도는 표 범위를 찾는 모든 기능이 공유합니다. 정렬뿐 아니라 중복 항목 삭제, 부분합, 텍스트 분할, 자동 합계가 같은 계산을 씁니다. 만 행 너머를 못 보던 것은 그 전부였습니다.

진행 표시 자체는 문제가 없었습니다. 2만 행 정렬은 화면에 결과를 먼저 보여 주고 시트 탭 옆에 `저장 중…` 을 띄운 뒤 1.5초 만에 `모든 변경사항 저장됨` 으로 바뀝니다.

## 검증 결과

- 실제 브라우저에서 `A20000` 이 `A10000` 으로 잘리는 것을 본 뒤 고쳤고, 고친 뒤 `A150000` 에 값을 입력해 서버에 저장되는 것까지 확인했습니다.
- E2E를 더했습니다. 12,000행 시트에서 `C12000` 으로 이동해 입력한 값이 서버에 남는지, 정렬이 표 전체(12,000행)를 대상으로 삼는지 확인합니다. 이전 번들에서는 `C10000` 에 멈춰 실패합니다.
- 열 전체 선택 라벨을 확인하던 기존 E2E가 `B1:B10000` 을 기대하고 있어 상수에서 읽도록 고쳤습니다.
