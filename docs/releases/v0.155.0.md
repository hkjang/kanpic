## 릴리즈 요약

v0.155.0은 v0.152.0이 빠뜨린 것을 채웁니다. 엑셀은 `LAMBDA` 의 매개변수를 파일 안에 **`_xlpm.` 을 붙여** 적는데, 내보낼 때 그것을 붙이지 않았고 가져올 때 떼지 않았습니다.

## 진짜 엑셀이 쓴 파일이 이상하게 들어오고 있었습니다

엑셀에서 만든 `LAMBDA` 이름을 가져오면 매개변수가 이렇게 들어왔습니다.

```
마진율(_xlpm.매출, _xlpm.원가)
```

사람이 지은 적 없는 이름입니다. `_xlfn.` 과 같은 까닭의 표시일 뿐, 화면에 보일 이름이 아닙니다.

선언하는 자리와 **본문에서 부르는 자리가 함께** 바뀌어야 짝이 맞습니다. 선언만 떼면 `매출` 을 받아 `_xlpm.매출` 을 부르는 수식이 되어 `#NAME?` 이 됩니다.

## 고치다 더 깊은 것이 나왔습니다

이름을 이루는 글자에 **한글이 빠져 있었습니다.**

```
isFunctionNameRune -> A-Z a-z 0-9 . _
```

함수 이름은 모두 영문이라 여태 드러나지 않았습니다. 그런데 `LAMBDA` 의 매개변수는 **사람이 짓는 이름** 이라 이 나라에서는 대개 한글입니다. `매출` 을 이름으로 읽지 못하니 본문에서 그 자리를 찾지 못했고, 붙이는 쪽도 떼는 쪽도 **반만** 되고 있었습니다.

```
전  _xlfn.LAMBDA(_xlpm.매출,_xlpm.원가,(매출-원가)/매출)      ← 짝이 어긋남
후  _xlfn.LAMBDA(_xlpm.매출,_xlpm.원가,(_xlpm.매출-_xlpm.원가)/_xlpm.매출)
```

작은따옴표 안은 건너뜁니다. 매개변수와 같은 이름의 시트가 있다고 그 자리를 바꾸면 **가리키는 곳이 달라집니다.**

훑기는 함수 이름 쪽과 한자리를 씁니다. 문자열을 건너뛰는 규칙을 두 번 적으면 한쪽만 고치게 됩니다.

## 정직하게 적어 둡니다

**엑셀 자체로는 확인하지 못했습니다.** 이 환경에 엑셀도 LibreOffice 도 없습니다. 다만 엑셀이 파일에 적는 꼴이 이것이므로, 맞추는 쪽이 안전합니다 — 엑셀이 `_xlpm.` 을 요구한다면 지금까지 내보낸 파일이 엑셀에서 깨지고 있었던 것이고, 요구하지 않는다면 이번 변경은 그저 엑셀과 같은 꼴로 적는 것입니다.

## 함께 넣은 시험

- **만들어 놓고 함수 목록에 적지 않은 함수** 를 잡는 시험. 목록에 적힌 413개가 다 동작하는지는 이미 보고 있었지만 반대는 보지 않았습니다. 목록에 없으면 자동완성에도 나오지 않아, 이름을 이미 아는 사람만 쓸 수 있는 함수가 됩니다. `ISFORMULA` 하나가 걸리는데 이것은 일부러 뺀 것이라 까닭과 함께 적어 두었습니다.
- **Postgres 가져오기의 이름 있는 수식.** 트랜잭션 안의 직접 `INSERT` 인데 아무 시험도 지나지 않고 있었습니다. 열 이름이 어긋났다면 `LAMBDA` 이름이 든 파일을 처음 여는 사람에게서 터졌을 것입니다.

## 검증 결과

- 진짜 엑셀이 쓴 꼴을 읽는 것, 시트 이름을 건드리지 않는 것, 한글·영문·함수와 겹치는 이름·문자열 안의 같은 글자를 확인합니다.
- 나갔다 들어오는 길 여섯 가지가 모두 제자리로 돌아옵니다.
- Go 시험 전체와 통합 시험 전체가 통과합니다.
