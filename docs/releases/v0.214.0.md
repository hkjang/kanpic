# v0.214.0

## 다른 워크북의 저장 결과를 이 워크북에 얹지 않는다

오프라인이거나 저장이 잠깐 막혔을 때, 편집은 브라우저 안의 저장 큐에 쌓였다가
연결이 돌아오면 서버로 나갑니다. 이 큐는 지금 어떤 워크북을 보고 있는지 모릅니다.
밀려 있는 작업이면 시트를 가리지 않고 전부 보냅니다. 그래야 잠깐 열었다 닫은
워크북의 편집도 잃지 않기 때문입니다.

문제는 받는 쪽이었습니다. 응답이 도착하면 그 작업이 **어느 시트의 것인지 보지 않고**
지금 열린 시트에 반영했습니다.

- A 워크북을 고치다 저장이 막힌 채 B 워크북을 엽니다.
- 3초마다 도는 큐 비우기가 A 의 작업을 보냅니다.
- A 의 서버 버전이 B 의 것으로 씌워지고, A 의 작업 번호가 **B 의 되돌리기 더미**에 쌓입니다.
- B 에서 Ctrl+Z 를 누르면 화면에 있지도 않은 A 의 셀이 되돌아갑니다.

보내는 일은 그대로 두었습니다. 다른 워크북의 편집도 계속 서버로 나갑니다.
좁힌 것은 화면에 반영하는 쪽입니다. **결과는 그 작업을 넣은 시트에만 닿습니다.**

워크북 버전은 이 변경과 무관하게 협업 연결이 계속 최신으로 맞춰 주므로,
지금 보는 워크북이 뒤처지는 일은 없습니다.

## 막힌 작업이 남의 워크북 것이면 여기를 막지 않는다

행과 열을 넣거나 지우기 전에는 밀린 저장이 없는지 확인합니다. 그런데 이 확인이
큐 전체를 셌습니다. 다른 워크북에서 영영 실패하는 작업 하나가 남아 있으면,
지금 워크북에서 행 하나 넣는 것까지 막혔습니다. 이제 **이 워크북의 시트만** 셉니다.
