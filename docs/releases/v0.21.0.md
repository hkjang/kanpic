## 릴리즈 요약

v0.21.0은 워크북과 시트를 실제로 운영하는 데 필요한 관리 기능을 채웁니다. **시트 관리 화면과 시트 숨기기·드래그 재배치·다른 워크북으로 복사**, **워크북 휴지통과 복원**, **사용자별 즐겨찾기**, 그리고 관리자 콘솔의 **사용자 및 역할 관리**를 추가했습니다.

v0.20.0에서 공유 체계를 도입하면서 드러난 결함도 함께 고쳤습니다. 특히 즐겨찾기는 워크북 전역 상태였기 때문에 공유받은 뷰어가 별표를 달 수 없었고, 별표를 달면 다른 사용자 목록에도 영향을 주었습니다.

필수 런타임 환경 변수는 계속 `POSTGRES_DSN` 하나이며 마이그레이션 `019_workbook_management.sql`과 `020_user_directory.sql`이 자동 적용됩니다.

## 시트 관리

- 탭 왼쪽의 목록 아이콘 또는 **파일 → 모든 시트 관리…** 로 시트 관리 창을 엽니다. 시트별 데이터 셀 수, 수식 수, 사용 범위(A1 표기), 마지막 변경 시각을 표로 확인하고 이동·숨기기·복사·삭제를 한 자리에서 실행합니다.
- 창 상단에 워크북 전체 시트 수, 데이터 셀 수, 수식 수를 요약합니다.
- **시트 숨기기·표시**: 탭 메뉴에서 숨기고 **숨긴 시트 N** 버튼에서 다시 표시합니다. 숨긴 시트의 값과 수식은 계속 계산되므로 다른 시트의 참조가 깨지지 않습니다.
- **탭 드래그 재배치**: 탭을 끌어 원하는 위치에 놓으면 순서가 저장됩니다.
- **다른 워크북으로 시트 복사**: 셀·수식·서식·행 높이·열 너비·고정 영역을 함께 복사합니다. 이름이 겹치면 `이름 (2)`로, 같은 워크북에 복사하면 `이름 복사본`으로 조정됩니다. 원본은 보기 권한과 복사 허용 정책을, 대상은 편집 권한을 요구합니다.

## 워크북 휴지통

- 워크북 삭제는 즉시 소멸이 아니라 휴지통 이동입니다. 홈 화면의 **휴지통** 필터에서 삭제 시각과 삭제한 사람을 확인하고 복원하거나 완전히 삭제합니다.
- 복원은 시트, 셀, 공유 설정을 그대로 되돌립니다. 완전 삭제는 확인 후에만 실행되며 되돌릴 수 없습니다.
- 휴지통은 소유자와 관리자에게만 보입니다. 삭제된 워크북은 공유를 평가할 수 없기 때문입니다.

## 사용자 및 역할 관리

- `/admin`에 **사용자 및 역할** 화면을 추가했습니다. 로그인한 사용자는 사용자 ID·표시 이름·이메일·마지막 접속 시각과 함께 디렉터리에 자동 등록되고, 아직 로그인하지 않은 사람도 미리 등록할 수 있습니다.
- **계정 정지**: 정지하면 모든 세션이 즉시 삭제되고 이후 요청은 `403 account_suspended`로 차단됩니다. 자기 자신은 정지할 수 없습니다.
- **kanpic 역할**: 사용자에게 부여한 역할은 워크북 공유의 **역할** 대상으로 바로 사용할 수 있습니다. OIDC 토큰 역할과 kanpic 역할은 합쳐서 평가되며 한 사용자는 최대 50개 역할을 가집니다.
- **세션 종료**: 특정 사용자의 모든 브라우저 세션을 관리자가 종료할 수 있습니다.
- 목록에서 역할, 소속 부서, 소유 워크북 수, 마지막 접속을 확인하고 사용자·이메일·역할·부서로 검색합니다.
- 콘솔 사이드바에 남아 있던 동작하지 않는 링크(사용자 및 역할, 워크스페이스, 보안 정책)를 실제 화면과 바로가기로 정리했습니다.

## 수정된 문제

- 즐겨찾기가 워크북 전역 상태여서 공유받은 뷰어는 별표를 달 수 없었고, 별표가 모든 사용자에게 공유되었습니다. 이제 사용자별로 저장되며 기존 별표는 소유자에게 이전됩니다.
- 마지막으로 표시된 시트를 숨길 수 있어 편집기에 열 수 있는 시트가 남지 않을 수 있었습니다. 이제 서버가 거부하고 UI에서도 비활성화됩니다.
- 숨긴 시트가 탭과 활성 시트 후보로 노출되었습니다. 이제 탭에서 제외되고 활성 시트는 표시된 시트 중에서 선택됩니다.
- 보기 권한 사용자에게 이름 변경·삭제 같은 실패할 시트 관리 메뉴가 그대로 보였습니다. 이제 권한에 따라 비활성화됩니다.
- 워크북 수정 응답에 공유 필드가 빠져 클라이언트 캐시가 공유 상태를 잃을 수 있었습니다.
- 넓은 대화상자(공유, 시트 관리)가 기본 모달 너비에 눌려 열이 잘리던 문제를 고쳤습니다.
- 사용하지 않는 내부 함수를 제거했습니다.

## REST API

```http
GET    /api/v1/workbooks/trash
POST   /api/v1/workbooks/{workbookId}/restore
DELETE /api/v1/workbooks/{workbookId}/purge
PUT    /api/v1/workbooks/{workbookId}/favorite
GET    /api/v1/workbooks/{workbookId}/sheet-stats
POST   /api/v1/sheets/{sheetId}/copy
GET    /api/v1/admin/users
POST   /api/v1/admin/users
GET    /api/v1/admin/users/{userId}
PATCH  /api/v1/admin/users/{userId}
POST   /api/v1/admin/users/{userId}/roles
DELETE /api/v1/admin/users/{userId}/roles/{role}
DELETE /api/v1/admin/users/{userId}/sessions
```

- 즐겨찾기는 읽기 권한만 요구합니다. 개인 상태이기 때문에 뷰어도 설정할 수 있습니다.
- 휴지통 관련 endpoint는 삭제된 워크북 목록으로 소유권을 확인합니다.
- 사용자 관리 endpoint는 관리자 세션 또는 `admin.*` scope를 요구합니다.

## MCP 도구

- `spreadsheet.workbook.trash|restore|purge|favorite`
- `spreadsheet.sheet.stats|copy`

## PostgreSQL 마이그레이션

- `019_workbook_management.sql`: `workbook_favorites` 테이블과 `workbooks.deleted_by` 열을 추가하고 기존 별표를 소유자 개인 즐겨찾기로 이전합니다.
- `020_user_directory.sql`: `directory_users`와 `user_roles` 테이블을 추가하고 워크북 소유자, 부서 구성원, 기존 세션 기록으로 디렉터리를 채웁니다.

## 업그레이드 참고

- v0.20.0 이하에서 시작하면 `019`, `020` 마이그레이션이 자동 적용됩니다. 운영 업그레이드 전 PostgreSQL 백업을 권장합니다.
- 워크북 삭제 API는 이제 휴지통 이동입니다. 완전 삭제가 필요한 자동화는 삭제 후 `DELETE /api/v1/workbooks/{id}/purge`를 함께 호출해야 합니다.
- 즐겨찾기를 설정하던 통합은 `PATCH /api/v1/workbooks/{id}`의 `favorite` 대신 `PUT /api/v1/workbooks/{id}/favorite`을 사용하십시오. 기존 필드는 응답에서 호출자 기준으로 계산됩니다.
- 계정 정지는 API 키에도 적용됩니다. 배치 작업용 계정을 정지하면 해당 키의 요청도 차단됩니다.
