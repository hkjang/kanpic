# v0.222.0

## `=COUNTIF(A:A,"Inf")` 이 0 을 냈다 — 그 칸이 있는데도

지난 판에서 셀 값을 숫자로 읽는 자를 좁혔습니다. 그런데 좁힌 것은 **셀 값**
하나였습니다. 조건(`SUMIF`, `COUNTIF`, `AVERAGEIF`…)과 질의문(`QUERY`)은
여전히 Go 의 `ParseFloat` 로 읽고 있었습니다.

그래서 조건으로 적은 글자가 숫자로 바뀌었습니다.

```
A1  Inf
A2  1_000

=COUNTIF(A1:A2,"Inf")     →  0
=COUNTIF(A1:A2,"1_000")   →  0
```

칸은 거기 있는데 없다고 답합니다. **빈 답이 아니라 틀린 답입니다.**

내보낸 자료에 `Inf` 가 몇 줄이나 섞여 있는지 세어 보려는 사람이 정확히 이
조건을 씁니다. 그리고 `0` 을 보고 깨끗한 자료라고 판단합니다.

이제 조건과 질의문도 셀 값과 **같은 자**로 읽습니다.
`">=1e3"` 같은 숫자 조건은 그대로 숫자입니다.

## 정렬과 거르기, 차트도 보았다

같은 뿌리를 가진 자리를 모두 뒤졌습니다. 결과는 이렇습니다.

| 자리 | 상태 |
|---|---|
| 정렬 (`sort.go`) | JSON 숫자만 읽는다 — 글자는 글자로 견준다. 문제 없음 |
| 거르기 (`filter.go`) | 같다. 문제 없음 |
| 차트 (`chart.go`) | NaN 과 무한대를 이미 막고 있다. 문제 없음 |
| 조건 (`functions.go`) | **고쳤다** |
| 질의문 (`query.go`) | **고쳤다** |

고칠 것이 없는 곳은 그대로 두었습니다.

  - `">=1e3"`, `">1000"`, `"500"` 같은 숫자 조건이 그대로 숫자로 견주어지는지
