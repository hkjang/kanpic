# v0.223.0

## 병합된 칸에 붙여넣으면 병합이 어긋났다

병합 `B2:C3` 의 덮인 칸 C3 에 값을 붙여넣으면 이렇게 됐습니다.

```
B2  (병합 B2:C3)      ← 여전히 병합을 기억한다
C2  (병합 B2:C3)
B3  (병합 B2:C3)
C3  "숨은 값"          ← 병합을 잃었다
```

세 칸은 병합을 기억하고 한 칸은 잊었습니다. 격자는 앵커 B2 를 보고 네 칸을
하나로 그리므로 **C3 에 넣은 값은 병합 아래 숨어 보이지 않았습니다.** 붙여넣기는
"저장됨" 이라고 했습니다.

자동 채우기가 앵커를 지나가면 반대로 됐습니다. 앵커가 병합을 잃고 나머지가
사라진 병합을 가리킨 채 남아, 그 칸을 고치려는 **다음 편집이 "stored merge
metadata is invalid" 로 거절**됐습니다. 사람이 무엇을 해야 하는지 알 수 없는
말입니다.

## 병합에 쓰면 병합 전체가 같은 작업에서 풀린다

서버가 병합의 일관성을 지킵니다. 병합에 속한 칸의 서식이 그 병합을 잃는 쓰기가
오면, **그 병합의 모든 칸을 같은 작업 안에서 풉니다.** 값·수식·메모는 그대로
둡니다.

- 붙여넣기, 자동 채우기, API, AI, 자동화 — 어느 길로 와도 한 규칙입니다.
- 되돌리기 한 번에 병합이 돌아옵니다. 풀린 칸 모두가 한 작업에 들어 있기 때문입니다.
- 서식 덧칠은 병합을 건드리지 않습니다. 사람이 직접 한 병합·해제는 스스로를 알리지 않습니다.
- 어긋난 상태 자체가 만들어지지 않습니다.

구글 시트가 하는 방식입니다. 엑셀처럼 거절하는 길도 있었지만, 서버는 이미
전체를 덮는 붙여넣기에서 병합을 풀고 있었고, 거절은 AI 와 자동화의 쓰기를
알 수 없는 오류로 세웁니다.

## 조용히 풀지 않는다

결과에 `unmerged_ranges` 를 실어 격자가 말합니다.

> **B2:C3 병합을 풀었습니다**
> 병합된 칸에 값을 넣으면 병합 전체가 풀립니다. 실행 취소로 되돌릴 수 있습니다.

저장이 끊겼다 이어져 같은 쓰기를 다시 보내면 서버는 첫 응답을 되풀이합니다.
그 되풀이도 풀린 병합을 함께 말합니다 — 작업 문서에 저장해 두기 때문입니다.
되풀이만 본 격자가 병합이 사라진 것을 모르는 일은 없습니다.
