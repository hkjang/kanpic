## 릴리즈 요약

v0.189.0은 **날짜 서식의 따옴표 안 글자** 를 그대로 적습니다. 한국에서 만든 파일의 날짜가 제대로 보입니다.

## 같은 자리에 같은 잘못이 있었습니다

v0.188.0에서 숫자 서식의 따옴표와 대괄호를 고쳤습니다. 날짜 쪽은 손대지 않았는데, 같은 잘못이 그대로 있었습니다.

```
yyyy"년" m"월" d"일"   →   2023"년" 3"월" 15"일"
h"시" m"분"            →   12"시" 0"분"
yyyy\-mm               →   2023\-03
[$-412]yyyy-mm-dd      →   [$-412]2023-03-15   (서버만)
```

**한국에서 만든 파일의 날짜는 거의 이 꼴입니다.** 따옴표가 그대로 보이는 날짜는 사람이 적은 것이 아니라 프로그램이 잘못 그린 것으로 읽힙니다.

## 미리 걷어낼 수 없습니다

따옴표 안을 먼저 지우면 `"day"` 처럼 안에 든 글자가 날짜 기호로 읽힙니다. 기호를 하나씩 읽는 자리에서 통째로 옮깁니다.

## 대괄호를 다루는 방식이 둘이 달랐습니다

격자는 `[h]` `[mm]` `[ss]` 만 남기고 나머지를 걷어냈고, 서버는 **아무것도 걷어내지 않았습니다.** 격자 쪽이 맞으므로 서버를 맞췄습니다. 같은 것을 두 곳에서 따로 정해 두면 이렇게 갈립니다.

## 시험이 왜 못 잡았는가

붙잡는 목록에 날짜 서식은 많았지만 **따옴표가 든 것은 한 줄도 없었습니다.** 지난 판과 똑같습니다 — **두 벌이 서로 맞는 것은 둘 다 맞다는 뜻이 아닙니다.** 여섯 줄 더했습니다.

## 검증 결과

- 두 벌이 **868줄** 을 같은 답으로 냅니다.
- 웹 시험 445개와 Go 시험 전체, 브라우저 시험 33개가 통과합니다.
