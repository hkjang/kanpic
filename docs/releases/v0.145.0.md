## 먼저 "며칠인가" 를 세는 여섯 개

`PRICE`, `YIELD`, `DURATION` 은 겉보기에 복잡하지만, 전부 같은 질문에서 시작합니다. **결제일이 어느 이자 기간 안에 있고, 그 기간이 며칠이며, 앞뒤로 며칠 떨어져 있는가.**

그래서 `COUPPCD`, `COUPNCD`, `COUPNUM`, `COUPDAYS`, `COUPDAYBS`, `COUPDAYSNC` 를 먼저 만들고 나머지를 그 위에 얹었습니다.

지급일은 만기일에서 거꾸로 물러나며 잡습니다. **만기일이 그 달의 마지막 날이면 지급일도 모두 마지막 날** 입니다 — 2월을 지나며 날짜가 밀리면 기간 길이가 어긋납니다.

```
=COUPPCD("2018-03-05", "2019-02-28", 4)  ->  2018-02-28
=COUPNCD("2018-03-05", "2019-02-28", 4)  ->  2018-05-31
```

## 가격은 경과이자를 뺍니다

사는 쪽이 파는 쪽에 따로 주는 몫이라, 가격에 넣으면 그만큼 부풀어 오릅니다.

깨끗한 경우 — 결제일이 지급일과 겹칠 때 — 는 표준 연금 공식과 같아야 합니다. 그 값을 파이썬으로 따로 계산해 맞췄습니다. 기간 가운데에서는 `YIELD(PRICE(y)) = y` 왕복으로 봅니다. 경과이자를 빼지 않으면 거기서 어긋납니다.

## 시험이 너무 강했습니다

"지난 날 + 남은 날 = 기간 길이" 라는 시험을 썼다가 기준 `2`(실제/360)와 `3`(실제/365)에서 깨졌습니다.

확인해 보니 **엑셀도 그렇습니다.** 기간 길이는 360이나 365를 횟수로 나눈 값인데 앞뒤 날 수는 진짜 날짜를 셉니다. 억지로 맞추면 채권 가격이 엑셀과 달라집니다.

시험을 기준 `0`·`1`·`4` 로 좁히고, 어긋나는 두 기준의 값을 **따로 적어 두었습니다.** 나중에 이것을 버그로 보고 고치는 일이 없도록 합니다.
